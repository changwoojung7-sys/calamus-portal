## 2. 도메인 이전

| 용도 | 옛 주소 | 새 주소 |
|---|---|---|
| 소개 사이트 + 공급자 포털 + 고객 다운로드 (Pages `virtual-office`) | `virtual-office.calamus.ai.kr` | `worknexus.calamus.ai.kr` |
| 공개 체험 (Pages `virtual-office-demo`) | `try.virtual-office.calamus.ai.kr` | `try.worknexus.calamus.ai.kr` |

- 두 새 도메인을 각 Pages 프로젝트의 커스텀 도메인으로 **추가**했다. 이전 기간에는 옛 주소도 그대로 열려 있다.
- **소스 변경**: 소개 페이지 데모 링크(`DEMO_URL`), 프리셋 관리 화면 링크, 오피스 앱 관리 허브의 문서·다운로드 링크(`AdminManagementHub.tsx`, 1.0.6부터 고객 서버에 반영), 촬영 모드·녹화 스크립트의 엔딩 주소.
- **문서 변경**: 운영·설치 가이드, 거래처 매뉴얼, 구조 분석 문서, 매뉴얼 원본과 PDF 11개 등 38곳. 과거 사고 기록 문장과 변경 이력은 옛 주소를 그대로 둔다.
- **매뉴얼 PDF 생성 스크립트 버그 수정**: Node 24의 `fs.rmSync`가 Windows의 한글 경로에서 프로세스를 비정상 종료(0xC0000409)시켜 `npm run manuals:pdf`가 아무 출력 없이 실패했다. 기존 PDF는 `unlinkSync`로 지우고, 임시 HTML과 프로필 폴더는 영문 이름을 쓰도록 바꿨다.

### 남은 일 — 옛 도메인 정리
옛 주소로 들어오는 링크(1.0.5 이하 고객 서버, 예전 안내문, 북마크)가 끊기지 않도록, 커스텀 도메인을 지우기 **전에** Cloudflare 규칙(Redirect Rules 또는 Bulk Redirects)으로 301 리다이렉트를 건다.
- `virtual-office.calamus.ai.kr/*` → `https://worknexus.calamus.ai.kr/$1`
- `try.virtual-office.calamus.ai.kr/*` → `https://try.worknexus.calamus.ai.kr/$1`
- 고객 서버가 부르는 `/api/release-links/*`가 경로를 유지한 채 넘어가는지 확인한다.

## 3. Cloudflare Access 재구성

### 3.1 배경
Access 보호는 **도메인마다 따로** 설정된다. 새 도메인을 추가만 하면 `/manage`·`/download` 화면은 열리지만 API가 `403`으로 막혀 쓸 수 없었다. 정리하는 과정에서 기존 공급자 앱이 삭제되어, 공급자 앱을 새로 만들었다.

### 3.2 최종 구성
| 앱 | 정책 | 목적지 | 서버 변수 |
|---|---|---|---|
| `worknexus-supplier` (공급자 관리) | Virtual Office 공급자 관리자 허용 **만** | `worknexus`·`virtual-office` 각각 `/manage*`, `/api/manage/*` | `CF_ACCESS_AUD` = `26e96191…823afc` (Pages Secret, 2026-10-08 등록 후 재배포) |
| `worknexus` (고객 다운로드) | 고객 이메일 인증(Everyone) | `worknexus`·`virtual-office` 각각 `/download`, `/api/download` | `CF_CUSTOMER_ACCESS_AUD` |

- `/api/release-links`는 어느 앱에도 넣지 않는다. 고객 서버가 로그인 없이 업데이트 파일을 받아 가는 경로다.
- 확인 결과(로그인하지 않은 상태): 두 도메인 모두 공급자 경로는 공급자 앱 로그인으로, 다운로드 경로는 고객 앱 로그인으로 302가 나뉘었다. `/api/release-links`는 410으로 서버까지 도달했다. 공급자 포털 로그인 후 고객 목록이 정상으로 보이는 것도 확인했다.

### 3.3 반드시 지킬 것
- 서버는 공급자 권한을 **이메일 목록이 아니라 AUD(어느 앱을 통과했는지)로만** 판단한다(`functions/api/manage/_middleware.js`).
- 따라서 **고객 앱(Everyone 정책)에 `/manage` 경로를 넣거나, 고객 앱의 AUD를 `CF_ACCESS_AUD`에 넣으면 안 된다.** 이메일만 있으면 누구나 공급자 포털과 라이선스 발급에 들어올 수 있게 된다.
- `CF_ACCESS_AUD`를 바꾼 뒤에는 반드시 다시 배포한다. Pages Secret은 배포할 때 고정된다.
- Access 목적지를 바꾼 뒤 반영되기까지 1분 정도 걸릴 수 있다.
