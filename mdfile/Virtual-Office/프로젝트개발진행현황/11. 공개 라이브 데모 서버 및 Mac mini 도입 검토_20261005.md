# 공개 라이브 데모 서버 및 Mac mini 도입 검토

- 작성일: 2026-10-05
- 목적: `try.worknexus.calamus.ai.kr`의 실시간 상호작용 체험 확대와 상시 데모 서버 도입 판단을 위한 참고 자료
- 현재 회선: LG U+ 기가비트 유선 인터넷

## 1. 현재 공개 체험 사이트의 한계

현재 `try.worknexus.calamus.ai.kr`는 Cloudflare Pages와 D1 기반 데이터 API를 사용한다. 로그인, 사원 목록, 건물 프리셋, 공지, 게시글과 화이트보드 같은 데이터 기능은 체험할 수 있지만 다음 실시간 미디어 기능을 완전하게 제공하는 상시 서버는 없다.

- 사용자 위치와 상태를 동기화하는 상시 WebSocket 서버
- 근거리 대화 설정 및 LiveKit 토큰 발급 API
- 회의실 화상회의와 화면공유용 LiveKit SFU
- 외부망 WebRTC 미디어 경로와 TURN/TLS

따라서 현재 화면에 표시되는 사원 캐릭터는 대부분 데모 DB에 등록된 사원이며 실제 동시 접속자를 뜻하지 않는다. 접속자가 혼자라서 상대방 음성이 들리지 않는 것은 자연스럽지만, 근거리 대화 버튼 자체가 꺼지는 주된 이유는 데모 Pages 환경에 근거리 대화용 서버 API와 LiveKit이 없기 때문이다.

## 2. 권장 공개 데모 구성

여러 건물 구조가 있다는 사실은 기술적인 장애가 아니다. 서버에서는 건물 템플릿, 층과 방을 조합해 LiveKit 방과 상태 채널을 분리할 수 있다. 다만 공개 이용자가 여러 건물과 방으로 흩어지면 서로 마주칠 확률이 낮아 실제 상호작용을 체험하기 어렵다.

다음과 같이 역할을 나누는 방식을 권장한다.

1. 기존 여러 건물은 공간 구조와 UI를 살펴보는 미리보기로 유지한다.
2. 하나의 건물을 `라이브 체험 사옥`으로 지정한다.
3. 라이브 체험 사옥에만 상시 Node 서버와 LiveKit SFU를 연결한다.
4. 서로 다른 데모 계정으로 로그인한 이용자를 한 건물에 모은다.
5. 동시 접속 한도, 자동 로그아웃, 데이터 주기 초기화와 오남용 방지 정책을 적용한다.
6. 서버가 중단된 경우에는 시각 체험 모드로 자동 전환하고 실시간 기능 제한을 안내한다.

## 3. Mac mini에서의 구동 가능성

WorkNexus가 Mac에서 기술적으로 구동 불가능한 것은 아니다. LiveKit은 macOS에서 실행할 수 있고 Docker Desktop도 Apple Silicon을 지원한다. 다만 현재 WorkNexus는 다음 두 환경만 공식 패키지로 지원한다.

- Windows 통합 설치 패키지
- Ubuntu/Linux Docker 설치 패키지

현재 macOS용 네이티브 설치 패키지는 없다. 기존 패키지를 Mac에 그대로 설치할 수 없는 주요 이유는 다음과 같다.

- Windows 패키지는 `livekit-server.exe`, `cloudflared.exe`와 Windows 트레이 프로그램을 사용한다.
- Linux 설치기는 `/opt`, `/etc/machine-id`, `systemd`, `ip route` 같은 Linux 전용 기능에 의존한다.
- Linux Docker 구성은 호스트의 `/etc/machine-id`를 라이선스 하드웨어 지문에 사용한다.
- 현재 오프라인 Docker 이미지 묶음은 x86-64 중심이므로 Apple Silicon ARM64 이미지 묶음을 별도로 생성하고 검증해야 한다.
- macOS용 설치, 업데이트, 자동 시작, 백업, 복원과 장애 대응 절차가 아직 없다.

### 3.1 가능한 실행 방식

| 방식 | 판단 |
|---|---|
| macOS에 현재 Windows 패키지 설치 | 불가 |
| macOS에 현재 Linux 설치 스크립트 실행 | 불가 |
| Docker Desktop에서 Compose 수동 실행 | 기술적으로 가능하나 미검증 |
| Mac 안의 Linux VM에 Linux 패키지 설치 | 가능성이 높지만 네트워크·라이선스 검증 필요 |
| macOS 네이티브 Node + LiveKit 구성 | 가능하나 별도 설치·운영 도구 개발 필요 |

## 4. Mac mini를 구매할 경우의 권장 사양과 용도

개발, 빌드, 문서와 영상 제작을 함께 수행하면서 개인용 라이브 데모 서버를 시험한다면 Mac mini는 활용 가치가 있다.

- Apple Silicon M4 계열
- 통합 메모리 24GB 이상 권장
- SSD 512GB 이상 권장
- Wi-Fi보다 유선 기가비트 Ethernet 사용
- 정전 복구 후 자동 시작 설정
- 가능하면 UPS 연결
- Docker Desktop 또는 Linux VM 기반 시험 운영

다만 개발 작업 중 재부팅하거나 Docker Desktop을 종료하면 공개 체험 서버도 중단된다. 한 장비에서 개발 PC와 상시 서버를 겸하면 운영 안정성이 개발 일정에 영향을 받는다.

## 5. 전용 Linux 미니 PC와의 비교

공개 데모 서버만을 목적으로 한다면 x86-64 기반 Linux 미니 PC가 현재 WorkNexus 구조에 더 잘 맞는다.

- 기존 Linux Docker 패키지를 그대로 적용하기 쉽다.
- `systemd`, `/etc/machine-id`, 자동 시작과 백업 절차를 그대로 사용할 수 있다.
- Apple Silicon용 이미지와 라이선스 호환 작업이 필요 없다.
- Mac mini보다 저렴한 장비를 전용 서버로 분리할 수 있다.
- 개발 PC를 재부팅해도 데모 서버에는 영향이 없다.

따라서 선택 기준은 다음과 같다.

- 개발 장비 가치까지 중요하면: Mac mini 구매 후 Docker/VM 지원을 추가 개발
- 빠르고 안정적인 상시 데모가 우선이면: x86-64 Linux 미니 PC
- 외부 접속 안정성과 관리 부담을 줄이려면: Linux VPS 또는 집 서버와 TURN VPS의 혼합 구성

## 6. LG U+ 기가비트 회선에서 반드시 확인할 사항

기가비트 유선 회선은 기본 대역폭 측면에서 유리하지만, 표시 속도만으로 공개 WebRTC 서버 운영 가능 여부가 결정되지는 않는다. 다음 항목을 실제로 점검해야 한다.

### 6.1 회선과 공유기

- 업로드 실측 속도와 장시간 안정성
- 서버는 반드시 유선 LAN으로 연결
- 공유기의 포트 포워딩 지원 여부
- 공유기 재부팅 시 내부 IP 고정 또는 DHCP 예약
- 외부 IP 변경 주기
- 공인 IPv4 제공 여부
- CGNAT 또는 통신사 공유 주소 사용 여부
- 필요한 UDP 포트를 통신사가 제한하는지 여부

공유기 WAN 주소와 외부 IP 확인 사이트의 주소가 다르면 CGNAT 또는 이중 NAT 가능성을 점검한다. 공인 IP 또는 필요한 포트 포워딩을 확보하지 못하면 TURN 중계 서버를 외부 VPS에 두는 방식을 검토한다.

### 6.2 WorkNexus와 LiveKit 경로

Cloudflare Tunnel은 웹 페이지, API와 WebSocket 신호 경로에 사용할 수 있다. 그러나 WebRTC 미디어의 모든 UDP 트래픽을 Cloudflare Tunnel이 대신하는 것은 아니다. LiveKit 미디어에는 다음 경로를 별도로 검증해야 한다.

- HTTPS/WSS 신호 경로
- WebRTC UDP 포트 범위
- WebRTC TCP 대체 경로
- TURN/UDP 및 TURN/TLS
- 모바일 통신망, 회사 방화벽과 공공 Wi-Fi에서의 접속

현재 WorkNexus Linux 기본 구성은 앱 포트와 함께 LiveKit 신호 포트, TCP 대체 포트, TURN/UDP와 RTC UDP 범위를 사용한다. 실제 외부 공개 시 포트 범위는 운영 환경에 맞게 최소화하고 방화벽 정책과 함께 확정해야 한다.

## 7. 현실적인 단계별 도입안

### 1단계: 구매 전 회선 검증

현재 보유한 Linux 서버를 잠시 사용해 U+ 회선의 외부 접속, 공인 IP·NAT, LiveKit UDP와 TURN 동작을 먼저 검증한다. 학교 데모 데이터는 별도 백업하고 테스트용 인스턴스와 포트를 분리한다.

### 2단계: 장비 선택

- 회선 검증이 성공하고 전용 서버가 우선이면 Linux 미니 PC를 선택한다.
- 개발 환경 개선과 macOS 활용이 더 중요하면 Mac mini를 선택하고 WorkNexus macOS Docker 지원을 개발한다.

### 3단계: 라이브 체험 사옥 운영

- 하나의 기본 건물만 라이브 체험 대상으로 지정
- 데모 계정과 동시 접속 제한 적용
- 자동 데이터 초기화 및 세션 만료 적용
- 서버 상태 확인 및 오프라인 안내 적용
- 장애·재부팅 후 자동 복구 검증

### 4단계: 필요 시 TURN 분리

집 회선이나 공유기 제약으로 모바일·회사망 접속이 불안정하면 저가형 외부 VPS에 TURN/TLS만 배치한다. 업무 데이터와 WorkNexus 서버는 집 장비에 유지하면서 제한적인 미디어 릴레이만 외부 인프라를 사용할 수 있다.

## 8. 현재 결론

1. U+ 기가비트 유선망은 공개 데모 운영에 유리한 출발점이지만 공인 IP, CGNAT와 UDP 경로 확인이 선행되어야 한다.
2. Mac mini에서도 WorkNexus를 구동할 수 있으나 현재는 공식 지원 환경이 아니다.
3. Mac mini를 선택한다면 Apple Silicon용 Docker 이미지, macOS 설치·자동 시작·백업과 하드웨어 라이선스 방식을 추가 개발해야 한다.
4. 공개 데모 전용 장비만 필요하다면 현재 패키지와 가장 잘 맞는 x86-64 Linux 미니 PC가 더 단순하다.
5. Mac mini는 개발 장비와 데모 시험 서버를 겸하는 선택으로는 충분히 검토할 가치가 있다.
6. 최종 구매 전에 현재 Linux 서버로 외부 WebRTC 경로를 먼저 시험하여 장비 문제가 아닌 회선 문제를 배제하는 것이 가장 경제적이다.
