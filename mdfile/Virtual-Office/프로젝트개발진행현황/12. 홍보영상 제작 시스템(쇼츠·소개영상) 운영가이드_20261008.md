## 2. 쇼츠 — 촬영 모드 (`src/cinema/`)

### 2.1 구조
- 개발 서버에서 `http://localhost:5173/?cinema`로 연다. `import.meta.env.DEV` 분기라 **운영 빌드에는 코드가 들어가지 않는다**(`src/main.tsx`).
- `src/cinema/scenario.ts`: 45초 시나리오. 카메라 경로, 배우 동선, 말풍선, 자막, 엔딩 카드, 체험 주소(`TRIAL_URL`)를 모두 **시간 t의 함수**로 정의한다. 그래서 몇 번을 녹화해도 같은 영상이 나온다.
- `src/cinema/CinemaApp.tsx`: 유진IT 건물 구조(`cinema-data/yujinit-building-plan.json`, 라이선스 payload에서 추출)를 넣고, 개발 DB의 STARTUP 직원(엔터프라이즈 설치본에서 가져온 17명)을 출연시킨다. 후처리 효과는 N8AO, 아웃포커싱, Bloom, 비네팅, ACES를 쓴다.
- `src/cinema/dashboard.ts`: 회의실 스크린에 띄우는 데모 대시보드(가상 수치).
- 옵션: `&faces=voxel`(얼굴 사진 대신 기본 얼굴), `&names=alias`(가명), `&t=초`(해당 시점부터 미리보기).

### 2.2 녹화
```bash
# 개발 서버(공인 터널 없이)
PORT=3001 node server/index.js
VO_DEV_TUNNEL=off npx vite

npm run promo:record                 # 사내용(실명·사진)
npm run promo:record -- --public     # 외부 공개용(기본 얼굴 + 가명)
node scripts/record-promo.mjs --stills=3,9,15   # 정지 화면만
node scripts/record-promo.mjs --public --from=40 --to=45 --out=recordings/x.mp4   # 구간만
```
- 설치된 Chrome을 `puppeteer-core`로 열고 `frameloop="never"` + `advance(t)`로 한 프레임씩 그린 뒤 캡처해서, `ffmpeg-static`으로 60fps H.264를 만든다. 약 7분 걸린다.
- `VO_DEV_TUNNEL=off`가 없으면 vite가 Cloudflare 공인 터널을 열어 개발 데이터가 외부에 노출된다.

### 3.2 녹화 전용 서버
- **운영 모드**로 띄운다. 데모 모드는 첫 화면이 "건물 고르기"라 실제 고객 화면과 다르다.
- 2026-10-13부터는 `servers.mjs` 하나로 띄운다. 같은 PC의 운영 설치본(3001·LiveKit 7880)과 겹치지 않도록 **녹화 서버 3011 + 시험 전용 LiveKit 7895(UDP 51600~51800) + vite 5173(API는 3011, 공인 터널 없음)**을 함께 켠다. 녹화 도구의 기본 서버 주소도 3011이다(`STUDIO_SERVER`로 바꿀 수 있음).
```bash
node --no-warnings scripts/promo-studio/setup-db.mjs        # 서버를 끈 상태에서(첫 소개 영상용)
node scripts/promo-studio/servers.mjs                       # 녹화 서버·LiveKit·vite 함께 실행(Ctrl+C로 종료)
```
- 시험 전용 LiveKit은 운영 설정처럼 모든 주소에 바인딩한다. `127.0.0.1` 전용(`--node-ip 127.0.0.1`)으로 띄우면 Chrome이 루프백 ICE 후보를 만들지 않아 회의가 "연결 중"에서 멈춘다.
- 개발 서버에서 주소에 `?studio`를 붙이면 유진IT 건물 구조를 `licensedBuildingPlan`으로 쓴다(`src/utils/devStudioPlan.ts`, 개발 전용).
- 주인공 로그인 정보: 김하늘 / 첫 비밀번호 `1234` → 챕터 1에서 `Haneul!2026`으로 바꾼다. 봇 비밀번호는 `cast.mjs`의 `BOT_PASSWORD`이다(녹화 전용 데이터라 실제 서비스와 무관).

### 3.3 녹화와 합치기
```bash
node scripts/promo-studio/record-all.mjs                 # 전체(약 15분)
node scripts/promo-studio/record-all.mjs --from=ch5-tour # 특정 챕터부터
node scripts/promo-studio/rerecord.mjs ch1-login ch7a-allhands   # 일부만 다시 찍고 합치기
```
- 챕터 순서: 인트로 → 첫 출근 → 캐릭터·사진 → 하단 버튼 → 근거리 대화·1:1 통화·화면 공유 → 사옥 투어·루프탑 → 화상회의 → 사내 전체 회의(발표자 시점) → 외부 고객 세미나(게스트 시점) → 엔딩.
- `assemble.mjs`가 챕터마다 배속(1.25~1.5)을 적용하고 자막 시각도 같은 비율로 맞춘다. 5분 안에 들어가도록 조정해 두었다.
- 접속 주소는 사내 IP가 아니라 터널링 도메인(`https://yujinit.calamus.ai.kr`)을 입력한다.

### 3.4 알려진 한계
- 실제 앱을 실시간으로 녹화하므로 PC 부하에 따라 프레임이 고르지 않을 수 있다(평균 20~50fps → 30fps로 맞춤).
- 화상회의 참석자 카메라는 3명이다. 계획은 4명이었지만 2명이 회의 입장 버튼을 찾지 못했다.
- 화면 공유는 녹화용 브라우저에서만 `getDisplayMedia`를 미리 만든 영상과 무음 오디오로 바꾼다. 앱 코드는 바꾸지 않았다.

- **시간 조건**: a1이 회의를 "지금부터 약 5분 뒤 시작"으로 예약한다. 외부 링크와 ▶참여하기는 시작 30분 전부터 열리고, a4는 시작 시각까지 기다렸다가 찍는다(회의실 사용 중 확인 창이 끼지 않게).

### 3.6 시연영상 B — 직원들의 일상 소통

화상회의는 A편에서 다루고, B편에서는 근처 대화·방별 격리·소리 차단·반응 8종·게시판·팀 일정·태블릿 이동·2D·1:1 통화와 시안 공유를 촬영한다. 출연진은 가상 직원만 사용한다.

```powershell
node scripts/promo-studio/servers.mjs --reset=b
# 다른 터미널에서
node scripts/promo-studio/record-all-b.mjs
# 이후 장면 재촬영 (기존 앞 장면 파일 보존)
node scripts/promo-studio/record-all-b.mjs --from=b3-boards
```

- 결과 폴더: `recordings/demo-b-16x9/` (git 제외).
- `worknexus-demo-b-captioned.mp4`: 한국어 자막을 화면에 넣은 검토용 영상.
- `worknexus-demo-b.mp4`, `.srt`: 편집용 합본과 별도 자막. `youtube-chapters.txt`, `stills/`도 생성.
- 태블릿은 Chrome의 iPad 사용자 에이전트·터치 화면 에뮬레이션으로 시연하며 실제 기기 촬영은 아니다.
- 기존 스튜디오 방식과 동일하게 영상은 무음이다. 실제 통화·카메라 연결 화면은 녹화하지만 음성 트랙·배경음악·내레이션은 넣지 않는다. 시안 공유 영상은 녹화용 브라우저의 `getDisplayMedia` 대체 소스로 사용한다.
- `finish-b.mjs`만 실행하면 기존 합본에 자막을 다시 넣을 수 있다.
- 테이블 중심 카메라 연출본은 `node scripts/promo-studio/record-directed-b.mjs`로 재촬영한다. `--only=b2-reactions`로 특정 장면만 교체한다. `direction.mjs`가 어라운드·카메라 이동·페이드·촬영 UI를 제어하고, 개발 전용 `StudioFocus.tsx`가 피사계 심도를 처리한다. 촬영 카메라의 y 좌표는 층별 바닥 높이에 자동으로 맞춘다.

## 4. 엔딩 카드 주소만 바꾸는 방법 (음악·자막 유지)

CapCut에서 음악과 자막을 넣은 영상을 다시 만들지 않고 **주소 줄만 덮어쓴다.**
1. 새 주소로 엔딩만 다시 렌더링한다. 쇼츠는 `record-promo.mjs --public --from=40 --to=45`, 소개 영상은 `record-chapter.mjs ch8-outro`.
2. 원본과 비교해 카드가 나타나는 시각과 주소 줄 위치를 찾는다. 쇼츠는 1058~1087행, 소개 영상은 y=835~891.
3. ffmpeg `overlay`로 그 영역만 덮는다. 오디오는 `-c:a copy`로 그대로 둔다.
   - 소개 영상: 새 엔딩을 `-itsoffset 284.5`로 맞추고 `enable='gte(t,291.22)'`부터 덮는다. 카드가 나타나는 2프레임만 띠가 약간 밝다.
   - 쇼츠: 렌더링이 결정적이라 `-itsoffset 40`에 `t≥40.9`부터 덮으면 이음매가 생기지 않는다.

> 페이드 구간에 알파 페이드를 섞으면 옛 주소가 비쳐 보인다. 페이드 없이 즉시 교체하는 방식이 가장 깨끗했다.

## 5. 유튜브 업로드 문구

### 쇼츠
- 제목 예: `브라우저만 열면 출근 완료! 3D 가상 오피스 WorkNexus 🏢`
- 설명 첫 두 줄에 핵심 문구를 두고, 체험 주소 `https://try.worknexus.calamus.ai.kr`와 해시태그를 넣는다.

### 5분 소개 영상
- 제목 예: `브라우저로 출근하는 3D 가상 오피스 | WorkNexus 5분 기능 소개`
- 설명에 챕터 목록을 그대로 붙인다. 유튜브는 `0:00`으로 시작하고 각 구간이 10초 이상이면 자동으로 챕터를 만든다.
```
0:00 인트로
0:10 첫 출근 — 설치 없이 웹으로 로그인
0:40 나만의 캐릭터와 사진 등록
1:14 하단 버튼 둘러보기
1:47 근거리 대화 · 1:1 채팅·통화·화면 공유
2:29 사옥 투어와 루프탑
3:04 화상회의와 화면 공유
3:39 사내 전체 회의(대강당)
4:05 외부 고객 세미나(100석 타운홀)
4:45 엔딩
```
- 영상 속 인물, 회사, 수치는 가상 데이터라 설명에 "시연용 가상 데이터" 안내를 넣는다.
- 임베드 화면에 보이는 제목은 **유튜브 스튜디오의 제목**이다. 로컬 파일 이름과는 관계없다.

## 6. 개발 데이터 관련 메모
- 개발 DB(`server/data/virtual_office.db`)에 엔터프라이즈 직원 17명과 프로필·얼굴 사진을 STARTUP 템플릿으로 가져왔다. 가져오기 전 DB는 `server/data/backup-before-cinema-import-20261008/`에 있다.
- 리센느 멤버 얼굴 사진은 실제 연예인이라 **외부 공개 영상에는 쓰지 않는다**(공개판은 기본 얼굴과 가명 사용).
- `vite.config.ts`: `VO_DEV_TUNNEL=off`이면 개발 서버가 공인 터널을 열지 않는다(기본 동작은 그대로).
