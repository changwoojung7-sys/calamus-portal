## 1. 1.0.6에 포함된 변경

### 1.1 타운홀 외부 고객 초대 링크 수정 (`2d8d048`)
- **증상**: 외부 고객이 세미나 초대 링크(`?townhallEvent=…&guest=…`)를 열면 게스트 등록 화면이 아니라 사내 포털이 나와 입장하지 못했다.
- **원인**: `src/App.tsx`가 로그인하지 않은 방문자를 모두 사내 포털로 보냈다. "로그인 전 포털 표시" 변경(`d25b43b`) 이후 생긴 문제다.
- **수정**: 초대 링크로 들어오면 로그인 분기보다 먼저 `TownHallView` 게스트 화면(이름·회사·이메일·동의 → 등록하고 입장)을 연다.
- **확인**: 진행자가 행사를 시작한 뒤 초대 링크로 등록하면 객석에 입장되는 것을 녹화로 확인했다. 기능 소개 영상 4:05 장면이 이 흐름이다.
- 1.0.5 이하를 쓰는 고객 서버는 이 문제가 있으므로 1.0.6 업데이트를 권한다.

### 1.2 화상회의 창 화면 공유 연결 중 로딩 표시 (`64da538`)
- 다른 사람의 공유 화면이 아직 도착하지 않았을 때(LiveKit 연결 중, 재연결 중, 트랙 대기) 검은 화면 대신 스피너, 단계 표시(연결 중 → 스트림 수신 → 화면 표시), 진행 바, 안내 문구를 보여 준다.
- 헤더 배지도 "연결 중..." 또는 "영상 수신 준비 중"으로 바뀐다. 내가 공유할 때는 표시하지 않는다.
- 파일: `src/components/RemoteScreenViewerModal.tsx`

### 1.3 링크 주소 변경
- 오피스 앱 관리 허브의 문서·다운로드 링크가 `worknexus.calamus.ai.kr`을 가리킨다(13번 문서 참고).

### 1.4 버전 표기
- `release-manifest.json` 기준으로 버전 표기 13개 파일을 1.0.6으로 맞췄다. `package.json`·lock 파일(이 프로젝트 줄만), `server/`, `src-tauri/`, `docker-compose.yml`, `server/Dockerfile`, `deploy/docker.env.example`, C# 실행기 3개가 해당한다. `npm run verify:release-version`을 통과했다.
- 화면에 보이는 문구(관리자 콘솔, HUD, 사내 포털, 서버 상태 페이지, 트레이 메뉴, 설치 창 제목, 문서센터, 매뉴얼 PDF 머리말)도 1.0.6으로 바꿨다. 관리자 콘솔의 릴리스 날짜는 2026-10-08이다.

## 2. 1.0.5를 다시 올리지 않고 1.0.6으로 올린 이유
1. 포털이 같은 버전·채널·프로파일·종류의 파일 업로드를 거부한다(`release_artifact_exists`, 409). 파일을 지우는 기능도 없다.
2. 번호가 같으면 이미 1.0.5를 쓰는 고객에게 업데이트가 전달되지 않는다.
3. Linux `update.sh`는 문제가 생기면 이전 버전 이미지 태그로 되돌리는데, 이전과 새 버전이 같으면 되돌릴 대상이 새 이미지와 같아진다.
4. 이미 내려받은 고객의 파일과 포털의 SHA-256이 달라진다.

## 4. Linux 묶음 원격 빌드 절차 (노트북에서 실행)

1. **LF 소스 묶음 만들기**: 큰 문서 폴더를 빼서 1.4MB가 된다. 서명 검증용 공개키 `.pem` 2개는 빌드에 필요하므로 들어간다.
   ```bash
   git -c core.autocrlf=false archive --format=tar.gz -o worknexus-src-1.0.6.tar.gz HEAD -- . ':!mdfile' ':!marketing-public'
   ```
2. **SSH(22번 포트)로 업로드하고 빌드를 시작**한다.
   - 접속 정보는 `.env`의 `ubuntu_server_*`에서만 읽고 화면·로그에 남기지 않는다(Node `ssh2` 사용).
   - `.env`의 `ubuntu_server_port`는 9090(Cockpit 웹 콘솔)이라 SSH에는 쓰지 않는다.
   ```bash
   # 서버
   mkdir -p ~/worknexus/build-1.0.6 && tar -xzf ~/worknexus/worknexus-src-1.0.6.tar.gz -C ~/worknexus/build-1.0.6
   cd ~/worknexus/build-1.0.6
   setsid nohup bash -c 'bash scripts/package-linux.sh; echo "EXIT $?"' > ~/worknexus/build-1.0.6.log 2>&1 < /dev/null &
   ```
3. **진행 확인**: `tail ~/worknexus/build-1.0.6.log`. 버전 검증 → 앱 이미지 빌드 → LiveKit·Redis·cloudflared 이미지 받기 → 묶음 구성 → 압축 순서로 진행되며, 약 10분 걸렸다.
4. **내려받기와 해시 대조**: 서버의 `sha256sum` 값과 노트북에서 계산한 값이 같은지 확인한다.
5. **정리**: 서버의 소스 압축 파일은 지운다. `~/worknexus/build-1.0.6` 폴더와 로그는 남겼다.

## 5. 공급자 포털에 올리기 (담당자 작업)
1. `https://worknexus.calamus.ai.kr/manage` → 릴리스
2. 버전 `1.0.6`, 채널, 프로파일 `production`, 운영체제 **Windows**로 `.exe`를 올린다. 같은 버전에 `.zip`도 올린다.
3. 운영체제 **Linux 도커 묶음**으로 `.tar.gz`를 같은 1.0.6에 올린다.
4. **서명 후 게시**를 누른다. 업로드한 SHA-256이 3장 표와 같은지 확인한다.
5. 1.0.5는 그대로 둬도 된다. 고객은 1.0.6을 새 업데이트로 받는다.
