## 1. 시작하기 전에 — 큰 그림 이해하기

Virtual Office는 **우리 회사 컴퓨터(서버) 한 대**에서 돌아가는 프로그램입니다. 클라우드에 있는 게 아니라, 우리 회사 안의 컴퓨터 한 대가 "서버" 역할을 합니다.

이해를 돕는 비유를 하나 들면:

- 이 서버 컴퓨터는 **우리 회사 안의 작은 방송국**입니다.
- **회사 고정 도메인** = 임직원이 사내·사외에서 공통으로 사용하는 정식 입구(예: `https://회사이름.calamus.ai.kr`)
- **사내망 IP 주소** = 설치 확인이나 장애 진단에 사용하는 내부 전용 보조 주소(예: `http://192.168.0.100:3001`)
- **임시 외부 주소** = 정식 도메인 발급 전 짧은 시험에만 쓰는 일회성 주소(5장 참고)

> [!IMPORTANT]
> 엔터프라이즈 운영 환경의 기본 접속 주소는 라이선스에 등록된 **`https://회사이름.calamus.ai.kr` 고정 도메인**입니다. 사내 직원, 재택근무자, 외근자 모두 이 주소를 우선 사용합니다. 사내 IP나 `trycloudflare.com` 임시 주소를 임직원용 기본 주소로 배포하지 않습니다.

이 문서는 설치 → 처음 켜기 → 사내 사용 → 외부 사용 → 라이선스 등록 → 문제 해결 순서로 설명합니다.

## 2. 서버 설치하기

1. 고객 다운로드 포털(17장)에서 받은 설치 파일(`VirtualOffice_Server_Setup_v1.x.x_production.exe`)을 서버로 쓸 컴퓨터에 옮깁니다. 리눅스 서버라면 18장을 보세요.
   - 이 컴퓨터는 **회사 근무시간 동안 항상 켜져 있어야** 합니다 (직원들이 접속하는 동안 꺼지면 안 됩니다).
   - 일반 사무용 PC도 괜찮지만, 가능하면 아무도 끄지 않는 전용 PC를 권장합니다.
2. 설치 파일을 더블클릭해서 실행합니다.
3. 화면 안내에 따라 [설치 시작]을 누릅니다 — 별도로 입력할 내용은 거의 없습니다. 바탕화면에 바로가기 아이콘이 자동으로 생성됩니다.
4. 설치가 끝나면 **Node.js나 Docker 같은 프로그램을 따로 설치할 필요가 없습니다.** 전부 설치 파일 안에 이미 포함되어 있습니다.

> 💡 이미 예전 버전이 설치되어 있는 컴퓨터에 새 설치 파일을 실행해도 괜찮습니다 — 기존에 등록된 라이선스, 직원 정보, 대화 기록 등은 **그대로 보존**되고 프로그램 파일만 최신 버전으로 바뀝니다.

## 3. 서버 처음 켜기 & 관리자 계정 만들기

1. 설치 폴더(보통 `C:\Virtual_Office_Server`)에서 **`VirtualOfficeServer.exe`**를 더블클릭합니다.
2. 화면 오른쪽 아래, 시계 옆에 작은 아이콘이 하나 생깁니다. 이게 **"서버 조종실"**입니다. 이 아이콘이 떠 있는 동안은 서버가 계속 켜져 있는 상태입니다.
   - 아이콘이 안 보이면 시계 옆의 위쪽 화살표(▲)를 눌러 숨겨진 아이콘 목록에서 찾아보세요.
3. 최초 관리자 계정을 만들어야 합니다:
   - 설치 폴더 안 `server\data\bootstrap-token.txt` 파일을 메모장으로 엽니다 (설치 직후 딱 한 번만 생기는 파일입니다).
   - 안에 적힌 긴 글자(토큰)를 전체 복사합니다.
   - 이 토큰 값을 가지고 칼라무스 설치 담당자에게 최초 관리자 등록을 요청합니다 (컴퓨터 명령어를 한 줄 실행해야 하는 유일한 단계라, 처음 한 번은 담당자와 함께 진행하시길 권장합니다).
   - 관리자 계정이 만들어지면 이 토큰 파일은 더 이상 필요 없으니 삭제해도 됩니다 (보안을 위해 삭제를 권장합니다).
4. 이후부터는 트레이 아이콘 우클릭 → **"3D 가상오피스 접속"** → 로그인 화면에서 방금 만든 관리자 계정으로 로그인합니다.

## 4. 사내(회사 안)에서 사용하기

정식 라이선스 등록이 끝난 엔터프라이즈 고객은 회사 안에서도 **회사 고정 도메인**을 기본으로 사용합니다.

1. 칼라무스가 발급한 주소(예: `https://회사이름.calamus.ai.kr`)를 사내 포털·메신저·브라우저 즐겨찾기로 배포합니다.
2. 동료들은 Chrome 또는 Edge 주소창에서 이 주소로 접속합니다. 별도 프로그램 설치는 필요 없습니다.
3. 트레이 아이콘의 **"사내망 접속 주소 복사"**로 얻는 `http://192.168.x.x:3001` 주소는 고정 도메인 장애 진단이나 설치 직후 내부 연결 확인에만 사용합니다.

> ⚠️ 사내 IP 주소는 회사 네트워크 밖에서 접속할 수 없으며, 브라우저 보안 정책 때문에 화면공유·마이크·카메라가 제한될 수 있습니다. 정상 업무는 HTTPS 고정 도메인으로 접속하세요.

## 5. 회사 밖(재택·출장)에서 사용하기 — 고정 주소 우선

엔터프라이즈 운영의 표준 접속 방식은 사내와 동일한 **회사 고정 도메인**입니다. 임시 주소는 정식 운영 방식이 아니라 초기 설치 시험이나 장애 확인을 위한 예외 수단입니다.

### 기본 방법. 회사 고정 주소(정식 운영)

칼라무스가 회사 전용 주소(예: `https://회사이름.calamus.ai.kr`)를 발급합니다. 이 주소는 라이선스의 고객·건물·미디어 주소와 함께 서명되며 서버를 재시작해도 바뀌지 않습니다.

1. 칼라무스 담당자에게 회사에서 사용할 도메인 이름을 신청합니다.
2. 담당자가 고정 앱 주소와 화면공유 미디어 주소를 포함한 라이선스(`.calamus-license`)를 발급합니다.
3. 6장의 방법으로 라이선스를 등록하고 서버를 재시작합니다.
4. 서버 상태 화면에서 다음 두 주소가 계약 내용과 일치하는지 확인합니다.
   ```text
   🔒 [고정 외부 접속 주소] https://회사이름.calamus.ai.kr
   🔒 [고정 화면공유 주소] https://회사이름-media.calamus.ai.kr
   ```
5. 임직원에게는 첫 번째 앱 주소를 사내외 공통 접속 주소로 배포합니다. 두 번째 미디어 주소는 LiveKit 연결에 사용되는 시스템 주소이므로 사용자가 직접 열 필요가 없습니다.

### 예외 방법. 임시 주소(짧은 시험 전용)

1. 트레이 아이콘 우클릭 → **"🚨 임시 외부 접속 주소 켜기"**
2. 경고창이 뜹니다 — "이 주소를 아는 사람은 로그인 화면까지는 누구나 들어올 수 있다"는 뜻이니 꼭 읽어주세요.
3. [예]를 누르면 몇 초 뒤 `https://아무개무개.trycloudflare.com` 같은 주소가 자동으로 생성됩니다.
4. 트레이 아이콘 우클릭 → **"외부 공인 접속 주소 복사"**로 이 주소를 복사해서 필요한 사람에게 전달합니다.
5. **다 쓰면 반드시 "임시 외부 접속 주소 끄기"를 눌러 꺼주세요.**

⚠️ **이 주소의 특징**
- 서버를 재시작할 때마다 주소가 **바뀝니다.**
- URL만 알면 누구나 로그인 화면까지 들어올 수 있는 **임시 공개 주소**입니다.
- **매일 계속 켜두는 용도가 아닙니다** — 초기 설정 테스트나 급할 때만 잠깐 쓰는 용도입니다.

### 두 주소의 용도 비교

| | 회사 고정 도메인 | 임시 주소 |
|---|---|---|
| 주소가 바뀌나요? | 바뀌지 않음 | 재시작마다 바뀔 수 있음 |
| 누가 설정하나요? | 칼라무스가 계약·라이선스와 함께 발급 | 고객 관리자가 허용된 시험 환경에서 일시 실행 |
| 언제 쓰나요? | 임직원이 매일 사용하는 기본 주소 | 초기 설치 시험 또는 지원 담당자와 진행하는 단기 진단 |
| 운영 적합성 | 정식 운영 표준 | 상시 운영 금지 |

정식 고정 주소를 사용하는 운영 서버에서는 임시 주소를 함께 켜지 마세요. 운영 모드는 원칙적으로 라이선스에 서명된 고정 주소만 사용하며, Quick Tunnel은 관리자가 `VO_ALLOW_QUICK_TUNNEL=1`로 명시한 단기 시험에만 허용합니다.

## 6. 라이선스 파일 등록하기 (칼라무스에서 받은 파일)

칼라무스에서 이메일 등으로 `.calamus-license` 파일을 받으면 아래처럼 등록합니다.

1. 관리자 계정으로 로그인 후, 화면 우측 상단의 **"관리자 센터"** 또는 **"관리자 콘솔 열기"**를 클릭합니다.
2. **"라이선스"** 탭으로 이동합니다.
3. 받은 `.calamus-license` 파일을 선택해서 올립니다.
4. **"라이선스 등록"** 버튼을 클릭합니다 — "라이선스가 등록되었습니다" 메시지가 뜨면 성공입니다.
5. 트레이 아이콘 우클릭 → **"서버 재시작"**을 눌러 새 라이선스 내용(정원, 회의실 구성, 고정 주소 등)을 반영합니다.

> 💡 라이선스를 새로 등록해도 기존 직원 정보, 대화 기록, 방/좌석 배치 등은 사라지지 않습니다.

## 7. 화면공유·화상회의가 안 될 때

가장 흔한 원인은 **접속 주소가 `http://`(암호화 안 됨)인지 `https://`(암호화됨)인지**입니다. 최신 웹 브라우저(크롬, 엣지 등)는 보안 정책상 암호화 안 된 주소에서는 화면공유·마이크·카메라 기능을 아예 꺼버립니다.

| 접속 방식 | 화면공유 가능 여부 |
|---|---|
| `http://localhost:3001` (서버 컴퓨터 본인) | 가능 (브라우저가 예외로 허용) |
| `http://192.168.x.x:3001` (사내 IP) | **불가능** — 아래 해결법 참고 |
| `https://...trycloudflare.com` (임시 주소) | 기술적으로 가능하지만 단기 시험 전용 |
| `https://회사이름.calamus.ai.kr` (고정 주소) | 가능 (엔터프라이즈 기본) |

**해결법**: 사내 IP(`http://192.168.x.x:3001`) 대신 계약과 라이선스에 등록된 `https://회사이름.calamus.ai.kr` 주소로 다시 접속하세요. 사내 IP 그대로 화면공유를 쓰는 브라우저 보안 예외 설정은 사용자별 설정 오류와 보안 위험을 만들 수 있으므로 정식 운영 절차로 사용하지 않습니다.

더 자세한 내용은 `mdfile/사내망_브라우저_보안_HTTPS_화면공유_FAQ.md`를 참고하세요.

## 8. 일상 관리 — 재시작, 자동 실행, 업데이트

- **뭔가 느려지거나 이상할 때**: 트레이 아이콘 우클릭 → "서버 재시작"을 먼저 눌러보세요. 대부분의 문제가 재시작으로 해결됩니다.
- **컴퓨터를 껐다 켜도 서버가 자동으로 켜지게 하려면**: 트레이 아이콘 우클릭 → "Windows 시작 시 자동 실행"에 체크하세요.
- **새 버전으로 업데이트하려면**: 고객 다운로드 포털(17장)에서 받은 새 설치 파일을 그냥 다시 실행하면 됩니다 — 덮어설치해도 기존 데이터는 보존됩니다(2장 참고).
- **서버를 완전히 끄려면**: 트레이 아이콘 우클릭 → "서버 종료" (끄면 전 직원이 접속할 수 없게 되니 신중히 눌러주세요).

## 10. FAQ — 자주 묻는 질문

### 설치·실행 관련

**Q. 트레이 아이콘이 안 보여요.**
A. `VirtualOfficeServer.exe`를 다시 더블클릭하세요. "이미 실행 중"이라고 뜨면 서버는 이미 켜져 있는 것이니, 화면 오른쪽 아래 숨겨진 아이콘(▲ 화살표)을 눌러 찾아보세요.

**Q. 새 설치 파일로 덮어설치하면 기존 데이터가 사라지나요?**
A. 정상적인 덮어쓰기는 데이터 보존을 목표로 하지만, 작업 전 트레이 메뉴에서 **지금 백업 만들기**를 실행하세요. 백업에 기존 라이선스·터널·LiveKit 설정도 포함되어 같은 PC의 디스크 장애나 Windows 재설치 후에 함께 복원할 수 있습니다. 새 PC·메인보드 교체시에는 하드웨어 불일치로 차단되므로 인증요청파일부터 다시 만들어야 합니다.

**Q. 자동 백업은 어디에 저장되고 어떤 데이터가 들어 가나요?**
A. Production 서버는 실행 중 하루 한 번 운영 DB·아바타·고객 건물 프리셋·라이선스·Cloudflare 터널·LiveKit 자격 증명을 백업하고 최근 30개를 보관합니다. 기본 위치는 Windows `문서\Calamus Virtual Office Backups`이며, 트레이 아이콘 우클릭 → **백업 저장 폴더 설정**에서 BitLocker 암호화 외장 디스크나 접근 통제된 NAS로 바꾸는 것을 권장합니다. 백업은 서버 비밀정보이므로 메일·메신저로 보내지 마세요.

**Q. PC가 고장나서 다른 PC로 복구하려면 어떻게 하나요?**
A. 새 PC에 Production 패키지를 설치하고 백업 폴더를 복원한 뒤, 새 PC에서 `.calamus-request`를 생성해 서버 교체 재발급을 요청합니다. 복원된 기존 라이선스는 하드웨어 불일치로 실행되지 않습니다. 새 라이선스를 등록한 후 고정 도메인·터널·LiveKit을 확인하면 사원·근태·게시글·채팅·아바타·고객 프리셋을 이어서 사용할 수 있습니다.

### 접속 관련

**Q. 사원이 접속이 안 된대요.**
A. 사내·사외 구분 없이 먼저 계약된 `https://회사이름.calamus.ai.kr` 고정 주소를 정확히 입력했는지 확인하세요. 사내 IP 주소나 예전에 만든 임시 주소를 전달하지 않았는지도 확인합니다.

**Q. 외부 접속 주소를 눌렀는데 "준비 중"이라고만 나와요.**
A. 5~10초 정도 걸립니다. 잠시 후 다시 확인해보세요. 계속 안 되면 "서버 재시작" 후 다시 시도하세요.

**Q. 예전엔 되던 외부 주소가 갑자기 안 돼요.**
A. 임시 주소를 시험 중이었다면 서버 재시작으로 주소가 바뀔 수 있습니다. 엔터프라이즈 사용자는 임시 주소를 다시 배포하지 말고 계약된 `https://회사이름.calamus.ai.kr` 고정 주소로 접속하세요. 고정 주소도 열리지 않으면 서버·터널 상태와 라이선스의 도메인 일치 여부를 확인합니다.

**Q. 고정 주소를 쓰고 있었는데 갑자기 임시 주소로 바뀐 것 같아요.**
A. 트레이 메뉴에서 "임시 외부 접속 주소 켜기"를 실수로 누르신 경우일 수 있습니다. "임시 외부 접속 주소 끄기"를 누르고 서버를 재시작하면 다시 고정 주소로 돌아옵니다.

### 화면공유·화상회의 관련

**Q. 화면공유 버튼을 눌렀는데 화면이 안 나가요 / "연결 시간 초과"라고 떠요.**
A. 먼저 `http://` 사내 IP가 아니라 계약된 `https://회사이름.calamus.ai.kr` 고정 주소로 접속했는지 확인합니다. 주소가 맞다면 관리자 센터의 외부망 WebRTC 경로 진단과 12장의 점검 순서를 따릅니다.

**Q. 회의실 팀 채팅에 뜨는 회의실 목록이랑 화면공유할 때 뜨는 회의실 목록이 서로 달라요.**
A. 2026-09-23 업데이트로 두 목록이 항상 같은 기준(관리자가 방별 시설 관리에서 "화상회의 ON"으로 켜둔 방)으로 통일되도록 수정되었습니다. 최신 버전으로 업데이트했는데도 다르다면 서버를 재시작해보세요.

**Q. 회의 중에 마이크를 껐다 켜면 상대에게 안 들리거나, 상대 카메라가 안 보여요.**
A. 2026-09-25 업데이트로 회의 창의 마이크·카메라가 모두 LiveKit 미디어 서버로 전환되어 해결되었습니다. 최신 패키지로 업데이트해 주세요. 그래도 안 되면 회의 창 하단에 "미디어 서버에 연결할 수 없습니다" 안내가 떠 있는지 확인하고 12장을 따릅니다.

**Q. 두 사람이 동시에 말하면 한쪽 목소리만 들려요.**
A. 스피커로 들으면 브라우저의 에코 제거 기능이 상대 목소리가 나오는 동안 내 마이크를 줄입니다. 헤드셋을 쓰면 동시에 말해도 잘 들립니다.

**Q. 1:1 통화를 걸었는데 "상대가 회의 중이거나 다른 통화 중입니다"라고 떠요.**
A. 상대가 화상회의 창에 들어가 있거나 다른 사람과 통화 중이면 통화가 연결되지 않습니다. 상대가 회의를 마친 뒤 다시 걸어 주세요. 상대 머리 위에 "🎥 회의 중" 배지가 보이면 회의 중인 상태입니다.

### 근처 대화·카메라 관련

**Q. 마이크 버튼에 "근처 대화 꺼짐"이라고 나오고 눌러지지 않아요.**
A. 관리자가 근처 음성 대화를 켜지 않았거나(기본은 꺼짐) 그 방만 꺼 둔 상태입니다. 14장을 따라 켜면 됩니다. 화상회의 창 안의 마이크는 이 설정과 관계없이 동작합니다.

**Q. 근처 대화 목소리가 너무 멀리까지 들리거나, 가까이 가도 안 들려요.**
A. 같은 방 안에서 2.5m까지 선명하고 4m 밖에서는 들리지 않도록 정해져 있습니다. 다른 방이나 다른 층에 있으면 가까워도 들리지 않습니다. 왼쪽 아래 근처 대화 패널에 상대 이름과 거리가 보이는지, 상대 이름 옆 🔊를 실수로 눌러 소리를 꺼 두지 않았는지 확인합니다.

**Q. 동료가 카메라를 켜고 끄는 것이 제 화면에 반영되지 않아요.**
A. 2026-09-26 업데이트로 머리 위 카메라가 LiveKit으로 전환되어 같은 방 사람 모두에게 즉시 반영됩니다. 다른 방에 있는 사람의 카메라는 보이지 않는 것이 정상입니다.

**Q. 로그아웃한 동료가 계속 온라인으로 보여요.**
A. 2026-09-26 업데이트로 로그아웃하면 즉시 모든 사람 화면에서 퇴장 처리되도록 수정되었습니다. 최신 패키지로 업데이트해 주세요.

### 사내 대시보드 관련

**Q. 대시보드에 출근 시간은 보이는데 퇴근 시간이 안 보여요.**
A. 2026-09-23 업데이트로 수정되었습니다. 최신 버전으로 업데이트하면 출근 시간 아래에 퇴근 시간이 함께 표시되고(아직 퇴근 전이면 비어 있음), 퇴근 버튼을 누르면 바로 반영됩니다.

### 기타

**Q. "데스크톱 앱"이라는 탭이 있던데 다운로드가 안 돼요.**
A. 윈도우 전용 데스크톱 앱은 아직 준비 중인 기능입니다. 지금은 웹 브라우저(크롬, 엣지)로 동일하게 모든 기능을 이용하실 수 있습니다.

**Q. 라이선스를 등록하는데 `signature_invalid`가 나와요.**
A. 1.0.3 이하 서버에서 다른 PC의 브라우저로 등록할 때 생기던 문제입니다(파일 속 한글이 전송 중 깨짐). 다운로드 포털에서 **1.0.4 이상**을 받아 업데이트한 뒤 **같은 파일**로 다시 등록하세요. 라이선스를 새로 받을 필요는 없습니다.

**Q. 다운로드 포털에 로그인했는데 설치 파일이 안 보여요.**
A. 화면 위에 표시된 이메일이 회사에서 등록한 이메일인지 확인하세요. 다르면 **다른 계정으로 로그인**을 누릅니다(17장).

**Q. 더 궁금한 점이 있어요.**
A. 칼라무스 담당자에게 문의해주세요. 이 문서에서 다루지 않은 내용은 엔지니어용 상세 문서(`0. Windows_서버설치_라이선스발급_운영가이드_2026-09-24.md`, `사내망_브라우저_보안_HTTPS_화면공유_FAQ.md`)에 더 자세히 정리되어 있습니다.

## 11. 인증요청부터 정식 사용까지 — 처음 설치 체크리스트

1. 운영 패키지를 설치하고 서버를 켭니다. Node.js, SQLite, LiveKit, cloudflared는 패키지에 들어 있으므로 따로 설치하지 않습니다.
2. `bootstrap-token.txt`를 사용해 최초 관리자 계정을 한 번만 만듭니다.
3. 관리자 센터의 라이선스 화면에서 `.calamus-request` 인증요청파일을 생성합니다.
4. 이 파일을 칼라무스 담당자에게 전달합니다. 요청 파일에는 서버 공개키/식별자만 있고 직원 DB나 직접 편집한 건물은 들어 있지 않습니다.
5. 담당자는 계약에 연결된 건물셋과 고객 전용 앱/미디어 주소를 확인해 `.calamus-license`를 발급합니다.
6. 고객 관리자가 받은 파일을 등록하고 서버를 재시작합니다.
7. 라이선스 상태가 `active`인지, 표시된 고객명·건물·도메인이 계약과 같은지 확인합니다.
8. 사원을 등록하고 내부 접속을 시험한 뒤, 외부 PC/휴대폰으로 화면공유까지 시험합니다.

### 건물 구성을 변경하려면

고객 관리자 계정에는 건물·방 커스텀 스튜디오가 제공되지 않습니다. 가구 배치, 방 프리셋 또는 건물셋 변경이 필요하면 요구사항을 칼라무스 담당자에게 전달합니다. 칼라무스가 공급자 스튜디오에서 고객 전용 프리셋을 수정·게시한 뒤, 계약 건물셋에 연결하고 새 라이선스를 발급합니다. 고객 관리자는 새 라이선스를 등록하고 서버를 재시작하여 변경된 건물을 적용합니다.

## 12. 화면공유 장애를 확인하는 순서

1. 같은 방을 선택했는지 확인합니다. 화면·음성·채팅은 층이 아니라 실제 방 ID별로 나뉩니다. 회의실 화면공유·회의 음성·1:1 통화·근처 대화·머리 위 카메라는 모두 LiveKit 미디어 서버를 거칩니다. 미디어 주소나 포트가 막히면 이 기능들이 함께 영향을 받습니다.
2. 공유자는 한 방에서만 송출 중인지 확인합니다. 한 방은 발표자 한 명이며 같은 사람의 중복 송출은 막힙니다.
3. 앱 주소와 미디어 주소가 라이선스 화면에 표시된 값과 같은지 확인합니다.
4. 관리자 센터의 **외부망 WebRTC 경로 진단**을 실행합니다.
5. DNS/HTTPS/WSS가 성공해도 미디어 포트 또는 TURN이 막히면 영상·음성은 실패할 수 있습니다. 서버가 아닌 외부 인터넷망 두 곳에서 실제 시험합니다.
6. 문제가 계속되면 진단 결과, 발생 시각, 사용자/방 이름, 앱·미디어 주소를 함께 전달합니다. LiveKit API key/secret이나 터널 토큰은 전달하지 않습니다.

## 13. 관리자 권한과 스튜디오

- 일반 고객 관리자에게 공급자 계약·라이선스 발급 기능은 노출되지 않습니다.
- **고객 관리자와 일반 임직원은 건물·방 커스텀 스튜디오에 접근할 수 없습니다.** 메뉴와 관련 API 모두 공급자 운영 영역입니다.
- 고객 관리자는 계약된 건물 안에서 사원·팀·좌석·방별 시설 등 허용된 운영 항목만 관리합니다. 가구 프리셋, 방 원본, 건물셋의 생성·저장·삭제는 할 수 없습니다.
- 건물 또는 프리셋 변경은 칼라무스 공급자 담당자가 스튜디오에서 작업하고 고객 전용 버전으로 게시한 후 계약과 라이선스에 반영합니다.
- 로그아웃하면 서버 세션도 종료됩니다. 공용 PC에서는 브라우저 창만 닫지 말고 반드시 로그아웃하세요.
- 설치형 Demo에는 여러 샘플 건물이 보이지만, Production은 계약에 서명된 건물이 기준입니다.

## 14. 방 안 근처 음성 대화 켜기/끄기

근처 음성 대화는 같은 방 안에서 가까이(2.5m 선명 · 4m까지) 있는 사람끼리 채팅창 없이 마이크로 대화하는 기능입니다. 사무실·학교·공공기관처럼 시끄러워지면 곤란한 곳이 있으므로 **기본값은 꺼짐**이며, 관리자가 필요한 곳만 켭니다.

1. 관리자 콘솔 → **팀** 탭 → 아래쪽 **방별 시설 관리** 패널로 이동합니다.
2. 초록 상자 **"🗣️ 방 안 근처 음성 대화"**의 **전체 OFF** 버튼을 눌러 **전체 ON**으로 바꿉니다. 새로고침하지 않아도 모든 사용자에게 바로 적용됩니다.
3. 조용해야 하는 방(임원실·도서관·시험실 등)은 방 목록에서 **"🗣️ 근처 대화 ON"** 버튼을 눌러 **OFF**로 바꿉니다.
4. 끄면 그 방에서 진행 중인 대화가 **즉시** 끊기고, 그 방 사용자의 마이크가 자동으로 꺼집니다.

알아 두실 점:
- 화상회의 창의 마이크·카메라, 1:1 통화는 이 설정과 관계없이 동작합니다.
- 머리 위 카메라(HUD 카메라 버튼)도 이 설정과 관계없이 같은 방 사람에게 보입니다.
- 설정은 서버에 저장되어 서버를 재시작해도 유지됩니다.
- 모든 음성·영상은 사내 서버의 LiveKit 미디어 서버를 거치며, 사용자 PC끼리 직접 연결하지 않습니다(사용자 IP가 서로 노출되지 않음).

## 15. 방별 화상회의 예약과 팀 알림

일반 방 회의와 타운홀 세미나는 서로 다른 예약입니다. 일반 방 회의는 3D 오피스 안에서 화상회의 스크린이 켜진 방을 대상으로 하고, 대규모 외부 행사는 타운홀에서 예약합니다. 1.0.8부터는 방 회의에도 협력업체 등을 부르는 **외부 참석 링크**가 있습니다(예약 목록 → 외부 참석, 회의 시작 30분 전~종료 30분 후만 유효).

1. 상단의 **회의** 메뉴에서 **방 회의 예약**을 누릅니다.
2. 회의 제목, 실제 회의 방, 시작 날짜·시간, 종료 날짜·시간을 입력합니다.
3. 참석 대상을 **전사 공통** 또는 **특정 팀 전용**으로 선택합니다. 특정 팀 전용이면 알림을 받을 팀도 반드시 선택합니다.
4. 같은 방에 시간이 겹치는 일정이 있으면 서버가 저장을 거부하므로 기존 일정을 확인해 시간을 조정합니다.
5. 예약자는 자기 일정을 수정·삭제할 수 있고, 관리자는 모든 일정을 관리할 수 있습니다. 다른 일반 사용자는 임의로 변경할 수 없습니다.
6. 대상 직원에게는 시작 30분 전부터 임박 상태가 보이고, 10분 전부터 강조 표시됩니다. 진행 시간이 되면 **진행 중**으로 바뀝니다.
7. 대시보드에는 일정과 실제 방 이름이 표시됩니다. 3D 월드에서는 상단 회의 버튼과 해당 방 안내에 임박/진행 상태가 표시됩니다.

외부 고객 링크, 게스트 등록, 발표자 지정은 일반 방 예약에서 제공하지 않습니다. 이 경우 **타운홀 예약으로 이동**을 사용합니다.

## 16. 동시접속 한도와 방별 회의 정원

### 동시접속 한도 (라이선스)

- 라이선스는 **동시접속자 수(50 / 100 / 200 / 300명)**와 **타운홀 사용 여부**만 정합니다. **등록 사원 수는 제한이 없습니다.**
- 동시접속자는 **3D 오피스에 접속한 사원 + 외부 참석자(타운홀 게스트·방 회의 외부 참석자)**입니다. 같은 사람이 창·탭을 여러 개 열어도 1명입니다.
- 한도에 도달하면 다음 사람은 "동시접속 한도에 도달해 지금은 접속할 수 없습니다" 안내를 봅니다. **자리가 나면 15초 안에 자동으로 접속**됩니다. 외부 게스트는 등록 단계에서 같은 안내를 받습니다.
- 예: 동시접속 100명 계약에서 회의실 6개에 20명씩(120명) 모이면 101번째 사람부터 접속하지 못합니다. 이런 일이 잦으면 트레이 알림에 접속 실패 횟수가 표시되므로, 칼라무스에 계약 변경을 문의하세요.

### 방별 회의 정원 (관리자가 조정)

- 방 스크린을 눌러 **회의 창을 연 사람**(발표 화면·음성·카메라를 받는 사람)만 정원에 들어갑니다. 방을 지나가거나 3D 스크린만 바라보는 사람은 세지 않습니다.
- 기본값: **일반 방 30명, 강당(스튜디오에서 특별실·강당으로 만든 방) 100명**. 100명이 넘는 행사는 **타운홀(최대 200명)**을 사용합니다.
- 바꾸는 방법: 관리자 콘솔 → **팀** 탭 → **방별 시설 관리** → 방 줄의 **👥 정원** 칸에 1~100 사이 숫자를 입력하고 Enter. **기본값** 버튼으로 되돌립니다. 다음 입장부터 적용됩니다.
- 정원이 차면 회의 창에 "회의 정원(n명)이 찼습니다. 자리가 나면 자동으로 입장합니다"가 표시됩니다.
- 회의 화면은 **그 방 안에 있는 사람만** 볼 수 있습니다. 관리자 대시보드의 "지금 공유 중인 화면" 목록은 현황만 보여 줍니다.

### 서버 권장 사양

| 거래처 유형 | CPU | RAM | SSD | 네트워크 |
|---|---|---|---|---|
| 동시 100명 이하 | 4코어 8스레드 | 8 GB | 100 GB | 1 Gbps 유선 |
| 동시 200·300명 | 8코어 16스레드 | 16 GB | 200 GB | 1 Gbps 유선 |
| 강당 100명 발표·타운홀 사용 | 12~16코어 | 32 GB | 300 GB | 2.5 Gbps 유선 권장 (최소 1 Gbps 전용) |

상세 근거는 `mdfile/3. 워크넥서스 사내망 HTTPS 구축 가이드 (고객 IT·보안팀용).md` 1-3을 참고하세요.

## 17. 설치 파일 받기 — 고객 다운로드 포털

설치 파일과 새 버전은 **고객 다운로드 포털**에서 받습니다. 주소는 `https://worknexus.calamus.ai.kr/download`입니다.

### 로그인 (비밀번호 없음)

1. 위 주소를 엽니다.
2. 칼라무스에 등록한 **회사 이메일**을 입력하고 **Send me a code**를 누릅니다.
3. 그 메일로 온 **6자리 번호**를 입력합니다. 비밀번호는 없습니다.
4. 화면 위에 **"● 로그인됨 · 내 이메일"**이 보이고, 그 아래에 회사 이름과 받을 수 있는 버전 목록이 나옵니다.

> 💡 다운로드 계정(이메일)은 칼라무스가 등록해 드립니다. 담당자가 바뀌면 칼라무스에 이메일 추가를 요청하세요.

### 화면에 이런 안내가 나오면

| 안내 | 뜻과 해결 |
|---|---|
| "이 이메일은 다운로드 권한이 등록되어 있지 않습니다" | 다른 이메일로 로그인된 상태입니다. 화면 위 **다른 계정으로 로그인**을 누르고 등록한 이메일로 다시 로그인하세요. |
| "현재 사용할 수 있는 계약을 찾지 못했습니다" | 사용 기간이 끝났거나 아직 시작 전입니다. 칼라무스에 계약 기간을 확인해 달라고 요청하세요. |
| 목록이 비어 있음 | 아직 받을 수 있는 버전이 게시되지 않았습니다. |

### 받기

- **Windows 서버**: 버전 아래 **Windows 설치 프로그램 → 내려받기**를 누릅니다.
- **리눅스 서버**: 18장을 보세요.
- **안전 확인**: 각 파일 아래의 **파일 확인 번호(SHA-256)**는 파일이 중간에 바뀌지 않았는지 확인하는 번호입니다. 리눅스 명령은 이 확인을 자동으로 합니다.

## 18. Linux(리눅스) 서버에 설치하기

회사 서버가 리눅스(Ubuntu 등)라면 Windows 설치 프로그램 대신 **리눅스 서버용(Docker)** 파일을 씁니다. 서버에 **Docker**가 설치돼 있어야 합니다. 없으면 회사 IT 담당자에게 설치를 요청하세요.

### 처음 설치

1. 17장처럼 다운로드 포털에 로그인합니다.
2. 버전 아래 **리눅스 서버용 (Docker) → [서버에서 바로 받기]**를 누릅니다.
3. 초록 상자에 명령 4줄이 나타납니다. **[명령 복사]**를 누릅니다(이 명령은 1시간 동안, 3번까지 쓸 수 있습니다).
4. 서버의 터미널(검은 명령 창)에 붙여 넣고 Enter를 누릅니다. 관리자 비밀번호를 물으면 입력합니다.
5. 끝나면 화면에 다음이 나옵니다. **등록 토큰은 꼭 적어 두세요.**
   - `✅ WorkNexus 서버 … 설치 완료`
   - **접속 주소**(예: `http://192.168.0.10:3001`)
   - **최초 관리자 등록 토큰**
6. 브라우저로 접속 주소를 열어 **최초 관리자 등록**에 토큰을 넣고 관리자 계정을 만듭니다(3장과 같음).
7. 6장처럼 인증요청파일을 보내고, 받은 라이선스 파일을 등록합니다. **리눅스는 서버 재시작이 필요 없습니다.**
8. 라이선스를 등록하면 **1분 안에** 회사 고정 주소(`https://회사이름.calamus.ai.kr`)가 열립니다. 사내에서도 이 주소로 접속해야 마이크·카메라·화면공유를 쓸 수 있습니다.

### 일상 관리 (터미널 명령)

| 하고 싶은 일 | 명령 |
|---|---|
| 상태 보기 | `sudo /opt/worknexus/compose.sh ps` |
| 재시작 | `sudo /opt/worknexus/compose.sh restart` |
| 로그 보기 | `sudo /opt/worknexus/compose.sh logs --tail 100 virtual-office` |

### 새 버전으로 업데이트

설치 때처럼 포털에서 새 버전의 **[서버에서 바로 받기]** 명령을 복사합니다. 붙여 넣기 전에 마지막 줄의 `install.sh`를 `update.sh`로 바꿉니다.
- 업데이트는 데이터를 먼저 백업하고 새 버전을 적용합니다.
- 문제가 생기면 **이전 버전으로 자동으로 되돌립니다.**
- 직원 정보·대화·라이선스는 그대로 유지됩니다.

### 외부 연결 없이(폐쇄망) 쓰려면

처음 설치할 때 마지막 줄을 `sudo ./install.sh --no-tunnel`로 실행합니다. 이미 설치했다면 칼라무스에 문의하세요.

> ⚠️ 리눅스 서버의 방화벽(ufw)은 WorkNexus 포트를 막지 못합니다(Docker가 별도로 엽니다). 접속을 제한하려면 회사 공유기·방화벽 장비에서 설정하세요. 엔지니어용 상세 내용은 `0. Linux_서버패키지구성 및 설치_라이선스발급_운영가이드.md`를 참고하세요.
