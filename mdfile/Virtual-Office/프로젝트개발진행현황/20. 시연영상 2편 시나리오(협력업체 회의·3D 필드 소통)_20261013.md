# 20. 시연영상 2편 시나리오 — 협력업체 회의 · 3D 필드 소통

> 작성일: 2026-10-13 · 대상 버전: 1.0.8
> 대상: 홍보 영상을 기획·녹화하는 담당자와 개발자
> 관련 문서: `12. 홍보영상 제작 시스템(쇼츠·소개영상) 운영가이드_20261008.md`

10/8에 만든 첫 5분 소개 영상(김하늘의 첫 출근 → 화상회의 → 타운홀 세미나)에 이어, **1.0.7~1.0.8에 새로 들어간 기능**을 보여 주는 가로(16:9) 5분 영상 두 편의 시나리오다. 첫 영상과 겹치지 않게 구성했다.

| 편 | 제목 | 핵심 기능 | 진행 |
|---|---|---|---|
| A | 협력업체와 함께하는 개발팀 주간회의 | 팀·전사 일정, 벽 일정 보드, 구글 캘린더 추가, 방 회의 외부 참석 링크, 대시보드 ▶참여하기, 2D 업무 모드 | 먼저 제작 |

### 2.1 확장 제작안 — 직원들의 하루 (2026-10-13)

사용자 결정: B는 직원들의 다양한 일상 소통을 보여 주도록 확장한다. **화상회의는 A에서 다루므로 B에서 제외한다.** 아래 흐름을 기준으로 실제 앱을 자동 녹화한다. 시간은 합본의 `youtube-chapters.txt`로 확정한다.

| 장면 | 직원의 행동 | 보여 줄 기능 |
|---|---|---|
| 출근 | 김하늘이 동료가 있는 개발실에 들어온다 | 접속 중인 동료, 사무실 전경 |
| 가까이서 대화 | 동료에게 다가갔다가 멀어진다 | 마이크 범위 원, 근처 대화 패널, 2.5m 선명·4m 무음 |
| 방 이동과 집중 | 라운지로 이동하고 주변 소리를 차단한다 | 방별 음성 격리, 주변 소리 듣기/차단 |
| 팀 스탠드업 | 팀장의 질문에 찬성·반대·질문, 손들기 후 박수 | 손들기(H, 유지), 좋아요·반대·질문·박수, 머리 위 카메라·말풍선 |
| 동료 인사 | 손을 흔들며 인사한다 | 안녕하세요 반응과 팔 동작 |
| 정보 확인 | 벽 아카이브와 이번 주 일정 보드를 연다 | 게시판·공지, E 키로 팀 달력, 외근·휴가·교육 일정 |
| 외근 연결 | 태블릿 화면에서 이동 패드와 앉기를 쓰고 2D로 바꾼다 | 태블릿 브라우저 에뮬레이션, 이동 패드, 2D 업무 화면, 근처 대화 제외 |
| 개인 협업 | 2D 동료를 찾아 채팅→1:1 통화→시안 공유 | 실제 두 브라우저의 통화 수락, LiveKit 연결, 시안 검토 후 3D로 복귀해도 통화 유지 |
| 마무리 | 루프탑에서 수고 인사와 하트·웃음 | 나머지 반응 2종, 로고·체험 주소 |

녹화 봇의 `reaction()`은 서버 허용 7종을 전송한다. 손들기는 기존 `hand_raise`를 쓴다. 공개 영상에는 가상 직원만 출연하며 실제 연예인 계정은 사용하지 않는다.

재현: `node scripts/promo-studio/servers.mjs --reset=b` → 별도 터미널에서 `node scripts/promo-studio/record-all-b.mjs`. 결과: `recordings/demo-b-16x9/`. `--from=b3-boards` 등으로 이후 장면부터 다시 녹화할 수 있다.

첫 제작본: **6분 35초, 1920×1080, 30fps, 한국어 자막 31개, 챕터 7개**. 화면에 자막을 넣은 파일은 `worknexus-demo-b-captioned.mp4`, 편집용 합본은 `worknexus-demo-b.mp4`. 기존 스튜디오와 동일한 무음 녹화이며 배경음악·내레이션은 포함하지 않는다.

### 2.2 테이블 중심 재연출

사용자 피드백을 반영해, 1F 개발실의 실제 긴 회의 테이블과 의자 좌표에 동료들을 배치했다. 화상회의 창은 열지 않고 근처 대화로 소통한다. 팀장과 질문자는 일어나고, 나머지 동료는 앉아서 반응한다.

- 테이블 어라운드 뷰 → 팀장 발언 샷 → 맞은편 동료 반응 샷 → 질문자 손들기 → 발언자 쪽에서 보는 반대 시점 → 박수 전체 샷 → 인사 교차 샷.
- 카메라 위치·시선·화각을 장면별로 지정하며, 부드러운 이동과 피사계 심도 초점 전환을 사용한다. 가까운 인물 샷의 대사는 하단 자막으로 표시한다.
- 인트로·대화·질문·루프탑·엔딩 사이에 페이드 전환을 넣고, 마지막 로고는 페이드 아웃한다.
- `record-directed-b.mjs`로 인트로·근처 대화·반응·엔딩을 재촬영하고 전체를 다시 합친다. `--only=b2-reactions`로 한 장면만 재촬영 가능.
- 첫 고정 구도 영상은 `recordings/demo-b-16x9/v1-fixed-view/`에 보존한다.
- 카메라 및 초점 제어는 개발 스튜디오 전용이며, 운영 빌드에는 촬영 제어 코드와 후처리 모듈이 포함되지 않는다.
- 재연출 완성본: `worknexus-demo-b-directed.mp4`, **4분 55초, 한국어 자막 34개, 챕터 7개**. 인물 샷에서는 큰 말풍선을 숨기고 실제 대사를 화자 이름과 함께 하단 자막에 표시한다. 루프탑 이동 준비는 녹화에서 제외한다.

## 3. 녹화 시 주의 사항 (소스 확인 결과)

> 녹화 방법과 실제 구현 내용은 `12. 홍보영상 제작 시스템…운영가이드` 3.5절을 따른다. 아래는 기획 단계 메모다.

1. **시간 조건**: 외부 참석 링크와 대시보드 ▶참여하기는 회의 시작 30분 전부터 동작한다. 녹화 시작 시각 기준으로 회의를 "몇 분 뒤 시작"으로 예약해야 한다.
2. **외부 참석자 화면**: `?roomMeeting=<회의ID>&code=<코드>` → `RoomGuestView`. 입력칸은 "이름 (필수)", "회사·소속", "이메일(선택)". 화면에는 터널 주소를 보여 주고 실제로는 녹화 서버 주소로 연다(첫 영상 타운홀 장면과 같은 방식).
3. **구글 캘린더**: 버튼은 `calendar.google.com/calendar/render?action=TEMPLATE…`를 새 탭으로 연다. 구글 로그인이 필요하므로 개인 계정이 화면에 나오지 않게 시연용 계정을 쓴다.
4. **회의 창 분리(PiP)**: 문서 PiP는 별도 창이라 탭 화면 캡처에 잡히지 않는다. 영상에는 2D 전환으로 "회의 유지"를 보여 준다.
5. 출연진·데이터는 녹화 전용 서버(`cinema-data/studio-server`, git 제외)에만 만든다. 운영 LiveKit에 시험 방을 섞지 않는다.
