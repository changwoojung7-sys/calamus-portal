|---|---|---|
| 공급자 통합관리포털 | 칼라무스 운영자 | 고객·계약·건물셋·고정 도메인을 선택하고 라이선스를 발급 |

# 📘 PART 1. 서버 관리자 매뉴얼 (Server Administrator Manual)

## 1.1 솔루션 아키텍처 및 네트워크 구성

Virtual Office Enterprise는 고객 서버에 설치하는 **온프레미스(On-Premise)** 제품입니다. 데이터가 어디를 지나는지는 접속 방식에 따라 다르므로 아래처럼 구분해 설명합니다("외부 전송 없음"처럼 한 문장으로 단정하지 않습니다).

| 데이터 | 위치·경로 |
|---|---|
| 사원·근태·채팅·게시판·예약 DB | 고객 서버 SQLite에만 저장. 공급자·Cloudflare에 저장되지 않음 |
| 음성·카메라·화면공유 미디어 | 고객 서버의 LiveKit SFU가 중계(저장 안 함). Cloudflare를 거치지 않음 |
| 웹 화면·로그인·채팅 등 웹 요청 | **고정 도메인(`회사약칭.calamus.ai.kr`)을 쓰면 Cloudflare 터널을 거침**(HTTPS는 Cloudflare 엣지에서 종료 후 터널로 전달). 사내 IP·사내 도메인 접속이나 Split DNS는 Cloudflare를 거치지 않음 |
| 폐쇄망 모드 | 터널을 끄면(Windows: 관리자 센터 **외부 접속 및 터널 설정 → 외부 터널 차단**, Linux: `install.sh --no-tunnel`) 서버가 외부로 연결하지 않음. 라이선스는 파일로 오프라인 검증. 1.0.7부터 웹 화면 글꼴도 내장되어 사용자 PC가 외부 글꼴 서버에 접속하지 않음 |


```
┌────────────────────────────────────────────────────────────────────────┐
│               🏢 회사 온프레미스 메인 서버 PC (Port 3001)                │
│                                                                        │

│    ├── WebSocket 실시간 서버 (위치, 아바타 모션, 회의 상태 동기화)     │

│   [내장 LiveKit SFU]                                                    │
│    └── 모든 화면·음성·영상 전달 (회의실·1:1·근처 대화·머리 위 카메라)  │
└───────────────────────────────────▲────────────────────────────────────┘
                                    │
          ┌─────────────────────────┴─────────────────────────┐
          │ 사내망 Wi-Fi / 랜선 (Port 3001)                    │ 공인 터널 (HTTPS)
          ▼                                                   ▼
┌──────────────────────────────┐            ┌──────────────────────────────┐
│  사내 근무자 PC / 노트북     │            │  재택 / 외근 / 스마트폰 모바일│
```

### 주요 포트 및 프로토콜

| 포트 | 프로토콜 | 용도 | 설명 |
|:---:|:---:|:---|:---|
| **3001** | HTTP / WS | **통합 온프레미스 운영 서버** | 3D 웹앱(dist) + SQLite DB + WebSocket + REST API 올인원 |
| **5173** | HTTP/HTTPS | **개발 서버 (Vite)** | 개발 모드(`npm run dev`) 구동 시 HMR 지원 |
| **7880** | HTTP / WS | **LiveKit 신호 서버(내부)** | 앱이 미디어 방에 입장하기 위한 신호 교환 |
| **7881** | TCP | **LiveKit ICE/TCP** | UDP가 막힌 환경의 미디어 대체 경로 |
| **50000~50200** (Windows) / **50000~50300** (Linux 도커판) | UDP | **LiveKit 미디어** | 지연이 가장 낮은 기본 미디어 경로. 설치판마다 범위가 다르므로 설치한 판의 범위만 엽니다 |
| **3478** | UDP | **내장 TURN** | NAT/방화벽 환경의 중계 경로. Linux 도커판은 기본 사용, Windows는 설정한 경우만 |
| **443** | HTTPS / WSS | **Cloudflare Named Tunnel** | 고객 앱과 LiveKit 신호 주소. 실제 UDP 미디어를 대신 전달하지는 않음 |

## 1.2 서버 설치 및 초기 설정 (install-server.bat)

회사는 소스 코드 전체를 다룰 필요 없이, **서버 설치 패키지(`Virtual_Office_Server_v1.0.zip`)**만 사내 서버 컴퓨터에 다운로드하여 설치합니다.

### Step-by-Step 설치 절차

1. **사내 서버 컴퓨터 준비**:
   - Windows 10/11 또는 Windows Server (RAM 8GB 이상, 유선 LAN 연결 권장).
   - 운영 패키지에는 포터블 Node.js, SQLite, LiveKit, cloudflared가 포함되므로 별도 설치하지 않습니다.
2. **패키지 압축 해제**:
   - `Virtual_Office_Server_v1.0.zip` 파일을 원하는 경로(예: `C:\VirtualOffice-Server`)에 압축 해제합니다.
3. **`install-server.bat` 더블클릭 실행**:
   - 스크립트가 다음 과정을 전자동으로 진행합니다:
     - `[Step 1/5]` 패키지에 포함된 포터블 런타임 확인
     - `[Step 2/5]` 3D 클라이언트 웹 빌드 번들(`dist/`) 유효성 확인
     - `[Step 3/5]` 서버 라이브러리(`server/node_modules`) 자동 설치 및 기본 SQLite 템플릿 DB 복사
     - `[Step 4/5]` Cloudflare 터널 바이너리(`bin/cloudflared.exe`) 확인 및 미보유 시 자동 다운로드
     - `[Step 5/5]` 사내망 IPv4 주소 자동 감지 후 서버 즉시 구동

> [!IMPORTANT]
> **Windows 방화벽 인바운드 허용**:
> 최초 실행 시 Windows 보안 경고 팝업이 뜨면 **[개인 네트워크 및 사내 네트워크]** 체크박스를 반드시 선택하고 **[액세스 허용]**을 클릭해야 사내 다른 PC에서 정상 접속할 수 있습니다.

## 1.3 일상 서버 가동 및 터널 연동 (start-server.bat)

설치가 완료된 이후에는 서버 PC에서 **`start-server.bat`** 파일만 더블클릭하면 즉시 일상 운영이 시작됩니다.

### 실행 화면 및 콘솔 안내

```text
╔══════════════════════════════════════════════════════════════════════╗
║         🏢 Virtual Office Enterprise - 온프레미스 서버               ║
║        (3D 웹 클라이언트 + SQLite DB + WebSocket + REST)             ║
╚══════════════════════════════════════════════════════════════════════╝

[1] 사내망 네트워크 접속 주소:
    ▶  사내망 접속: http://192.168.219.104:3001
    ▶  서버 로컬:   http://localhost:3001

   🔒 [공인 HTTPS 터널 주소] https://random-name.trycloudflare.com
      ▶ 재택/외근/모바일 접속 가능 (공인 SSL 암호화 적용)
      ▶ 앱 HTTPS/WSS 연결 지원 (외부 미디어는 ICE/TURN 경로 별도 점검 필요)

[2] 사원 PC 이용 안내 (무설치 Zero-Install):
    * 사원들은 별도 프로그램을 설치할 필요가 없습니다.
    * 크롬(Chrome), 엣지(Edge) 브라우저로 위 주소에 바로 접속하시면 됩니다.

[3] 관리자 계정 안내:
    * 신규 고객사 설치본은 최초 부팅 시 콘솔에 출력되는 부트스트랩 토큰으로
      /api/setup/admin에서 최초 관리자 계정을 직접 등록합니다(고정된 기본
      관리자 계정이 없습니다 — 아래 1.5절 참고).
    * 개발/데모 환경은 마스터 개발자 계정(yujinit2005@gmail.com)이 매 부팅
      시 자동으로 복구되어 바로 로그인할 수 있습니다.
```

- **사내 근무자 안내**: 사내망 접속 주소(`http://192.168.X.X:3001`)를 사내 게시판이나 메신저로 공지합니다.
- **사외/재택 근무자 안내**: 정식 운영은 라이선스에 서명된 고객 전용 Named Tunnel 주소를 안내합니다. `trycloudflare.com` Quick Tunnel은 명시적으로 허용한 임시 시험용이며 운영 기본값이 아닙니다.
- **서버 종료 방법**: 해당 콘솔 창에서 `Ctrl + C`를 누르거나 창을 닫으면 서버 및 백그라운드 터널 프로세스가 안전하게 자동 종료됩니다.

## 1.4 개발자 모드 (npm run dev & 자동 터널)

로컬 개발 환경에서 기능 추가나 코드 수정을 진행할 때는 `npm run dev`를 사용합니다.

- **포트(2026-10-12 정리)**: 소스에서 바로 실행한 개발 서버는 데모 프로파일이라 **3002**에서 뜹니다(같은 PC의 운영 설치본은 3001). `npm run dev`가 개발 화면(5173)과 공급자 포털 화면(5174)을 이 개발 서버로 자동 연결합니다. 시작할 때 `Customer server : http://localhost:3002 (demo profile)`, `Customer office : http://localhost:5173 → API http://localhost:3002`가 표시됩니다.
- 운영 설치본(3001)에 붙여 보고 싶으면 `VO_DEV_API_TARGET=http://localhost:3001`을 지정하고 실행합니다.
- 5173·5174 포트를 예전 개발 화면이 잡고 있으면 새 화면이 뜨지 않습니다(고정 포트). 남은 node 창을 먼저 닫습니다.

- [scripts/viteCloudflareTunnelPlugin.ts](../scripts/viteCloudflareTunnelPlugin.ts)가 `vite.config.ts`에 내장되어 있어, 개발 서버 기동과 동시에 `cloudflared.exe`가 백그라운드로 자동 실행됩니다.
- Vite 터미널의 `Local`, `Network` 주소 바로 아래에 다음과 같이 공인 터널 주소가 함께 출력됩니다:
  ```bash
    ➜  Local:   https://localhost:5173/
    ➜  Network: https://192.168.219.104:5173/
    ➜  Tunnel:  https://xxxx-xxxx.trycloudflare.com/ (공인 HTTPS - 사외/모바일/화상회의 지원)
  ```
- 키보드 `r`(재시작) 또는 `u`(URL 보기)를 누를 때도 Tunnel 주소가 유지됩니다.

## 1.6 건물 방 구조 기반 부서·시설 자동 생성 및 방별 시설 관리

Virtual Office의 건물 구조(층수, 방 배치, 방 이름)는 고정된 1F~4F 레이아웃이 아니라 **계약된 건물 템플릿**(공급자가 라이선스에 서명해 발급한 실제 건물, 또는 데모 환경의 학교/스타트업/일반회사 등 샘플 템플릿)에 따라 정해집니다. 관리자는 이 실제 방 구조를 기준으로 부서와 회의 시설을 자동으로 채울 수 있습니다.

- **건물 방 구조로 부서 자동 생성** ([관리자 콘솔] ➔ [팀] 탭): 버튼 한 번으로 현재 건물의 모든 방을 분석해 방마다 부서(팀)를 자동 생성·매핑하고, 방에 화상회의 스크린(`screenSlot`)이나 화이트보드(`whiteboard`)가 지정되어 있으면 해당 시설의 마스터 레코드도 함께 생성합니다. 이미 생성된 방을 다시 실행해도 기존 배치를 덮어쓰지 않고 갱신만 합니다.
- **방별 시설 관리** (같은 탭의 하단 패널): 방마다 부여된 직렬 코드(예: `RM-STU-101`)와 함께, 화상회의 스크린·화이트보드 사용 여부를 방 단위로 개별적으로 켜고 끌 수 있습니다. 자동 생성 시 시설이 없던 방도 여기서 수동으로 추가할 수 있습니다.
- **근처 음성 대화 설정** (같은 패널 상단의 초록 상자): 같은 방 안에서 가까이 있는 사람끼리 마이크로 대화하는 기능을 켜고 끕니다(2.6.2절).
  - **전체 ON/OFF**: 건물 전체 스위치입니다. 기본값은 **꺼짐**이라 관리자가 켜야 사용할 수 있습니다.
  - **방별 "🗣️ 근처 대화 ON/OFF"**: 전체를 켠 상태에서 임원실·도서관·시험실처럼 조용해야 하는 방만 끌 수 있습니다.
  - 끄면 그 방에서 진행 중인 대화가 **즉시** 끊기고, 사용자 마이크 버튼이 "근처 대화 꺼짐"으로 바뀝니다. 화상회의(회의 창)와 머리 위 카메라에는 영향이 없습니다.
- 팀명, 층별 인원 정원, 좌석 배치 형태를 수정하면 3D 월드의 책상과 아바타 좌석이 실시간 동적 재배치됩니다.

## 1.8 SQLite DB 백업, 마이그레이션 및 방화벽 포트 설정

- **데이터베이스 파일 위치**: `server/data/virtual_office.db`
- **권장 백업**: Production 트레이 아이콘 우클릭 → **운영 데이터 백업 및 복원**을 사용합니다. 서버 실행 중에도 SQLite online backup으로 일관된 스냅샷을 만들고, 하루 한 번 최근 30개를 보관합니다.
- **포함 범위**: DB, 업로드된 아바타, 고객 건물 프리셋, 설치 개인키·라이선스, Cloudflare 터널 설정·토큰, LiveKit 자격 증명·런타임 설정입니다. 같은 하드웨어에서 디스크 장애나 Windows 재설치 후 전체 운영 환경을 복구하는 용도입니다.
- **보안 주의**: 백업에 서버 비밀정보가 포함되므로 일반 클라우드 링크·메일·메신저로 전송하지 않습니다.
- **저장 위치**: 서버 PC 내부 디스크만 사용하지 말고 BitLocker 암호화 외장 디스크 또는 접근 통제된 NAS를 지정합니다.
- **방화벽 수동 개방 명령 (필요 시 Windows PowerShell 관리자 권한)**:
  ```powershell
  New-NetFirewallRule -DisplayName "Virtual Office Server" -Direction Inbound -LocalPort 3001 -Protocol TCP -Action Allow
  ```
- **Linux 도커판**: 백업은 `update.sh`가 업데이트 때마다 자동으로 만들고, 수동 백업·복구 명령은 `0. Linux_서버패키지구성 및 설치_라이선스발급_운영가이드.md` 9장에 있습니다. 리눅스 ufw는 Docker 포트를 막지 못하므로 접근 제한은 사내 방화벽 장비에서 합니다(같은 문서 8장).

## 2.1 프로그램 무설치(Zero-Install) 브라우저 접속

일반 사원과 임직원은 PC나 스마트폰에 **어떠한 프로그램도 설치할 필요가 없습니다.**

1. **사내망 근무 시**:
   - 사내 Wi-Fi 또는 유선랜에 연결된 PC에서 브라우저(Chrome, Edge, Whale, Safari 등)를 실행합니다.
   - 주소창에 사내 서버 주소를 입력합니다:
     ```text
     http://[서버IP]:3001
     ```
2. **재택근무 / 외근 / 스마트폰 접속 시**:
   - 관리자가 공유한 공인 HTTPS 터널 주소를 입력합니다:
     ```text
     https://[도메인].trycloudflare.com
     ```
3. **다이렉트 출근 북마크 (팁)**:
   - 매일 출근하는 사원은 소개 포털을 거치지 않고 바로 로그인 모달로 직행할 수 있도록 브라우저 즐겨찾기에 등록합니다:
     ```text
     http://[서버IP]:3001/?view=office
     ```

### Chrome·Edge 그래픽 가속 설정(PC 권장)

3D 오피스와 화면공유 영상을 부드럽게 표시하려면 PC 브라우저의 그래픽 가속을 켜는 것을 권장합니다. 이 설정은 **화면을 보내는 PC의 브라우저 렌더링·영상 인코딩**과 **시청하는 PC의 영상 디코딩·3D 표시**에 도움을 줍니다. LiveKit SFU 서버에 고성능 그래픽카드가 반드시 필요하다는 뜻은 아닙니다.

#### Google Chrome

1. 주소창에 `chrome://settings/system`을 입력합니다.
2. **가능한 경우 그래픽 가속 사용**을 켭니다.
3. 표시되는 **다시 시작** 버튼을 눌러 Chrome을 재실행합니다.
4. 주소창에 `chrome://gpu`를 입력하고 `Graphics Feature Status`의 주요 항목과 `Video Decode`가 `Hardware accelerated`로 표시되는지 확인합니다.

#### Microsoft Edge

1. 주소창에 `edge://settings/system`을 입력합니다.
2. **가능한 경우 그래픽 가속 사용**을 켭니다.
3. 표시되는 **다시 시작** 버튼을 눌러 Edge를 재실행합니다.
4. 주소창에 `edge://gpu`를 입력하고 `Graphics Feature Status`의 주요 항목과 `Video Decode`가 `Hardware accelerated`로 표시되는지 확인합니다.

설정 항목이 잠겨 있거나 변경할 수 없다면 회사의 브라우저 정책으로 관리되는 PC일 수 있으므로 사내 IT·보안 담당자에게 요청합니다. 가속을 켠 뒤 화면이 검게 보이거나 심하게 깜빡이면 그래픽 드라이버와 브라우저를 먼저 업데이트한 후 다시 시험합니다. 스마트폰·태블릿 브라우저는 일반적으로 이 항목을 별도로 제공하지 않고 운영체제가 자동 관리합니다.

## 2.2 사원 로그인, 최초 비밀번호 변경 및 자동 출근 (clock_in)

1. 화면 중앙의 로그인 모달(또는 우측 상단의 **`사원/관리자 계정 변경`** 버튼)을 엽니다.
2. **[임직원 로그인]** 탭을 선택합니다.
3. 상단의 층수 필터 또는 **사원 검색창**에 본인 이름을 입력하여 본인 카드를 찾습니다(표시되는 층수/방 구조는 회사마다 계약된 건물 템플릿에 따라 다릅니다). 회사가 **로그인 전 사원 목록 숨기기**를 켰다면 사원 카드 대신 안내가 보이며, 위쪽 **이메일로 직접 로그인**에 회사 이메일과 비밀번호를 입력합니다.
4. 본인 사원 카드를 클릭하면 **비밀번호 입력 팝업**이 표시됩니다.
5. 비밀번호(관리자가 알려 준 초기 비밀번호: 기본 **`1234`**, 회사가 무작위 발급을 쓰면 10자리 비밀번호)를 입력하고 **[입장 및 출근 완료]** 버튼을 클릭합니다.
6. **최초 로그인 시 비밀번호 변경(필수)**: 기본 비밀번호를 그대로 쓰는 계정은 3D 오피스에 들어가기 전에 새 비밀번호를 설정하는 화면이 강제로 표시됩니다. 새 비밀번호와 확인란만 입력하면 되며, 이 단계를 건너뛰고 입장할 수 없습니다.
7. **자동 출근 등록**: 로그인 성공과 동시에(최초 로그인이면 비밀번호를 바꾼 직후) 사내 근태 DB에 오늘의 출근 시간(`clock_in`)이 자동 등록되며, 본인의 지정 층/방 좌석으로 즉시 입장합니다.
8. **로그인 유지와 자동 로그아웃**: 로그인은 최대 24시간 유지됩니다. 회사가 **미사용 자동 로그아웃**을 켰다면 정해진 시간 동안 입력이 없을 때 1분 전에 경고가 뜨고, **계속 사용**을 누르지 않으면 로그아웃됩니다. 이때 근태는 퇴근이 아니라 **자리 비움**으로 기록되고, 로그인 화면에 "장시간 사용하지 않아 자동 로그아웃되었습니다"가 표시됩니다. 다시 로그인하면 출근 기록에 "자동 로그아웃 후 재접속"이 남습니다. 회의·통화·화면공유 중에는 자동 로그아웃되지 않습니다.

## 2.3 3D 오피스 공간 조작 및 층간 이동

- **이동 조작**:
  - **마우스 조작**: 바닥의 원하는 위치를 마우스 좌클릭하면 해당 좌표로 아바타가 부드럽게 걸어갑니다.
  - **키보드 조작**: `W`, `A`, `S`, `D` 또는 `방향키`로 전후좌우 자유롭게 이동합니다.
- **카메라 시점 변경**:
  - `Follow 모드`: 내 아바타를 중심으로 3인칭 시점이 부드럽게 따라갑니다.
  - `Free 모드`: 마우스 드래그로 오피스 전체를 자유로운 각도와 거리에서 조망합니다.
- **층간 이동 방법**:
  - 화면 상단의 **층 선택 버튼**으로 이동할 층을 고른 뒤, 옆의 **방 선택 메뉴**에서 목적 방을 선택합니다. 선택한 층과 방으로 즉시 이동합니다.
- **휴대폰·태블릿**(1.0.7): 터치되는 기기에서는 화면 왼쪽 아래 **조이스틱**(끝까지 밀면 달리기)과 오른쪽 **앉기/일어서기** 버튼이 보입니다. 화면 크기와 관계없이 표시되며, **설정 > 화면** 또는 하단 **더보기**에서 자동/항상 표시/숨김을 기기별로 고릅니다. 휴대폰 화면의 하단 버튼에는 짧은 이름이 붙고, 아바타·내 자리 저장·동료·조작 안내 등은 **더보기**에 모여 있습니다.
- **반응**(1.0.7): 하단 **😀 반응** 버튼으로 ✋ 손들기(다시 누르거나 `H` 키로 내릴 때까지 유지), 👋 안녕하세요, 👍 좋아요, 👎 반대, 👏 박수, ❤️ 하트, 😂 웃음, ❓ 질문을 고릅니다. 약 3초 동안 머리 위에 효과와 함께 표시되어 같은 방 동료에게 보입니다(안녕하세요·박수는 팔 동작 포함).
- **디지털 게시판·화이트보드**: 방 벽의 **디지털 사내 아카이브** 게시판과 화이트보드는 **클릭**하거나, 앞으로 다가가 안내가 뜨면 **`E` 키**로 엽니다. 벽에 붙은 게시판·화이트보드·스크린은 항상 방 안쪽을 보도록 자동으로 정렬됩니다.
- **동료 아바타**: 같은 공간에 있는 동료의 아바타는 본인 아바타와 동일한 수준으로 얼굴·상의·하의가 그대로 표시됩니다(단색 실루엣이 아닙니다) — 프로필에서 설정한 외형이 다른 사람 화면에도 실시간으로 반영됩니다.

## 2.4 방 단위 화상 회의 & 화면 공유

각 회의실은 실제 건물 구조상의 방을 기준으로 독립된 화상 회의·채팅·화면 공유 세션을 가집니다 — 여러 회의실에서 동시에 회의를 진행해도 서로 섞이지 않습니다(관리자가 "방별 시설 관리"에서 해당 방의 화상회의/화면공유 사용을 켜둔 경우).

- **그 방에 있어야 송출·참여할 수 있습니다**(방 격리 원칙). 화면 공유 회의실 선택 창에서 다른 층·다른 방을 고르면 버튼이 **이동해서 송출 / 이동해서 회의 참여**로 바뀌고, 누르면 캐릭터가 그 방으로 이동한 뒤 진행됩니다(1.0.7).
- 다른 사람의 공유 화면이 아직 도착하지 않았을 때는 검은 화면 대신 연결 단계와 진행 표시가 보입니다(1.0.6).

### 회의 예약과 임박 알림

1. 상단 HUD의 **`[회의]`** 버튼에서 건물 안의 회의 방, 시작·종료 날짜와 시간, 참석 대상을 지정합니다.
2. 참석 대상은 **전사** 또는 **특정 팀**입니다. 특정 팀을 선택하면 실제 등록된 팀 목록에서 알림 대상을 고릅니다.
3. 같은 방에 시간이 겹치는 예약은 서버가 차단합니다. 날짜가 지난 예약이나 종료가 시작보다 빠른 일정도 저장되지 않습니다.
4. 대시보드에는 `D-N`, `N시간 후`, `30분 후`, `곧 시작`, `진행 중` 상태가 표시됩니다.
5. 전사 회의는 모두에게, 팀 회의는 해당 팀·예약자·관리자에게 임박 알림이 표시됩니다. 현재 들어온 방에 30분 이내 회의가 있거나 진행 중이면 3D 화면 상단에도 방 알림이 나타납니다.
6. 외부 고객 초대 링크와 게스트 등록은 일반 방 회의에서 제공하지 않습니다. **`[타운홀 예약으로 이동]`**을 눌러 타운홀·외부 세미나 일정에서 등록합니다.
7. 예약자는 목록의 연필 버튼으로 자기 회의를 수정하고 삭제할 수 있습니다. 관리자는 모든 예약을 관리할 수 있으며, 변경 내용은 접속 중인 사용자에게 새로고침 없이 반영됩니다.
8. 과거 버전에서 등록된 날짜 없는 일정은 삭제하지 않고 **날짜 미지정·기존 예약**으로 표시하지만, 잘못된 임박 알림을 막기 위해 자동 알림 대상에서는 제외합니다.

1. **내 화면 공유 시작**:
   - 하단 툴바의 **`[🖥️ 화면 공유]`** 버튼을 클릭합니다.
   - 전체 화면, 특정 애플리케이션 창, 브라우저 탭 중 원하는 화면을 선택합니다.
   - **공유 강조 효과**: 내가 화면을 공유 중일 때는 화면 전체 외곽에 **시안(Cyan) 네온 글로우 테두리**가 표시되어 현재 공유 상태임을 한눈에 인지할 수 있습니다.
   - 회의실 화면 공유는 사내 서버에 내장된 **LiveKit 미디어 서버**를 거쳐 전송됩니다. 시청하는 동료가 몇 명이든 화면을 공유하는 사람의 PC는 한 번만 업로드하면 되므로, 노트북처럼 성능이 낮은 PC로 발표해도 시청 인원이 늘어난다고 화면이 버벅이지 않습니다.
2. **동료의 공유 화면 시청**:
   - 회의실 중앙의 대형 3D 스크린을 클릭하면, **리사이즈 및 자유 이동이 가능한 플로팅 뷰어 창**이 즉시 열립니다.
   - 창 우하단 모서리를 드래그하여 원하는 크기로 확대하거나 최대화하여 볼 수 있습니다.
   - 모바일에서 화상회의에 참여할 때도 세로 화면을 그대로 유지한 채 하단의 마이크/카메라 버튼을 바로 사용할 수 있습니다(가로로 돌릴 필요 없음).
   - 스마트폰·태블릿에서는 화상회의 창을 여는 동안 뒤쪽 3D 오피스 렌더링이 기본적으로 정지됩니다. 음성·카메라·화면공유·채팅 연결은 그대로 유지되며, 회의창을 닫으면 3D 화면이 자동으로 다시 움직입니다.
   - 회의창 상단의 **`[3D 절전 On]`** 버튼으로 이 동작을 끄거나 다시 켤 수 있습니다. 장시간 회의에서는 발열과 배터리 소모를 줄이기 위해 `On` 상태를 권장합니다.
   - 모바일 가로 전환 안내는 표시하지 않으며, **전체화면** 버튼도 현재 사용 중인 세로·가로 방향을 그대로 유지합니다.
3. **정식 화상 회의(참가자 명단·발표자 제어)**: 같은 방에서 회의를 시작하면 참가자 명단이 있는 정식 회의 세션이 열립니다. 계약에 등록된 "동시 회의 세션 개수" 한도를 넘으면 새 회의 시작이 거부되고, 동료가 이미 참여 중인 세션에는 자유롭게 합류할 수 있습니다.
4. **참석자 피드 및 발언자 감지**:
   - 공유 화면 우측에 회의 참석자 목록과 본인의 라이브 웹캠/아바타가 표시됩니다.
   - 누군가 음성으로 발언하면 해당 참석자의 프로필 테두리에 녹색 파형 애니메이션이 표시되어 발언자를 즉시 확인할 수 있습니다.
5. **마이크 / 카메라 제어**:
   - 화상회의 창 하단 컨트롤 바에서 마이크(`[🎤 음성 On/Off]`) 및 카메라(`[📷 웹캠 On/Off]`)를 클릭 한 번으로 손쉽게 전환할 수 있습니다. HUD 마이크 버튼과 `M` 키도 회의 창이 열려 있는 동안에는 회의 마이크로 동작합니다.
   - 회의 음성·카메라도 화면공유와 같은 **LiveKit 미디어 서버**로 전송됩니다. 회의 창에 들어온 사람끼리만 듣고 보며, 3D 스크린만 보는 사람이나 같은 방에서 근처 대화 중인 사람에게는 들리지 않습니다.
   - 회의 창은 거리와 관계없이 참여할 수 있습니다. 벽 스크린을 멀리서 클릭하거나 하단 미리보기를 확대해도 바로 들어갑니다.
   - 근처 대화 중 마이크를 켠 채 회의 창을 열면 마이크가 회의로 옮겨집니다. 회의 창을 닫으면 마이크가 **꺼진 상태로** 돌아옵니다(주변에 목소리가 새지 않도록).
   - 회의 참여자 머리 위에는 "🎥 회의 중" 배지가 표시됩니다. 이 사람에게 근처에서 말을 걸어도 들리지 않는다는 뜻입니다.
   - 미디어 서버에 연결할 수 없으면 회의 창 하단에 안내가 뜨고 마이크·카메라 켜기가 비활성화됩니다.
   - 아이폰 등에서 소리가 나지 않으면 **"회의 소리 재생"** 버튼을 한 번 눌러 주세요.
   - 스피커로 들으면 두 사람이 동시에 말할 때 한쪽 목소리가 작아질 수 있습니다(브라우저 에코 제거). **헤드셋 사용을 권장합니다.**

## 2.5 주최자 전용 브라우저 녹화

녹화는 화면공유를 시작한 **주최자에게만** 허용되며, 결과 파일은 주최자의 브라우저에서 생성·다운로드됩니다. 중앙 서버가 모든 회의를 자동 보관하는 구조는 아닙니다.

1. **녹화 시작**:
   - 화상회의 뷰어 창 하단 중앙의 **`[🔴 회의 녹화]`** 버튼을 클릭합니다.
   - 녹화 프리셋을 선택합니다:
     - **초경량 모드 (80% 절감 권장)**: VP9 750kbps + Opus 24kbps (시간당 약 350MB)
     - **표준 모드**: VP9 1200kbps + Opus 48kbps (시간당 약 550MB)
     - **고화질 모드**: VP9 2500kbps + Opus 64kbps (선명한 텍스트 보존)
2. **녹화 진행 중 표시**:
   - 화면 상단에 붉은색 녹화 인디케이터와 경과 시간 타이머가 표시됩니다.
3. **음성/영상 분리 동시 저장 및 프리뷰**:
   - 녹화를 중지하면 **`MeetingRecordingModal`**이 자동으로 열립니다.
   - **영상 WebM 파일**: 발표 자료와 발언자 얼굴이 합성된 고화질 영상 다운로드
   - **음성 WebM 파일**: 회의록 작성 및 AI STT 텍스트 변환용 고음질 오디오 다운로드
   - 중앙 녹화 저장소, 보존기간 정책, 서버 기반 STT/AI 회의록은 별도 확장 기능이며 현재 기본 패키지의 완료 기능으로 보지 않습니다.

## 2.6 방 단위 채팅 및 1:1 비밀 귓속말

- **채팅창 열기**: 하단 툴바의 **`[💬 사내 채팅]`** 아이콘을 클릭합니다.
- **창 크기 조절 및 최대화**:
  - 우하단의 리사이즈 핸들을 잡고 드래그하여 채팅창 크기를 자유롭게 늘리거나 줄일 수 있습니다.
  - 헤더의 **최대화(Square) 버튼**을 누르면 대화에 집중할 수 있는 대형 뷰로 확장됩니다.
- **채널 선택**:
  - **회의실 채팅**: 건물의 실제 방마다 독립된 채팅방이 자동으로 생깁니다. 드롭다운에서 방을 선택하면 그 방의 채팅으로 전환되며, 다른 방에서 나눈 대화와 섞이지 않습니다(2.4절의 방 단위 화상 회의와 동일한 방 단위로 분리).
  - **1:1 귓속말**: 특정 동료를 선택하여 다른 사람에게 보이지 않는 비밀 업무 대화 진행
  - **1:1 화면 공유**: 1:1 대화 중에도 화면 공유가 가능합니다. 공유한 화면과 소리(탭 오디오를 함께 선택한 경우)는 **두 사람 전용 LiveKit 방**으로만 전송되어 대화 상대에게만 표시되며, 다른 동료에게는 전혀 전달되지 않습니다. 소리가 막히면 공유 화면 왼쪽 아래 **"공유 소리 재생"** 버튼을 누르세요.
- **메시지 관리**:
  - 본인이 전송한 메시지 옆의 휴지통 아이콘을 클릭하면 DB에서 영구 삭제됩니다.

## 2.6.1 1:1 음성·영상 통화

1:1 채팅 상단의 **`[📞 통화]`** 버튼으로 대화 상대에게 음성 통화를 겁니다.

1. **걸기**: 내 화면 왼쪽 아래에 "거는 중" 카드가 뜨고, 상대 화면 왼쪽 아래에는 **수락 / 거절** 카드가 뜹니다. 30초 동안 응답이 없으면 자동으로 취소됩니다.
2. **통화 중**: 통화 카드에 상대 카메라(꺼져 있으면 프로필), 통화 시간, 내 카메라 미리보기가 보이고, 마이크·카메라·채팅 열기·종료 버튼이 있습니다. 상대가 말하면 카드 테두리가 초록으로 빛납니다.
3. **화면공유와 함께 쓰기**: 통화 중에 채팅 창의 **`[화면공유]`**를 켜고 끌 수 있습니다. 화면공유를 끝내도 통화는 끊기지 않고, 통화를 끝내도 화면공유는 유지됩니다.
4. **이럴 때는 연결되지 않습니다**:
   - 상대가 **화상회의 중**이거나 다른 통화 중이면 "상대가 회의 중이거나 다른 통화 중입니다"가 표시됩니다.
   - 상대가 접속해 있지 않으면 "상대가 접속해 있지 않습니다"가 표시됩니다.
5. **회의와의 관계**: 통화 중에 회의실 스크린을 누르면 "통화를 종료하고 화상회의에 참여할까요?"를 묻습니다. 통화가 끝나면 마이크·카메라가 꺼진 상태로 근처 대화로 돌아옵니다.
6. 통화는 메인 창에서만 걸고 받을 수 있습니다(창 분리한 채팅 창에는 통화 버튼이 없습니다).

## 2.6.2 방 안 근처 대화와 머리 위 카메라

관리자가 근처 음성 대화를 켜 둔 방에서는(1.6절), 채팅창 없이 **마이크를 켜고 말하면 같은 방 안 가까운 사람에게 들립니다.**

- **켜는 법**: 하단 HUD의 마이크 버튼 또는 `M` 키. 버튼 문구로 지금 목소리가 어디로 가는지 알 수 있습니다.
  - "근처 대화 중": 같은 방 가까운 사람에게 들림
  - "회의 마이크": 화상회의 창으로 들림
  - "통화 마이크": 1:1 통화로 들림
  - "근처 대화 꺼짐": 관리자가 이 방의 근처 대화를 꺼 둠
  - "음소거 (M)": 마이크 꺼짐
- **들리는 거리**: **2.5m까지 선명**, 2.5~4m는 점점 작게, **4m 밖은 들리지 않습니다.** 다른 방이나 다른 층에서는 가까워도 절대 들리지 않습니다.
- **누가 말하는지 보기**:
  - 말하는 사람 발밑에 **초록 네온 링**이 퍼집니다. 흐린 남색 링은 "말하고 있지만 내게는 들리지 않는 사람"(회의 중이거나 멀리 있음)입니다.
  - 마이크를 켠 사람 머리 위에는 🎙️가 보이고, 말할 때 음파 막대가 움직입니다.
  - 내 마이크가 켜져 있으면 내 발밑에 **2.5m/4m 범위 원**이 표시됩니다.
- **근처 대화 패널**(왼쪽 아래): 4m 안에 있는 사람을 가까운 순으로 보여 줍니다. 🔊 버튼으로 특정 사람 소리만 **내 쪽에서** 끌 수 있고, 상대에게는 알려지지 않습니다.
- **머리 위 카메라**: HUD 카메라 버튼을 켜면 같은 방 사람 모두의 화면에 내 얼굴이 아바타 머리 위에 표시됩니다. 켜고 끄는 즉시 반영되며, 근처 대화 설정과 관계없이 동작합니다. 회의 창이나 1:1 통화를 시작하면 카메라가 그쪽으로 옮겨집니다.
- **소리가 안 날 때**(주로 아이폰): 마이크 버튼 옆의 🔊 버튼을 한 번 누르세요.
- 모든 음성·카메라는 사내 서버의 LiveKit 미디어 서버를 거치며, 사용자 PC끼리 직접 연결하지 않습니다.

## 2.6.3 팀·전사 일정 (1.0.8)

- 상단 **📅 일정** 버튼(휴대폰은 **더보기 → 팀·전사 일정**)이나 포털 첫 화면의 **이번 주 일정** 카드에서 달력을 엽니다.
- 일정 종류: 🎉 행사 · 🌴 휴가 · ⏰ 마감 · 🚗 외근·출장 · 📚 교육 · 📌 기타. 방 회의 예약(📹)과 타운홀(🎤)도 달력에 함께 보이지만, **예약·수정은 각자의 기존 화면**에서 합니다(일정 기능은 회의·타운홀 예약 로직을 바꾸지 않습니다).
- 권한: **전사 일정은 관리자**, **팀 일정은 그 팀 직원**이 등록합니다. 수정·삭제는 작성자나 관리자만 할 수 있고 감사 로그에 남습니다.
- **구글 캘린더에 추가**: 내용이 채워진 구글 캘린더 새 일정 화면이 열리고 [저장]만 누르면 됩니다. **파일로 받기(.ics)**는 아웃룩·아이폰용입니다. 둘 다 한 번 넣는 방식이라 나중에 바뀐 내용은 따라가지 않습니다.
- **벽 일정 보드**(스튜디오 소품 `schedule_board`): 이번 주 일정을 벽에 보여 줍니다. 팀이 배정된 방은 그 팀 + 전사, 로비 등은 전사 일정. 클릭이나 `E` 키로 그 방 팀에 맞춘 달력이 열립니다. 공유 스크린 바로 옆에는 걸지 않습니다(스크린의 E 키 안내가 우선).

## 2.6.4 방 회의 외부 참석 링크 (1.0.8)

- 협력업체 등 사내 계정이 없는 사람을 방 회의에 부르는 링크입니다. 회의 예약 목록에서 **외부 참석**(예약자·관리자만) → **외부 참석 링크 만들기** → **복사**.
- 받은 사람은 로그인 없이 이름·소속·동의 후 **그 회의실 회의에만** 들어옵니다(마이크·카메라·화면공유·회의 채팅). 3D 오피스·다른 방·직원 목록은 보이지 않고, 회의 채팅은 입장 이후 메시지만 보입니다. 이름 뒤에 `· 외부`가 붙습니다.
- **회의 시작 30분 전 ~ 종료 30분 후**에만 입장 가능. 예약 취소 시 즉시 막힘. 패널에서 외부 참석자 목록·**내보내기**, 링크 **재발급**(이전 링크 무효)·**끄기**. 재발급·끄기·내보내기는 들어와 있던 외부 참석자를 바로 내보냅니다. 감사 로그에 남습니다.
- 외부 참석자도 동시접속 인원에 포함됩니다. 외부 참석자는 고객 전용 터널 주소(`회사약칭.calamus.ai.kr`)로 **링크만 눌러** 들어옵니다(별도 VPN·계정 불필요). 고객이 직접 그 주소 앞에 Cloudflare Access 같은 추가 인증을 걸었거나 VPN 사용자만 접속하게 막아 둔 경우에만 외부 참석자(타운홀 게스트 포함)도 막히며, 이때는 외부 참석용 예외 설정이 필요합니다.
- 대규모 외부 세미나는 계속 타운홀(2.8)을 사용합니다.

## 2.6.6 2D 업무 모드 (1.0.8)

- 3D 없이 **동료(채팅·1:1 통화) / 회의실(사용 중 인원·공유·예약·들어가기) / 오늘 일정**만 쓰는 가벼운 화면. 대시보드 **💻 2D 업무 모드**, 3D 화면 **💻 2D로 전환**, 2D 화면 **3D로 전환**. 마지막 방식 기억, 휴대폰·태블릿은 처음 2D.
- 회의 창·1:1 통화·채팅 등은 3D·2D 공용 창이라 **보기를 바꿔도 회의·통화·화면 공유가 끊기지 않습니다.**
- 2D에서는 근처 대화를 쓰지 않습니다(서버도 거부). 내 캐릭터는 마지막 자리에 서 있고 동료 화면에 **💻 2D** 표시.

## 2.6.5 예약 회의 참여 — 대시보드·사내 링크 (1.0.8)

- 대시보드 회의 카드: 참석 대상 회의에 **▶ 참여하기**(시작 30분 전~진행 중, 그 방으로 이동 + 회의 창 자동 열림) 또는 **회의실로 이동**(그 전). 회의 예약 창 버튼과 **사내 링크**(`/?meeting=방&id=회의`, 로그인 후 이어짐)도 같은 방식입니다.
- 시작 전 그 방이 사용 중이면(`🔴 회의실 사용 중 n명`) **시작 시각에 자동 참여**(기본) / 지금 들어가기를 묻습니다. 시작 후에는 예약 회의 우선으로 바로 들어갑니다.
- 예약 참석자가 아닌 사람이 그 방 회의 창을 쓰고 있으면 30분 전·10분 전·시작 후 단계로 안내 띠가 나옵니다. 강제 퇴장은 하지 않습니다.

## 2.7 근무 상태 변경 및 퇴근 기록 (clock_out)

1. **근무 상태 실시간 변경**:
   - 우측 상단 내 프로필 카드에서 상태 버튼을 클릭하여 즉시 변경합니다:
     - 🟢 **업무중 (Office)**: 정상 집무 상태
     - 🟡 **자리비움 (Away)**: 식사, 휴식, 자리 비움
     - 🔵 **회의중 (Meeting)**: 화상/오프라인 회의 참석 중
     - 🟣 **외근/출장 (Trip)**: 병원 외진, 외부 미팅 출장
   - 상태 변경 시 동료들의 화면에 실시간으로 상태 배지가 동기화됩니다.
2. **퇴근 처리 (clock_out)**:
   - 일과 종료 시 프로필 메뉴의 **`[퇴근하기]`** 버튼을 클릭합니다.
   - 사내 근태 DB에 오늘의 퇴근 일시가 확정 기록되며, 브라우저 세션이 안전하게 로그아웃 처리됩니다.

## 2.8 타운홀 (전사 대규모 세미나)

타운홀은 3D 오피스와는 별도의 독립된 강당 공간(210석)으로, 계약 한도(기본 100명) 안에서 전사 세미나·발표 행사에 사용합니다. 계약에 따라 관리자가 건물 템플릿 스튜디오(또는 관리자 콘솔의 "라이선스" 탭)에서 사용 여부를 끄면 아래 진입 버튼 자체가 보이지 않습니다. 예약부터 종료·복구까지의 자세한 절차는 **[타운홀 세미나 운영 매뉴얼](0.%20타운홀_세미나_운영매뉴얼_2026-09-26.md)**을 참고하세요.

1. **입장하기**: 사내 포털 메인 화면의 **`[🏛️ 타운홀 로비 입장]`** 버튼을 누르면 예정된 일정이 없어도 바로 로비로 들어갈 수 있습니다.
2. **예약**: **직원이면 누구나** "세미나 예약·참석자·일정 관리"에서 세미나를 예약할 수 있습니다. 발표자는 **예약자 포함 최대 5명**입니다. 일정·명단 수정과 초대링크는 예약자와 발표자가, 삭제는 예약자가 합니다.
3. **시작·입장**: 예약자 또는 발표자 누구나 **`[행사 시작하고 입장]`**으로 행사를 시작합니다. 참석자는 본인 확인 체크 후 **`[본인확인 후 세미나 입장]`**으로 들어갑니다. 로비는 5초마다 상태를 확인해 시작되면 입장 버튼이 자동으로 나타납니다.
4. **외부 게스트 초대**: 세미나를 등록하면 외부 초대 링크가 표시됩니다. 이후 다시 확인하거나(🔗 아이콘) 유출됐을 때 기존 링크를 무효화하고 새로 발급(🔄 재발급)할 수 있습니다. 게스트는 링크로 들어와 이름·회사·이메일을 등록하면 바로 참석자로 입장합니다.
5. **마이크/카메라**: 입장 후 발표자이거나 "발언 승인"을 받은 참석자만 버튼이 나타납니다. 켜짐은 초록(마이크 켜짐·카메라 켜짐), 꺼짐은 빨강(음소거 됨·카메라 Off)으로 표시됩니다. 일반 참석자는 **`[✋ 손들기 / 질문 등록]`**으로 발언을 요청합니다.
6. **공유 소리 겹침 방지**: 발표자의 **`[공유 소리 내 스피커]`**는 기본 "끔"입니다. 공유 영상 소리를 발표자 스피커로 내보내지 않아, 발표자 마이크가 그 소리를 다시 잡아 참석자에게 겹쳐 들리는 것을 막습니다.
7. **나가기·종료**: 좌측 상단 **`[← 사무공간]`**은 사무실로 돌아가고, 패널 맨 아래 **`[미팅 나가기]`**는 로비에 남습니다. 예약자·발표자는 **`[행사 종료]`**를 쓸 수 있고, 잘못 종료했다면 **`[↺ 행사 다시 열기]`**로 같은 행사를 복구합니다.

## 3. 2026-09-24 변경사항과 운영자가 꼭 알아야 할 내용

### 3.1 인증요청파일과 라이선스의 관계

1. 고객 서버는 첫 실행 때 설치 인스턴스용 Ed25519 키를 만듭니다.
2. 관리자가 내보낸 `.calamus-request`에는 `instanceId`, 공개키, 요청 ID와 **하드웨어 식별자의 SHA-256 해시**가 들어갑니다. BIOS/메인보드 원본 번호나 비밀키, 고객이 편집한 건물 JSON은 들어가지 않습니다.
3. 공급자는 활성 계약, 계약에 고정한 건물 프로필, 앱/미디어 도메인과 터널 ID를 이 요청에 묶어 서명합니다.
4. 고객은 발급받은 `.calamus-license`를 관리자 센터에서 등록하고 서버를 재시작합니다.

> [!WARNING]
> 같은 PC에서 프로그램만 덮어쓰는 업데이트는 기존 설치 신분을 유지합니다. 디스크 장애·Windows 재설치 후에도 **같은 하드웨어**라면 전체 운영 백업을 복원해 기존 라이선스와 터널·LiveKit 설정을 이어서 사용할 수 있습니다. 새 PC나 메인보드 교체 후에는 복원해도 하드웨어 불일치로 차단되며, **인증요청파일을 다시 생성해 재발급**받아야 합니다.

### 3.2 건물 스튜디오 저장과 계약 반영

- 고객 서버의 스튜디오 저장은 해당 서버 SQLite와 로컬 범위에 저장됩니다. 고객 설치본이 공급자 D1을 무인으로 수정하지 않습니다.
- 공급자 마스터 프리셋은 Cloudflare Access로 보호된 공급자 포털에서 관리합니다. 공개 try 사이트는 데모 전용 저장 경로와 앱 권한을 사용합니다.
- 고객이 로컬에서 직접 수정한 건물을 라이선스에 넣으려면 JSON을 공급자에게 전달하거나 공급자 포털의 고객 전용 프리셋으로 저장·게시한 뒤, 계약 건물 프로필에 선택해야 합니다.
- 그 다음에 발급한 라이선스부터 해당 건물 구성이 서명되어 고객 서버에 적용됩니다. 인증요청파일을 다시 만든다고 로컬 건물 수정분이 자동 포함되는 것은 아닙니다.

### 3.3 권한 및 데이터 보호 보완

- 프리셋 생성·수정·삭제와 기본셋 지정은 개발자 또는 `building.manage` 권한이 있는 관리자만 수행합니다.
- 명시적 로그아웃은 서버 세션을 무효화하며, 종료 비콘은 요청자가 아니라 검증된 세션 사용자를 기준으로 근태를 기록합니다.
- 고객/공용 프리셋 캐시를 분리해 고객 전용 편집이 `COMMON` 샘플을 오염시키지 않도록 했습니다.
- 스튜디오에는 현재 편집 버전 표시, 저장 동선 정리, 회의용 긴 테이블·의자와 1인 안락의자 렌더링 개선이 반영되었습니다.

### 3.4 방별 화면공유와 외부망 점검

- 화면공유 상태는 `고객 + 건물 템플릿 + 방` 단위로 분리합니다. 한 방의 소리나 화면이 다른 방으로 넘어가면 정상 상태가 아닙니다.
- 고정 5건 제한은 사용하지 않습니다. 라이선스에 서명된 건물의 실제 화면공유 가능 방/스크린 수가 상한입니다. 한 방에는 발표자 한 명만 허용하고, 같은 사용자의 중복 송출은 차단합니다.
- Cloudflare Tunnel은 앱과 신호용 HTTPS/WSS 경로입니다. 영상·음성은 UDP 미디어 포트, ICE/TCP 또는 TURN 경로가 추가로 필요합니다.
- 관리자 센터의 **외부망 WebRTC 경로 진단**에서 DNS, 신호 URL, ICE/TCP, TURN 설정을 확인할 수 있습니다. 서버 자체 진단만으로 외부 UDP 통과를 확정할 수 없으므로 다른 인터넷망의 PC/휴대폰 두 대 이상으로 실제 송출·시청·음성을 시험해야 합니다.
