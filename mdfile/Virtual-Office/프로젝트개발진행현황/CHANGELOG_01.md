## 2026-10-12 — 2D 업무 모드(②~⑤단계) — 3D↔2D 전환 중 회의·통화·공유 유지

- **보기 방식** `officeView: '3d' | '2d'`(스토어, `vo_office_view`에 기억, 처음엔 휴대폰·태블릿 2D·PC 3D). 오피스 안의 보기라 `viewMode`(대시보드·타운홀과의 이동)는 그대로 → `releaseOfficeMedia`가 돌지 않아 회의·통화·공유 유지. App: 2D면 `OfficeCanvas`·HUD 대신 `WorkModeView`(3D WebGL 미로딩), 공용 창(`SharedOverlayLayer`)은 항상 유지.
- **음성**: `audioChannelManager`가 근처 대화를 3D 보기에서만 켠다(`nearbyView`). 2D로 바뀌면 근처 대화 마이크·머리 위 카메라를 끄고 연결 해제, 3D로 돌아오면(회의·통화가 없으면) 다시 연결. 2D에서 근처 대화 마이크를 켜려 하면 안내.
- **서버**: WS `office_view`(→ `peer_office_view`), 접속 정보에 `officeView`. 2D가 되면 근처 대화 LiveKit에서 내보내고, 2D 사용자의 근처 대화 토큰 요청은 거부. 동료 3D 화면 캐릭터 상태에 `· 💻 2D`.
- **2D 화면** `WorkModeView`: 동료(검색·팀·접속 중만, 상태·"회의 중(방)"·💻, 💬 채팅·📞 통화 — 회의 중인 동료는 통화 비활성+이유, 통화 오류 안내), 회의실(화상회의 켜진 방, 회의 중 인원·공유 중·진행/다음 예약, **들어가기** = `meetingJoin.enterRoomMeeting`: 참석 대상 예약이 진행 중이면 예약 참여 흐름), 오늘(내 회의 ▶ 참여하기 + 이번 주 일정). 위쪽: 근무 상태, 일정, 회의 예약, 설정, 대시보드, 3D로 전환. 휴대폰은 동료/회의실/오늘 탭.
- **진입**: 대시보드 **💻 2D 업무 모드**(3D 입장과 같은 준비 `enterOfficeAs`), HUD **💻 2D로 전환**, 휴대폰 더보기 **2D 업무 화면**.
- **확인**(확인용 서버 3011 + 시험 전용 LiveKit 7895, 실제 브라우저 2개): 30개 통과 — 대시보드 2D 진입·WebGL 미로딩·근처 대화 꺼짐·💻 표시, 2D 회의실 들어가기·연결·화면 공유, 공유 중 3D↔2D 왕복(회의 창·연결·동료 수신 유지, 토큰 재발급 0회), 회의 중 동료 통화 비활성, 2D에서 통화 걸기·연결, 통화 중 3D↔2D(통화 유지·재연결 없음·근처 대화 안 켜짐), 3D 복귀 시 근처 대화 재연결·💻 사라짐, 새로고침 기억, 휴대폰 탭·가로 넘침 없음. 회귀: 대시보드 참여, 창 분리(PiP), 공용 창, 외부 참석 API·화면·주최자, 일정 화면·API, 보안 모두 통과. `npm run build` 0 에러.

## 2026-10-12 — 공용 창 영역 분리(2D 업무 모드 1단계) + 회의 창 분리 공유 끊김 수정

- **공용 창 영역** `SharedOverlayLayer`: 회의 창·1:1 통화 카드·채팅·설정·근태·회의 예약·화면공유 선택/미리보기·공지·게시판·퇴장 창과 서버 데이터 동기화(`syncFromDatabase`)를 HUD(3D 전용)에서 빼서 App 오피스 화면에 한 번만 그린다. 3D 보기와 앞으로 만들 2D 업무 보기를 오가도 이 창들이 닫히지 않아 회의·통화·공유 연결이 유지된다. HUD에는 3D 전용(근처 대화 패널·층 이동 효과)만 남김. 화면 모양 변화 없음.
- **창 분리 공유 끊김 원인**: 분리된 새 창도 앱 시작 때 '내 자리 복원'(층 이동)을 실행했고, 층 이동이 방금 연 회의 창을 닫아 분리된 창이 회의에서 빠진 빈 화면이 됐다(송출은 원래 창에서 계속돼 동료에게는 보였지만, 본인에게는 공유가 꺼진 것처럼 보여 다시 공유하게 됨). 분리된 창은 자리 복원을 건너뛰고 현재 방을 회의실로 맞춘다.
- **Chrome·Edge 문서 PiP** `src/services/meetingPip.ts`: 회의 창을 고정 상자(`MeetingWindowHost`)에 그리고, 창 분리 때 그 상자를 통째로 항상-위 PiP 창으로 옮긴다(React 재마운트 없음 → LiveKit 토큰 재발급·재연결 없음). **원래 창으로** 버튼·PiP 창 닫기 시 원래 화면으로 복귀(회의 유지), 회의를 닫으면 PiP도 닫힘. LiveKit adaptiveStream은 문서 PiP를 지원.
- **미지원 브라우저(예전 팝업)**: 원래 창이 공유 중지 함수를 열어 두고, 팝업에서 내가 발표자면 **화면 공유 중지** 버튼이 활성화된다.
- **확인**(확인용 서버 3011 + 시험 전용 LiveKit 7895, 실제 Chrome): 창 분리 20개 통과 — PiP 이동, 영상 재생, 분리·복귀 중 공유·동료 수신 유지, 토큰 재발급 0회, PiP 닫기 복귀, 팝업에서 내 공유 보임·중지. 공용 창: 1:1 통화(호출·수락·연결·종료)·설정·근태·1:1 채팅·퇴장 창 9개 통과. 회귀: 대시보드 참여 21, 외부 참석 API·화면·주최자 화면, 일정 화면·API 19, 보안 18 통과. `npm run build` 0 에러.
- 문서: 화상회의 가이드 3.1, 통합 매뉴얼 3.8. 1.0.8에 포함.

## 2026-10-09 — 미사용 자동 로그아웃(자리 비움 기록), 근태 저장 오류로 서버가 멈추던 문제

- **미사용 자동 로그아웃**: 관리자 보안 정책에 `idleTimeoutMinutes`(0=사용 안 함·30·60·120·240·480, 다른 값은 무시)를 추가했다. 기본은 꺼짐.
  - "사용 중" 기준: 창이 열려 있는 것만으로는 사용 중이 아니다. 키보드·마우스·터치 입력이 있거나 회의·1:1 통화·화면공유·타운홀 참석 중이면 브라우저가 1분에 한 번 사용 신호를 보낸다(WebSocket `activity`, 소켓이 없으면 `POST /api/session/activity`). `src/components/IdleLogoutGuard.tsx`.
  - 판단은 서버가 한다: 세션마다 마지막 사용 시각(`lastActivityAt`)을 두고 1분마다 확인해, 시간이 지난 세션을 지우고 소켓을 4002(`idle_timeout`)로 닫는다. 최대 24시간 유지는 그대로.
  - 근태: 사용자 결정에 따라 **퇴근이 아니라 자리 비움**. 상태를 `away`로 바꾸고, 출근 기록이 있으면 `away` 근태("미사용 N분으로 자동 로그아웃(자리 비움)")를 남긴다. 소켓 종료 처리가 일반 종료처럼 퇴근 상태로 덮어쓰지 않게 했다. 감사 로그 `auth.idle_logout`.
  - 화면: 만료 1분 전에 "곧 자동 로그아웃됩니다 [계속 사용]" 경고(입력이 있어도 연장). 로그아웃되면 로그인 화면에 안내가 뜨고, 같은 날 다시 로그인하면 출근 기록 메모가 "미사용 자동 로그아웃(자리 비움) 후 재접속"이 된다.
  - 시험용 환경변수 `VO_IDLE_MINUTE_MS`(1분을 몇 ms로 볼지, 운영에서는 설정하지 않음).
- **근태 저장 오류로 서버 전체가 멈추던 문제(기존 결함)**: `POST /api/attendance`에 이미 있는 id를 보내면 DB 고유키 오류가 처리되지 않아 서버 프로세스가 종료됐다. 로그인한 사용자 누구나 일으킬 수 있었다. 409로 돌려주도록 고쳤다.
- 확인: 확인용 서버를 1분=1초로 띄워 30분 정책을 시험했다. 미사용 세션 30초 뒤 4002 종료·토큰 401, 사용 신호를 보낸 세션은 유지, 근태 `away` 기록·퇴근 기록 없음, 상태 `away`, 허용 외 값 무시(8개 통과). 화면에서 자동 로그아웃 안내를 확인했다. 기존 보안 시나리오 18개도 다시 통과. 1분 전 경고 창은 실제 시간(30분)이 필요해 화면으로는 확인하지 못했다.

  - 보드 위 글자(drei `Html`)의 바깥 틀은 기본값이 `pointer-events: auto`라서, `style={{ pointerEvents: 'none' }}`(안쪽 글자에만 적용)만으로는 뒤의 3D 보드까지 클릭이 가지 않았다. `pointerEvents="none"` 속성을 같이 줬다(아카이브 게시판 3곳, 화이트보드·소품 라벨 4곳, 층별 게시판 `FloorGalleryBoard3D` 3곳).

## 2026-10-02 — 공급자 포털 릴리스 업로드 수정, Windows·Linux 배포 파일 분리

- **릴리스 업로드 오류 원인 3가지 수정**
  1. 설치본(154MB)이 Pages Functions 요청 본문 한도(약 100MB)를 넘었다 → R2 멀티파트 업로드로 바꿔 50MB 조각으로 보낸다(`functions/api/manage/releases/multipart/init·part·complete·abort.js`). 옛 단일 업로드 `upload.js`는 삭제.
  2. 릴리스 노트를 HTTP 헤더(`X-Release-Notes`)로 보내 한글이 들어가면 브라우저가 요청 자체를 거부했다 → JSON 본문으로 보낸다.
  3. 한 버전에 파일을 하나만 둘 수 있었다 → `release_artifacts` 테이블(마이그레이션 `0010`)을 추가해 한 버전에 Windows 설치본(.exe/.zip)과 Linux 도커 묶음(.tar.gz)을 함께 둔다. 기존 릴리스 행은 Windows 파일로 자동 이관된다. `releases`는 다른 테이블이 참조하고 있어 재구성하지 않고 그대로 둔다(0009와 같은 이유).
- **SHA-256 조각 계산**: 브라우저가 파일 전체를 메모리에 올리지 않고 조각을 보내면서 이어서 계산한다(`src/marketing/sha256Stream.ts`, Node `crypto`와 결과 일치 확인, 약 78MB/s).
- **게시 시 파일별 서명**: 게시(`PATCH /api/manage/releases/:id`)할 때 파일마다 `platform`·`kind`를 포함한 manifest에 서명한다. 서명 전 파일(게시 뒤 추가한 파일)은 고객에게 보이지 않으며, "새 파일 서명 후 재게시"로 서명한다.
- **고객 다운로드 포털**: 버전별로 Windows·Linux 파일을 각각 보여 주고 내려받는다(`/api/download/artifacts/:id`). Linux 파일에는 "서버에서 바로 받기" 버튼이 있어 1시간·3회 쓸 수 있는 링크와 `curl → sha256sum 확인 → 압축 해제 → install.sh` 명령을 만들어 준다(`/api/download/links`, 공개 경로 `/api/release-links/:token`, DB에는 토큰 해시만 저장). 옛 경로 `/api/download/releases/:id`는 삭제.
- 다운로드 기록(`download_audit_logs`)에 `artifact_id` 열을 추가했다.

## 2026-10-02 — 고객 다운로드 로그인 정비, Windows 1.0.4 패키지, 시험 서버 정리

- **고객 다운로드 로그인**: 고객용 Cloudflare Access 앱이 없어서, 어떤 고객도 다운로드 포털에 로그인할 수 없었다.

  - 서버 설치용 `/api/release-links`는 로그인 없이 열려 있다.
- **다운로드 화면 개선**:
  - 같은 Cloudflare 팀의 공급자 로그인이 공유되어, 공급자 이메일로 자동 로그인되면서 "계약을 찾지 못했습니다"로 보이던 문제를 고쳤다.
  - 화면 위에 "로그인됨 · 이메일 · 다른 계정으로 로그인"을 표시한다.
  - 오류를 "등록되지 않은 이메일"(`customer_portal_user_not_registered`)과 "계약 없음"으로 나눴다(`functions/_lib/customer-access.js` `requireDownloadCustomer`).
- **Windows 1.0.4 패키지**: `VirtualOffice_Server_Setup_v1.0.4_production.exe`(약 156MB)와 zip을 만들었다. 포털 1.0.4 릴리스에 업로드·서명 후 재게시를 마쳤다(SHA-256 `6ef75fb7…df15ff8`, 로컬 파일과 일치). 이제 1.0.4는 Windows·Linux 두 파일 모두 게시·서명 상태다. 안전성 검증(380개 파일)을 통과했고, 한글 깨짐 수정이 들어 있다.
  - 작업 폴더에 커밋하지 않은 `RemoteScreenViewerModal.tsx` 변경(화면공유 로딩 표시)이 있었다. 리눅스 묶음(커밋 기준)과 맞추려고 잠시 치운 뒤 빌드했고, 빌드 후 그대로 되돌렸다.

- **우분투 시험 서버**: 옛 설치 폴더를 정리하고, 모든 컨테이너를 `/opt/worknexus` 관리로 옮겼다. ufw는 다른 서비스 공존과 Docker 포트 우회 때문에 켜지 않았다. 사외 영상·음성의 제약을 기록했다(`0. Linux_우분투서버_구축기록` 7장).

## 2026-10-02 — 서버 JSON 요청 한글 깨짐 수정(라이선스 등록 signature_invalid)

- **증상**: 우분투 도커 서버에서 관리자 화면으로 라이선스를 등록하면 `signature_invalid`로 거부됐다. 같은 파일을 노트북과 컨테이너 안에서 직접 검증하면 통과했고, 공개키도 세 곳(저장소·서버 소스·컨테이너) 모두 같았다.
- **원인**: `server/index.js`의 `parseJsonBody()`가 받은 조각을 `body += chunk`로 조각마다 문자열로 바꿨다. 한글(UTF-8 3바이트)이 조각 경계에서 잘리면 `�`로 깨져 라이선스 내용이 바뀌고 서명이 맞지 않게 된다. 같은 PC(localhost)에서는 조각이 커서 드물지만, 랜으로 보내면 조각이 작아져 큰 요청(라이선스 약 120KB, 한글 4천여 바이트)에서 재현된다. 실제 HTTP 요청을 16KB 조각으로 보내 수정 전 실패·수정 후 통과를 확인했다.
- **수정**: 조각을 Buffer로 모았다가 끝에서 한 번에 UTF-8로 바꾼다. 서버의 모든 JSON API가 이 함수를 쓰므로 건물 배치·화이트보드 같은 큰 한글 요청도 함께 고쳐진다. 라이선스 서명·검증 코드는 바꾸지 않았다.
- **영향**: 이미 배포된 Windows 1.0.3에도 같은 버그가 있다(다른 PC에서 관리자 화면으로 큰 요청을 보낼 때). 다음 패키지에 포함해야 한다.

## 2026-10-02 — 고객사 고정 주소 약칭(subdomain_slug) 입력 화면

- **문제**: 신규 거래처(ubuntu-Linux)에 라이선스를 발급하면 `subdomain_slug_required`로 멈췄다. 발급 버튼은 서명 전에 거래처 고정 주소(`약칭.calamus.ai.kr`) 터널을 먼저 만드는데, 약칭 입력 화면이 없어 그동안 DB에 직접 넣어 왔고 이번 거래처는 비어 있었다.
- **고객사 등록 양식**에 "고정 주소 약칭 (선택)" 입력란을 추가했다. **고객사 목록**에는 "고정 주소" 열을 추가했다. 약칭이 없으면 "미입력 · 입력", 있으면 "약칭 · 변경" 버튼이 보이고, 고정 주소가 이미 만들어졌으면 주소를 초록색으로 보여 주며 변경할 수 없다.
- 새 API `PUT /api/manage/customers/:id/slug`(`functions/api/manage/customers/[id]/slug.js`): 활성 터널이 있으면 `subdomain_slug_locked`(409)로 거부한다. 이미 발급된 라이선스의 주소와 어긋나지 않게 하기 위해서다.
- 검사 규칙(`functions/_lib/customer-slug.js`): 영문 소문자·숫자·하이픈 2~30자, 하이픈 시작·끝·연속 금지, `-media`로 끝나는 이름(미디어 주소와 겹침)과 `www`·`api`·`try` 등 예약어 금지, 다른 거래처와 중복 금지(DB 고유 인덱스).
- 라이선스 발급 화면은 약칭이 없을 때 오류 코드 대신 "고객 메뉴에서 약칭을 입력하세요" 안내를 보여 준다.

## 2026-09-26 — 방 안 근처 음성 대화를 LiveKit으로 전환 (1단계) + 관리자 켜기/끄기

**배경**: 기존 근접 음성은 사무실 전체 접속자와 P2P로 연결하고 받는 쪽에서 음량만 0으로 줄였다. 외부 접속자끼리는 TURN이 없어 연결이 잘 안 되고, 다른 방 대화 데이터가 비참가자 PC까지 전달됐으며, 마이크를 껐다 켜면 전송이 끊겼다. 누가 말하는지 표시도 내 아바타에만 있었다.

- **근처 대화 LiveKit 방**(`proximityVoiceManager.ts` 신규): 방마다 별도 LiveKit 방(`vo-near-<해시>`)에 접속한다. 같은 방 안에서 **3m 이내 선명, 3~6m 점점 작게, 6m 밖 무음**. 8m 안에 들어온 사람부터 수신하고 10m 밖이면 수신을 끊는다(경계 반복 방지). iOS가 `<audio>.volume`을 무시하므로 LiveKit `webAudioMix` + `setVolume`으로 음량을 조절한다. 방을 빠르게 옮겨도 0.3초 뒤 마지막 방에만 접속하고, 세대 번호로 오래된 연결 결과를 버린다.
- **음성 채널 관리자**(`audioChannelManager.ts` 신규): 마이크가 회의로 갈지 근처 대화로 갈지 결정하는 유일한 곳. HUD 버튼·M 단축키·회의 창 버튼 모두 여기로 모인다. 회의 창을 열면 근처 대화 연결을 끊고 켜 둔 마이크를 회의로 옮긴다. 회의 창을 닫으면 마이크를 끄고(주변에 목소리가 새지 않게) 근처 대화로 돌아온다. 회의를 팝아웃 창으로 분리하면 팝아웃이 닫힐 때까지 메인 창도 근처 대화에 들어가지 않는다. 팝아웃 보조 창은 근처 대화에 참여하지 않는다.

  - `POST /api/proximity-voice/livekit-token`: 서버가 WebSocket으로 알고 있는 사용자의 현재 방과 요청한 방이 같을 때만 발급한다(옆방 엿듣기 방지). 권한은 마이크 발행만 준다.
  - 사용자가 다른 방·층으로 이동하거나 접속이 끊기면 서버가 `RemoveParticipant`로 이전 방에서 직접 퇴장시킨다.
  - 로컬 SQLite 테이블 `proximity_voice_settings`를 추가했다(`building_presets` 스키마 변경 없음).
- **관리자 UI**(`AdminConsoleModal.tsx`): "방별 시설 관리"에 근처 음성 대화 전체 ON/OFF 스위치와 방별 "🗣️ 근처 대화" 버튼을 추가했다.

## 2026-09-25 — 회의실 마이크·카메라와 1:1 화면공유를 LiveKit으로 전환 (P2P 제거)

**배경**: 회의 크게보기 창에서 화면공유만 LiveKit이고 참가자 마이크·카메라는 P2P(`voiceManager`)였다. 마이크/카메라를 껐다 켜면 새 트랙이 전송되지 않고(sender에 정지된 트랙 잔류, `replaceTrack` 후 `ontrack` 미발생), 음량이 회의 참여가 아닌 아바타 위치 기준이라 소리가 끊겼다 이어지기를 반복했다. 또 P2P가 회의 참가자가 아니라 사무실 전체 접속자와 연결되어 회의 미디어가 비참가자 PC까지 전달되는 보안 문제가 있었다.

- **회의실 미디어 통합**(`sharedScreenMediaManager.ts`): 회의실 LiveKit 방 하나가 화면공유 영상·공유 음성·참가자 마이크·카메라를 모두 싣는다. 토큰 역할을 `attendee`(3D 스크린 시청, 화면만 구독) / `meeting`(회의 창 참가자, 마이크·카메라 발행) / `presenter`(화면공유 발행)로 분리(`server/index.js`, `publishSources`·참가자 metadata `mediaRole` 추가).
- **재접속·역할 변경 시 마이크/카메라 유실 방지**: 발행 희망 상태(`wantMicrophone`, `cameraTrack`)를 저장해 두고 연결 직후 `applyLocalMedia()`로 다시 발행한다. 회의 중 화면공유 시작/종료(`meeting↔presenter` 재접속)에도 음성·영상이 유지된다. 연결 종료 시 카메라 트랙(mediaStreamManager 소유)은 정지하지 않는다.
- **참가자 목록 정리**: LiveKit metadata `mediaRole`이 `meeting`/`presenter`인 참가자만 회의 타일로 표시하고, 나 자신(팝아웃 등 다른 창)은 제외한다.
- **구독 기준 변경**: 참가자 마이크·카메라는 역할이 아니라 "이 방의 회의 창이 열려 있는가"로 구독한다(회의 창을 닫은 발표자·3D 스크린 시청자는 회의 음성을 받지 않음).
- **마이크/카메라 토글 단일화**(`useOfficeStore.ts`): 회의 창이 열려 있으면 HUD 버튼·M 단축키·회의 창 버튼 모두 LiveKit으로 전송한다. 창을 열 때 켜져 있던 근접 음성 마이크/카메라는 LiveKit으로 옮기고, 창을 닫거나 방이 바뀌면 회의 미디어를 모두 끈다.
- **LiveKit 연결 불가 시 안내**: 회의 창 하단에 연결 상태 안내를 표시하고, 연결할 수 없으면 마이크/카메라 켜기를 비활성화한다("켜진 척" 방지). P2P 대체 경로는 두지 않는다(외부 접속자 대상·보안 검토 부담).
- **소리 재생 버튼**: 화면공유 음성과 참가자 마이크 재생 잠금을 분리 계산해 한쪽이 다른 쪽 버튼을 숨기지 않게 했다. iOS WebKit은 참가자 마이크가 있으면 첫 1회 명시적으로 재생 버튼을 누르게 한다.
- **1:1 화면공유**(`directMediaManager.ts` 신규, `ChatModal.tsx`): P2P 대신 두 사용자 전용 LiveKit 방(`vo-direct-<해시>`, 서버가 인증 사용자 쌍+건물 템플릿으로 방 이름 결정)으로 전송한다. WebSocket은 공유 시작/종료 알림만 담당한다. 같은 트랙이면 스트림을 재사용해 깜빡임을 없애고, 공유 음성 재생 잠금 시 "공유 소리 재생" 버튼을 표시한다.
- **팝아웃 창 P2P 차단**(`networkManager.ts`): 서버가 WebRTC 시그널을 메인·팝아웃 창 모두에 보내 같은 offer에 answer가 두 번 가던 문제 — 팝아웃 보조 창은 근접 음성 P2P에 참여하지 않는다.
- **녹화**: 회의 녹화의 내 음성/참석자 음성을 LiveKit 트랙에서 가져온다.
- **당시 알려진 한계**: LiveKit 토큰은 구독 가능한 트랙 종류를 제한할 수 없어, 3D 스크린 시청자가 회의 음성을 받지 않는 것은 클라이언트 구독 설정으로 보장된다. 서버 강제 격리가 필요하면 "화면 시청 방"과 "회의 방"을 분리해야 한다. 이 시점에는 오픈 공간 근접 음성을 P2P로 유지했으나, 다음 날인 2026-09-26 LiveKit 전환을 완료했다(이 문서 상단의 최신 항목 참고).
