# OnAnbu 보안 현행 명세

> 최종 현행화: 2026-10-01

## 강제 원칙

1. 추천에 쓰는 병원은 HIRA `ykiho`가 존재해야 한다. 투석·재활·ICU 같은 인프라를 “확인됨”으로 표시할 때는 HIRA 또는 승인 기관회원의 출처 팩트가 있어야 한다.
2. 환자 이름·연락처·주민번호·상세 병력 원문은 외부 LLM 프롬프트로 보내지 않는다.
3. `service_role`과 공급자 비밀키는 브라우저 번들·Git에 포함하지 않는다.
4. 화면 표시가 아니라 Auth 메타데이터, RLS, 서버 RPC에서 권한을 판정한다.
5. 가입·전원·비용 저장은 명시 동의와 최소 정보 원칙을 따른다.

## 구현 상태

- `ai-care-search`에 PII 마스킹, 요청 길이/Origin/요청량 방어가 있다. AI가 발견한 병원은 HIRA 마스터의 `ykiho`로 연결된 경우에만 화면에 남긴다.
- **자체 문지기 알고리즘(`intentClassifier.ts`)**: 클라이언트/Edge에서 정규식 기반 PII 마스킹을 수행하여 전화번호, 주민번호, 성명을 차단하고 의도 지문 캐시를 통해 안전하고 비용 없는 즉각 응답을 보장한다.
- **유령 병원 차단**: 대표전화(유선번호)가 검증되지 않은 병원은 최종 추천 집합에서 배제한다.
- 현행 발견형 검색은 병원명 정규화 유사 매칭을 우선한다. HIRA에 존재하지 않는 병원은 항상 제외한다.
- **상담 취소 RPC 보안 (`cancel_my_admission_consult_target`)**: `auth.uid()`와 상위 `transfer_consult_requests.user_id`를 엄격히 대조하여 본인이 요청한 건이 아니면 갱신을 차단하고, `CANCELED` 상태로 안전하게 전이한다.
- 네이버 client secret은 `naver-auth` Edge Function Secret에만 격리하며 토큰 교환은 URL 로그에 시크릿·인가 코드가 남지 않도록 POST 본문으로 수행한다.
- 네이버 OAuth 요청은 `crypto.randomUUID()` state를 콜백에서 검증하고, Edge Function은 원시 네이버 오류 응답이나 토큰을 브라우저에 반환하지 않는다.
- 개인·기관 가입 동의는 `auth_consent_records`에 버전·출처·시각을 남긴다.
- `auth_consent_records`는 직접 조회/쓰기 권한을 주지 않고 인증 RPC만 실행 가능하다.
- Trust 배치는 관리자 JWT 또는 배치 시크릿을 검증하며, 공식 홈페이지 판정을 재검증한다.
- 전원 상담 연락처·환자 상태 요약은 명시 동의 후 저장하며 요청자와 선택 기관의 승인 회원·최고관리자만 제한 RPC로 조회한다.
- 후기 인증은 관리자 근거 기록을 필수화했으며, 증빙 수집·진위확인 체계가 없는 상태에서 영수증 이미지만으로 승인하지 않는다.
- **크롤러 배포물 비밀키 금지 (2026-10-01)**: 누구나 내려받는 크롤러 EXE에는 공개 접속 정보(사이트 주소·공개 키)만 내장하고, 빌드 스크립트가 서비스 키 혼입 시 빌드를 중단한다. 다른 PC 야간 배치는 최고관리자 로그인(app_metadata.user_type=ADMIN) 권한으로만 저장하며, 로그인 유지 정보는 Windows DPAPI로 그 PC·계정 전용 암호화(`--logout`으로 삭제).
- **크롤링 주장 격리**: 홈페이지 수집 태그는 검토 대기열(`hospital_crawl_claims`, RLS로 직접 접근 차단)에만 쌓이고, 관리자 승인 RPC를 거친 태그만 `verified_crawl_tags`로 검색 근거가 된다. 크롤링은 HIRA 마스터·기관 확인 플래그·기관 수동 태그를 수정하지 않는다.
- **입원상담 허용목록**: 접수 RPC가 테마별 허용 처치·연령·상태·상담 목적(`transfer_theme_catalog`)으로 자유 입력을 막는다.
- **SECURITY DEFINER 최소권한**: `save_hospital_provider_profile`의 모든 현행 오버로드는 `PUBLIC`, `anon` 실행권한을 회수하고 승인 기관회원·서비스 역할만 내부 소유권 검사 후 실행한다(`202610010005`).
- **거절 회신 무결성**: 수용 어려움(`UNAVAILABLE`) 답변에는 비용 견적을 첨부할 수 없으며 프런트와 DB 트리거가 함께 차단한다(`202610010006`).
- **자동 발굴 홈페이지 격리**: 크롤러가 찾은 URL은 `hospital_website_candidates` 검토 대기열에만 저장되고, 최고관리자가 기관명·주소·전화번호를 대조해 확정하기 전 HIRA URL·공개 프로필에 반영하지 않는다(`202610010007`).

## AI 데이터 접근 통제

| 데이터 | 접근 정책 |
| --- | --- |
| 공개 질문·요약·통합 추천 | `mask_public_ai_query` 적용 후 전체 공개 가능. 작성자 식별정보는 반환하지 않음 |
| 개인 AI 상세 리포트 | 로그인 사용자의 자기 질문만 허용. 최초 한 번 계정 연결 동의 기록 |
| 기관회원 AI 상세 리포트 | `hospital_memberships.status='APPROVED'`를 서버에서 확인한 회원에게 공개 질문 근거 허용 |
| 관리자 AI 상세 리포트 | 전체 공개 질문 근거 허용 |
| 공급자별 AI 전체 답변 원문·토큰 | `get_admin_ai_response_originals`를 통해 시스템 관리자만 허용 |
| AI 엔진·프롬프트 설정 | 관리자 RPC만 조회·변경 허용 |
| AI 실행 설정 | `get_ai_engine_settings`를 `service_role`에만 허용 |

- 상세 리포트 RPC에 `authenticated` 실행권한이 있더라도 함수 내부에서 소유자·승인 기관회원·관리자 여부를 다시 판정한다.
- 기관회원과 일반 사용자가 받는 응답에는 `model_answer_text` 전체 원문을 포함하지 않는다.
- 관리자 엔진 설정에는 활성 상태·모델·프롬프트만 저장한다. OpenAI·Gemini·Perplexity API 키는 설정 UI와 설정 RPC 응답에 포함하지 않는다.
- 관리자 저장 RPC는 공급자 목록, boolean 활성값, 모델명 허용문자, 프롬프트 길이와 최소 한 엔진 활성화를 검증한다.

## AI 질문·원문 저장 보안

1. 사용자가 입력한 질문은 외부 AI 전달 전에 `piiMasker`를 거친다.
2. 검색 원장에는 마스킹된 질문, 내부 사용자 UUID/세션, 구조화 Intent를 저장한다.
3. 공급자 원문과 출처는 감사·품질 분석 자산으로 저장하지만 관리자 전용 RPC 외에는 노출하지 않는다.
4. 공개 질문 화면과 지역 통계는 다시 `mask_public_ai_query`를 적용한다.
5. HIRA의 `is_hira_verified=true`는 병원 식별이 확인됐다는 의미다. AI 추천 문장 전체를 국가기관이 검증했다는 의미로 사용하지 않는다.

## 지역 통계 권한

- 승인되지 않은 기관회원은 `get_regional_ai_dashboard`를 실행할 수 없다.
- 승인 기관회원은 자기 `ykiho` 기준 기관 언급 통계를 조회한다. 화면에서 다른 지역을 선택해도 다른 병원을 자기 기관으로 바꿀 수 없다.
- 관리자는 전체 지역 범위 또는 명시한 `ykiho`의 기관 범위를 조회할 수 있다.
- 실제 사용자 검색과 벤치마크 데이터는 `source_type`으로 분리해 시험 질문이 영업 통계로 오인되지 않게 한다.

## 확인해야 할 운영 항목

- `.env`는 절대 커밋하지 않고 `.env.example`에는 더미만 둔다.
- `npm run security:secrets`, `npm run security:rls`를 배포 전 실행한다.
- 크롤러 EXE를 다시 빌드할 때 내장 공개 접속 정보(`scripts/build/crawler_server/crawler_public_config.json`)에 서비스 키가 없는지 빌드 로그로 확인한다(혼입 시 빌드 자동 중단).
- 가입 약관·개인정보 처리방침 전문과 동의 철회 경로는 P0로 공개 전에 연결한다.
- 외부 공급자 키 교체·비용 한도·실패 알림을 운영 도구에서 관리한다.
- 관리자 프롬프트 변경 이력과 변경자 감사 로그는 후속 보완한다. 현재는 `system_config.updated_at`으로 최종 변경 시각을 기록한다.
- 병원명 부분 일치에서 동명이원 오연결 가능성을 모니터링하고, 기관 데이터가 충분해지면 주소·전화·지역 신뢰도 검증을 단계적으로 복원한다.

## 금지

- 테스트 OTP 우회, 클라이언트 권한 플래그 신뢰, 공개 SECURITY DEFINER 실행권한
- HIRA 미등록 시설을 AI 최종 답변에 추가, Trust 점수를 의료 품질로 표현
- 동의 없는 환자 PII 저장·AI 전송·기관 상담 전달
- 기관회원에게 공급자 전체 원문이나 다른 사용자의 식별정보를 노출, 클라이언트에서 관리자 여부만 판정
