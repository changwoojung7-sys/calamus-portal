## UX 원칙

- 홈은 서비스 이해, 병원찾기는 탐색에 집중한다.
- 상단 바로가기 배너는 모바일에서 홈 화면 추가, PC에서 데스크톱 PWA 설치를 우선 실행한다.
- **홈-상급병원 전원조건 일원화 (`HomeTransferSetup`)**: 7대 전원 테마 칩(시니어·암·정형재활·소아발달·정신건강·산부인과), 희망 입원시기, 병실, 간병 형태를 선택하고 상급병원 전원 설계로 자동 계승.
- **7대 테마별 동적 상담 마법사 (`AdmissionRequestWizard`)**:
  - 암 환자에게 노인 요양 기저귀 질문을 일절 묻지 않고, 통증 조절/피로도 및 항암 부작용 케어 질문으로 100% 맞춤 전환.
  - 정형재활(수술 2주차 보행훈련 등), 소아재활(발달지연/감각통합), 정신건강(정서안정도/병식) 등 테마별 상태 평가 질문 및 특이사항 태그 동적 공급.
- **기관 에디터 2단계 주력 전문분야(Theme Selector) UI (`HospitalAdminEditor`)**:
  - 일반병원(`21`)일 때 요양 전용 키워드(1:4간병, 치매전담 등) 자동 숨김 처리.
  - 상단 주력 전문분야 칩을 통해 정형외과, 암센터, 뇌신경재활 등 자기 병원 주력 인프라와 추천 태그만 상단에 모아서 1초 만에 원클릭 등록.
- **외래 전용 의원 100% 차단 (`App.tsx`)**: `hasBedsOnly` 체크 시 30병상 미만 외래 전용 의원/한의원을 배제하여 전원 환자의 신뢰도 보장.
- **기관회원 답변 간소화 (`HospitalAdmissionResponseForm`)**:
  - 12개 비용 인풋 대신 원클릭 표준 견적 패키지 프리셋 3종, 30초 퀵 서류 칩, 상용구 템플릿, 보호자 의뢰 요약 스플릿 뷰 제공.
- 40~60대 보호자와 시니어를 위해 본문 16px 내외, 높은 대비, 44px 이상 터치 영역을 지향한다.

## AI 정밀검색 화면

### 병원찾기 결과

- 정밀검색 실행 중에는 전체 화면 로딩 오버레이를 표시해 중복 클릭과 필터 변경을 막는다.
- 성공 직후 문장형 조건 검색 결과에 확인된 기관과 기관별 HIRA·승인 근거를 표시한다. 의료기관 간 순위·우열 점수·추천 서열은 표시하지 않는다.
- 새로고침하거나 기본 필터검색을 수행하면 마지막 AI 결과를 한 줄로 접고 사용자가 클릭해 다시 펼칠 수 있게 한다.
- 마지막 성공 검색은 브라우저 저장소에 질문, 검색 시각, 확인 기관, `searchLogId`를 보관해 새로고침 후에도 병원찾기에서 다시 볼 수 있다.
- AI 결과의 병원명을 클릭하면 기존 상세카드를 연다. 기본검색 결과 상태와 AI 정밀검색 결과 상태는 분리한다.

### 기관별 확인 근거

- 질문에서 확인된 기관은 가나다순으로 각각 표시한다. 기관끼리 한 표에 나란히 놓거나 통합 순위·모델별 순위·합의율을 표시하지 않는다.
- HIRA 병원 등록 확인, 기관회원 제공 소개·특화진료·장비·식사 등 서버가 결합한 기관별 근거를 표시한다.
- 개인회원은 최초 한 번만 계정 연결·상세 근거 열람 동의를 한다. 이후 자기 질문에서는 반복 동의를 요구하지 않는다.
- 승인 기관회원과 관리자는 공개 질문의 기관별 확인 근거를 볼 수 있다.
- 시스템 관리자는 별도 버튼으로 공급자별 AI 답변 전체 원문과 입력/출력 토큰을 펼쳐볼 수 있다. 원문은 기관회원과 개인회원에게 노출하지 않는다.

### 모두의 AI 병원 질문

- 기본 범위는 전체 질문이며 `내 질문 보기`로 로그인 사용자의 질문만 필터링할 수 있다.
- 지역과 최근 기간을 기준으로 마스킹된 질문, 화면 요약, 최근 검색어 Top 10을 표시한다.
- `기관별 확인 근거`는 확인 기관을 가나다순으로 표시하고 공개 가능한 HIRA·검증 근거를 펼친다.
- 개인 식별정보, 작성자 이메일/UUID, AI 공급자 전체 원문은 목록 응답에 포함하지 않는다.

## 기관회원·관리자 AI 통계 화면

### 지역 통계

- 기관회원 최초 진입 지역은 승인된 자기 병원의 주소로 설정한다.
- 기관회원과 관리자 모두 시·도 및 시·군·구를 변경할 수 있다.
- 데이터 기본값은 `실제 사용자 검색`이며 필요하면 `벤치마크 질문`을 별도로 선택한다.
- `우리 기관 언급 통계`는 선택 지역의 전체 질문 중 자기 기관이 유효 추천된 횟수와 노출률을 표시한다.
- `지역 전체 통계`는 선택 지역의 전체 검색, 조건 검색 응답률, 최근 질문과 확인 기관을 표시한다. 개별 기관 순위와 점유율은 표시하지 않는다.
- 관리자는 기관 범위를 조회할 때 요양기호를 지정할 수 있다.

### AI 엔진 설정

- 관리자에게만 탭을 표시한다.
- ChatGPT, Gemini, Perplexity별 사용/중지 스위치와 현재 모델, 공급자 전용 시스템 프롬프트를 표시한다.
- 비활성 엔진의 입력창은 잠그며, 모든 엔진을 동시에 끄는 저장은 차단한다.
- 저장 성공 시 다음 정밀검색부터 적용된다는 안내와 최종 변경 시각을 표시한다.
- API 키와 서비스 역할 키는 화면 데이터에 포함하지 않는다.

## 가입 UX

- 기존 로그인에는 재동의를 강제하지 않는다.
- 신규 개인 이메일 가입은 이름·비밀번호 확인·필수 동의 후 이메일 인증을 진행한다.
- 소셜 가입은 OAuth 이동 전 동의를 받고, 기관 가입은 OTP 발송 전 동의를 받는다.
- 네이버 로그인은 암호학적 OAuth state와 최초 요청의 Callback URL을 세션에 보관하고, 콜백에서 state 검증 후 Edge Function이 발급한 token hash를 Supabase 세션으로 교환한다. 콜백 URL은 비동기 처리 전에 정리하고 React StrictMode에서도 code를 한 번만 소비한다. 실패 시 Edge Function의 안전한 오류 안내를 사용자에게 표시한다.
- HIRA 공개 조회 전용 Supabase 클라이언트는 세션 저장과 URL 내 인증 콜백 감지를 비활성화해 주 인증 클라이언트의 네이버 OAuth 처리를 방해하지 않는다.
- 약관 전문 페이지와 개인정보 처리방침 링크는 공개 전 P0 보완 항목이다.

## 호스피스 완화의료 UI/UX 시스템

### 1. 카테고리 다중 필터 연동 세부 선택 칩 (`App.tsx`)
- **자연스러운 칩 전개**: 병원 검색 카테고리에서 [호스피스] 칩을 선택하면 즉시 하단에 `[전체]`, `[입원형]`, `[가정형]`, `[자문형]` 4종의 세부 선택 칩이 슬라이드 형태로 자연스럽게 노출된다.
- **다중 선택 AND 필터링**: [재활병원], [혈액투석], [호스피스] 등 여러 필터를 동시 선택한 상태에서도 세부 선택 칩(`hospiceSubtype`)이 유지되며, 모든 조건을 교집합(AND)으로 만족하는 기관만 실시간 필터링한다.

### 2. 호스피스 병원 전용 3대 서비스 & 인프라 카드 (`App.tsx`, `HospitalDetailModal.tsx`)
- **오직 호스피스 병원에만 노출**: 일반 요양병원/병원에는 불필요한 빈 카드가 절대 노출되지 않으며, 오직 호스피스 3대 서비스 중 1개 이상을 운영하는 기관에만 전용 카드가 렌더링된다.
- **3대 서비스 상태 카드**:
  - `입원형 완화의료`: 전용 호스피스 병동 24시간 입원 돌봄 (활성 녹색 배지)
  - `가정형 호스피스`: 전담팀이 환자 가정을 직접 방문하는 완화 돌봄 (활성 녹색 배지)
  - `자문형 호스피스`: 일반병동 및 외래 환자 대상 완화의료 자문 (활성 녹색 배지)
- **부가 인프라 카드**:
  - `호스피스 인가병상수`: 보건복지부 공식 인가 전용 병상 수 (예: `15개 병상`)
  - `간병보조인력 운영 여부`: 건강보험 수가가 적용되는 전담 간병도우미 제도 운영 여부 (`운영중` / `미운영`)
  - `소아청소년 완화의료`: 시범사업 참여 여부 배지
  - `법정 대상질환`: 말기암, 만성간경화, 만성폐쇄성호흡기질환 태그 표시

### 3. 3단계 맞춤 요양 경로 네비게이터 연동 (`CareDecisionNavigator.tsx`)
- 1단계 [치료/간호 필요조건]에서 [호스피스 완화의료] 선택 시, 즉시 하단에 `[전체]`, `[입원형]`, `[가정형]`, `[자문형]` 세부 선택 칩이 활성화된다.
- 최종 3단계 완료 후 `조건으로 병원 찾기` 클릭 시 `SearchOptions`에 호스피스 세부 유형이 전달되어 검색 결과에 즉시 반영된다.

- 결과 위에 `LtcMap`(초록 마커, 기준 위치 빨간 마커, 팝업에서 상세정보)을 보여 준다. 홈 네비게이터도 기관 구분 '장기요양기관'과 상세구분 칩을 제공하고 `ltcGroups`로 검색 화면에 넘긴다. 상세구분·인력 칩은 기관 구분 칩과 같은 크기(30px)다.

## 관리자 크롤러 화면 (2026-10-16)

- 다운로드: 서버 실행기, 야간 배치(`run_crawl.bat`), **서울·경기 병원급 이상 전용 배치**, **서울·경기 의원급 전용 배치**, 지역별 배치 ZIP, 설치 파일. 배치 파일은 받을 때 내용 확인 문구로 손상 여부를 검사한다(`fetchLauncherTemplate`, 여러 문구 중 하나 일치).
- 로컬 서버 접속은 `127.0.0.1:8008` → `localhost:8008` 순서로 시도하고, 안 되면 크롬 '로컬 네트워크 액세스' 허용 방법을 안내한다.
- URL 수작업 검증 '공공·플랫폼 의심' 판정 목록(`EXCLUDED_PLATFORM_DOMAINS`)에 병원 찾기 포털(hospital24.kr 등)을 포함한다. 자동 확정된 홈페이지는 '공식 확정'으로 보인다.

## 관리자 '검색 품질 관리' 탭 (2026-10-15, 읽기 전용)

- 위치: 관리자 → 검색 품질 관리(`/admin?tab=quality`). 구성은 `SearchQualityDashboard.tsx`, 집계는 `searchQualityService.ts`가 맡는다.
- 원칙: 기존 관리자 RPC(`admin_list_crawl_claims_light`, `admin_get_crawl_claim_evidence`, `admin_list_website_candidates`, `get_keyword_search_stats`)와 공개 테이블만 읽는다. DB 상태를 바꾸지 않고, 기관 순위·종합 점수를 만들지 않는다.
- 구성
  - 범위 선택(시도·등급·테마)
  - 품질 요약
  - 승인·거절 표본 재검증(근거 원문·출처·확인일·점검 신호, CSV 재검증표)
  - 키워드별 품질
  - 검색 필터별 근거 기관(근거 없는 시군구 포함)
  - 0건 검색
  - 공식 홈페이지 오류 의심(블로그·카페, 3곳 이상 공유 주소)
- 공개·비공개 노출 기준
  - 일반 사용자 화면: 순위·점수·기관 간 비교를 보여 주지 않는다.
  - 관리자·기관회원 화면: 순위 통계를 둘 수 있다.
  - 이 품질 화면: 순위 없이 키워드·데이터 품질만 다룬다.
