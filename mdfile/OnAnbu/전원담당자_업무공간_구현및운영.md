# 상급의료기관 전원담당자 업무공간 — 구현 및 운영

작성: 2026-10-17 (2026-10-16 전략·작업 요청 기준)

최종 현행화: 2026-10-17 · 연락처 공개 선택·추가 질문·담당자 알림·관리자 진입 후속 승인 반영 완료.

## 이번 구현 범위

기존 `/tertiary` 상급병원 퇴원기준 화면은 유지한다. 별도 `/coordinator`에서 전원의뢰 목록 → 의뢰 내용 → 기관별 회신 → 업무 기록을 연결한다. 의료기관의 비교표·순위·우열 점수는 만들지 않는다.

- 기관회원 가입에서 **수신기관·병원정보 담당자 / 상급병원 전원담당자**를 구분한다.
- 담당자는 본인 이메일로 인증 후 상급종합·종합병원의 소속·부서·업무 연락처를 신청한다. 관리자 승인 전에는 의뢰를 조회·작성할 수 없다.
- 동일 기관에 여러 담당자를 승인할 수 있다. 승인된 같은 기관 담당자는 공동 의뢰를 조회하고 처리 상태·업무 메모를 기록한다. 타 기관·승인 대기·정지 계정은 전용 RPC에서 차단한다.
- 수신기관 병원정보 소유권·편집 권한과 분리한다. 전원담당자 승인을 받아도 `HOSPITAL` 역할이나 수신기관 소유권을 자동 부여하지 않는다.
- 출발병원과 희망 시·군·구를 별도로 저장한다. 후보 탐색은 담당자가 지역을 지정하고 행정기관 기준점에서 기본 10km(5/10/15/20/30km)를 선택한다. 행정구역 경계를 넘어도 반경 안이면 포함한다. 실제 기준점 이름·주소를 표시하고 구청 미등록 시 상위 시청 기준을 안내한다. 검색 기준점은 자택 주소가 아니다.
- 의뢰 희망지역과 탐색 설정은 분리한다. 이번 버전의 탐색 지역·반경·종별/진료분야는 화면 내 임시 설정이며 의뢰를 다시 열면 희망지역·10km로 돌아간다. 기존 `radius_km=15`는 레거시 필수값 호환용으로 유지하고 검색은 새 RPC에 전달한 실제 반경을 사용한다.
- 7개 의뢰 분야를 분류용으로 선택한다. 필수·선호 조건은 따로 지정하고 분야 선택으로 필수 조건을 자동 추가하지 않는다.
- 승인 검색어(`verified_search_terms`)에서 필수 조건의 등록 근거를 AND 확인한다. 선호 조건은 제외하지 않는다. '미확인 기관 포함'을 명시적으로 켜면 개별 확인 후보를 함께 볼 수 있다. 같은 기관에 투석·재활 근거가 있어도 동시 수용 가능으로 판단하지 않는다.
- 기관 구분·진료분야는 기존 검색 카탈로그를 재사용한다. 각 그룹 안은 OR, 그룹 간은 AND다. 병원급 의료기관만 대상으로 하며 장기요양기관 입소/재가 흐름은 포함하지 않는다.
- 기관 목록은 직선거리순으로 40곳씩 조회하고 같은 페이지 결과를 지도·카드에 함께 표시한다. 의료적 우수성 순위가 아니다. 폐업·출발병원·좌표 없는 기관은 제외한다. 지도 마커에서 해당 카드로 이동한다. 조건·페이지 변경 시 선택이 초기화되며 이전 검색의 지연 응답은 무시한다. 기관 선택은 한 번에 1~3곳이고 온라인 문의는 운영 중인 인증 수신기관에만 허용한다. 미가입 기관은 전화 확인 대상으로 표시한다.
- 기존 `transfer_consult_requests`와 `transfer_consult_targets`에 연결하므로 수신기관의 기존 받은 의뢰 목록·답변 저장 기능을 재사용한다. 답변·유효기간·조건별 회신·서류 안내·기관이 제공한 비용 안내·변경 이력을 기관별로 확인한다.
- 30초 간격의 상세 새로고침과 수동 새로고침을 제공한다. 보호자 안내 출력에서는 내부 업무 메모·후보 검색·처리 버튼을 제외한다.
- 추가정보 문답은 기관별로 분리한다. 보호자는 본인 의뢰, 전원담당자는 승인된 동일 기관 의뢰를 조회하며 답변·연락처 공개 변경은 현재 배정된 담당자가 처리한다. 인계 UI로 담당자를 바꿀 수 있고 인계 자체와 이후 질문·회신은 새 담당자에게 알린다.
- 보호자 상담과 담당자 의뢰 모두 이름·전화번호를 보관하되 기관 공유는 별도 선택이다. 신규 수신기관에는 기본 비공개이며 기존에 전달된 의뢰의 공유 상태는 유지한다. 한 기관에 공개해도 다른 기관의 설정은 바뀌지 않는다.
- 기관 조회의 구형 RPC 자체에서 비공개 이름·전화번호를 `***`, `***-****-****`로 반환한다. 알려진 동일 연락처가 요약·구조화 메모·질문·대화·변경 이력·비용 안내에 반복되어도 수신기관 응답에서 마스킹한다. 다른 개인정보의 자동 탐지까지 보장하지 않으므로 자유서술에 개인정보를 입력하지 않는다.
- 기관별 공개/비공개 변경은 확인 후 이력에 기록한다. 재전송으로 이전 공개 설정을 덮어쓰지 않는다. 비공개 전환은 이후 조회를 제한할 뿐 이미 전달된 정보의 회수는 보장하지 않는다.
- 종료는 실제 전원 성사를 자동 의미하지 않는다. 종료/취소 시 기존 수신기관 진행 중 목록에서도 제외되는 점을 확인한다.

## 관리자 개발 검증 방법

기존 최고관리자 계정을 그대로 사용한다. 계정 이메일·비밀번호·관리자 역할은 변경하지 않았으며 별도의 가짜 병원 직원 계정을 생성하지 않았다.

1. 기존 최고관리자로 로그인하면 새 전원의뢰 업무 화면으로 이동한다. 관리자 역할·비밀번호는 바꾸지 않는다.
2. 상단 **전원의뢰 업무** 메뉴 또는 `/coordinator`로 이동한다.
3. 개발 관리자 기관 선택에서 다음 실제 마스터 기관을 선택한다.
   - 연세대학교 의과대학 용인세브란스병원 — 종합병원(11)
   - 분당서울대학교병원 — 상급종합병원(01)
4. 기관을 전환하여 각 기관의 의뢰 준비·후보 검색·업무 기록을 검증한다.

관리자 또는 개발 표시 담당자가 만든 의뢰는 `coordinator_is_development=true`로 저장된다. 실제 기관에 전송되지 않도록 화면과 `send_coordinator_case` 양쪽에서 막는다. 이 표시를 클라이언트가 해제할 수 없다. 실제 병원 명의 문의나 실제 병원 직원 계정으로 가장하지 않는다.

## DB 변경 및 적용 상태

다음 마이그레이션을 운영 DB에 적용했다.

- `202610160008_transfer_coordinator_workspace.sql`: 소속·의뢰 업무공간.
- `202610170001_coordinator_region_normalization.sql`: 시·도 정식명칭·약칭 구분.
- `202610170002_consult_contact_privacy.sql`: 기존 공개 상태 보존, 신규 기본 비공개, 기관별 선택·서버 마스킹.
- `202610170003_consult_messages_and_notifications.sql`: 담당자 대화 권한, 의뢰 유형별 알림·직접 연결, 이전 전송 RPC 우회 차단.
- `202610170004_coordinator_handover_notification.sql`: 새 담당자에게 업무 인계 알림.
- `202610170005_separate_guardian_coordinator_access.sql`: 구형 보호자 조회·취소·테마 수정과 담당자 의뢰 분리, 정지 작성자의 원본 테이블 조회 차단.
- `202610170006_contact_choice_consent_version.sql`: 안내 개정에 맞는 동의 v2 지원. 기존 v1 기록·구버전 클라이언트 호환 보존.
- `202610170007_coordinator_radius_search.sql`: 담당자 지정 좌표·반경·기관 구분·진료분야 검색. 기존 지역 검색 RPC·업무 데이터 변경 없이 읽기 전용 RPC를 추가했다.

- 새 물리 테이블은 `transfer_coordinator_memberships` **1개**다. `(auth_user_id)`는 고유하지만 `(hospital_ykiho)`는 고유하지 않아 기관별 다중 가입이 가능하다.
- 의뢰·회신·비용 테이블을 복제하지 않는다. 기존 의뢰에 소속기관, 개발 표시, 관리번호, 검색지역, 선호 조건, 업무 상태, 담당자, 업무 이력을 추가한다.
- 원본 테이블 직접 수정 권한은 부여하지 않고 승인·작성·조회·전송을 한정된 RPC로 제공한다. 기존 보호자용 RLS를 기관 전체 공개로 넓히지 않는다.
- `app_metadata.transfer_coordinator`는 메뉴 표시용이다. 실제 접근 권한은 RPC가 DB 승인 상태로 매번 확인하므로 오래된 토큰으로 정지를 우회할 수 없다.
- 후속 명시 승인에 따라 기관 조회·질문/답변·알림 함수를 확장했다. 보호자 알림은 본인의 `/my-consults?target=...`, 담당자 알림은 현재 담당자의 `/coordinator?request=...&target=...`로 구분한다. 알림 본문에는 연락처·환자 상태를 넣지 않는다. 기존 계정·연락처 원본·상담 기록은 삭제하지 않는다.
- `consent_version=coordinator-conditions-v1`와 기록 시각은 담당자의 정보 최소화·업무 연락처 전달 확인이다. 환자 건강정보 제공 동의를 의미하지 않는다.

## 정보 입력 원칙

첫 단계는 수용 조건 사전 문의다. 환자 이름·등록번호·생년월일·보호자 연락처·진료기록·첨부파일 입력 항목을 만들지 않았다. 업무 메모에도 개인정보를 기록하지 않는다. 임상 기록의 실제 전달은 기존 병원 절차를 따른다. 이름을 제외했다고 완전한 익명성을 보장하는 것은 아니므로 기관 시범 운영 전 보안·개인정보 검토가 필요하다. 이 흐름에서 외부 LLM으로 입력을 전송하지 않는다.

## 보류·후속 작업 (운영 전 확인)

1. **알림·추가 질문 연결은 후속 승인을 받아 완료했다.** 초기 자동 안전 검토에서 보류되었던 변경을 구체적 범위 승인 후 적용했고, 실제 DB 롤백 검사로 보호자/담당자 동작과 권한을 확인했다.
2. 향후 확장: 기관별 협력기관 목록, 내 담당/기관 전체 작업함 필터, 팀장·일반 담당자의 세부 권한. 담당자 배정·인계 UI 및 인계 알림은 현재 구현되어 있다.
3. 문의 조건 수정 시 버전 관리, 전화 확인 기록의 기관별 구조화, 의뢰별 메시지/조회 감사기록과 보존·파기 정책.
4. 검색 중심·기본 10km 지도와 기관 구분·진료분야 재사용은 완료했다. 후속: 탐색 설정 의뢰별 저장, 상세 조건별 키워드 판정의 기존 검색 카탈로그 일원화. 현재 담당자 사전 확인용 11개 조건의 근거 패턴은 담당자 RPC에 한정되어 있다. 장기요양기관 입소/재가 연계는 의료기관 전원과 별도 흐름으로 후속 설계한다.
5. 실제 전원 성사 기록, 최초 유효 회신 시간·회신율·담당자 재사용 지표. 업무 종료를 전원 성사로 집계하지 않는다.

## 2026-10-17 화면·프로세스 재구성 (2차)

### 업무 흐름
`① 의뢰 등록(3단계) → ② 후보 찾기(문의 바구니) → ③ 문의 진행(온라인 문의 + 전화 확인 목록) → ④ 회신 확인 → ⑤ 업무 종료(결과 기록)`

- 작업함: `내 담당`(내가 현재 담당자인 진행 중 의뢰) / `팀 진행 중` / `종료`. 새 회신이 있는 의뢰가 위로 온다. 처음 열 때 내 담당이 없으면 팀 진행 중을 보여 준다.
- 의뢰 상세 상단의 **다음 할 일**: 문의 전 → 후보 찾기, 새 회신 → 회신 보기, 추가 질문 → 답변, 전화 확인 남음 → 전화 확인, 수용 가능 회신 → 업무 종료 순으로 안내한다. 담당자가 아니면 인계받기를 안내한다.
- 후보 찾기의 바구니는 온라인 문의 가능 기관(인증 수신기관)과 전화 확인 기관을 함께 담는다. [문의 진행] 한 번으로 온라인 문의 전송과 전화 확인 목록 추가를 처리한다. 기관 수 제한 없음(한 번 200곳 이하). 개발 검증 의뢰는 모두 전화 확인 목록으로만 들어간다.
- 탐색 설정(시·도, 시·군·구, 반경, 기관 구분, 진료분야, 검색어, 미확인 포함)은 의뢰별로 자동 저장된다. 이전 버전의 '다시 열면 10km로 초기화' 동작은 없어졌다.
- 인수인계: [인계하기] → 받을 담당자 + 인계 메모(현재 상황·남은 할 일, 필수). 새 담당자에게 알림이 가고 의뢰 상단에 인계 메모가 고정된다. 업무기록 탭에 인계 이력이 남는다.
- 업무 종료: 결과(전원 기관 확정 — 문의·전화 확인한 기관 중 선택 / 보호자 직접 진행 / 의뢰 취소 — 사유 필수 / 기타 — 사유 필수). 잘못 종료하면 [다시 진행](사유 필수)으로 되돌린다. 업무 종료는 여전히 실제 전원 성사와 자동 동일시하지 않으며 결과 기록으로 구분한다.
