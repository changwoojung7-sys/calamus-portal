### 2) 수집 대상 주소 순서

### 3) 공식 홈페이지 판정과 자동 확정

| 후보 경로 | 확인 | 결과 |
| --- | --- | --- |
| 검색으로 찾은 주소 | 접속 + 페이지 안에 **기관명 + 심평원 대표전화**가 함께 있음 (`verify_candidate_homepage`) | **자동 확정** |
| 병원 블로그에 적힌 홈페이지 링크 | 같은 확인을 거친 경우만 후보로 사용 (`verified_blog_homepage`, 2026-10-16부터) | **자동 확정** |
| 그 밖의 주소(심평원 원천 등) | 크롤러가 바꾸지 않음 | 관리자 확인 |

- 자동 확정은 DB 저장 함수 `save_hospital_crawl_result`가 한다. 크롤러가 확인을 통과한 후보에 `homepage_candidate_verified = NAME_PHONE`을 붙이면, 공식 홈페이지 목록(`official_website_registry`, `source_type = AUTO_VERIFIED`)·심평원 주소·기관 프로필에 바로 반영하고 변경 이력(`hospital_homepage_change_audits`, 사유 '자동 확정')을 남긴다.
- 자동 확정 제외: 관리자가 같은 주소를 반려한 후보, 공공(.go.kr)·포털·블로그·SNS·단축주소, **병원 찾기 포털**(제목에 '병원찾기·진료과목별·병원정보' 등, 예: 병원24 hospital24.kr), 차단 도메인 목록(`EXCLUDED_DOMAINS`).
- 근거: 검색 경로 후보는 사람 검토 결과 승인 861 · 반려 13(약 98.5%). 블로그 링크 경로는 확인 없이 쓰던 시절 승인 18 · 반려 45여서 같은 확인을 넣었다.
- 주소(도로명)는 판정에 쓰지 않는다(이미지로만 주소를 넣은 홈페이지가 많다).
- 관리자 화면 '공공·플랫폼 의심'은 정부 도메인·포털·목록형 경로 주소를 모은다. 공립병원·보건소처럼 정부 사이트가 실제 공식 홈페이지면 '수동 확정'(`admin_override_suspicious_website`, 2026-10-15 버그 수정)으로 확정한다.

## 1. 결론

현재 크롤러는 병원 홈페이지에서 예약 전화, 네이버 블로그, 유튜브, 특화 진료 태그를 추출한다. 자동 발굴 단계는 병원명과 심평원 대표전화가 함께 확인된 URL만 후보로 인정한다. 2026-10-16부터는 이 확인을 통과한 후보를 공식 홈페이지로 자동 확정한다(위 '공식 홈페이지 판정과 자동 확정').

다음 두 경로의 자동 승격 위험은 2026-10-02 후보 격리 방식으로 차단했다.

1. 검색 결과에서 찾은 도메인이 제목에 병원 이름만 포함해도 `verify_candidate_homepage`를 통과할 수 있다.
2. 공식 블로그 소개글에서 URL을 뽑는 `extract_homepage_from_text`는 병원명·대표전화 재검증 없이 첫 번째 비차단 URL을 채택한다.

자동 수집값은 **후보 수집 → 검증 → 승인/반려 → 공개 반영** 상태로 분리하며, 관리자 확정 RPC만 HIRA URL과 공개 병원 프로필을 갱신한다.

## 2. 현재 실행 구조

```text

  → hospital_crawler.py

       ⑤ crawling_log/crawl_YYYY-MM-DD.md 기록
```

별도 Trust 배치(`official-website-trust-batch`)는 공식 홈페이지 본문에서 **심평원 병원명 또는 대표전화**가 확인된 URL만 `official_website_registry`에 `VERIFIED`로 저장한다. 일반 크롤러가 먼저 `homepage_url`을 저장할 수 있는 문제는 별도로 남아 있다.

## 4. 현재 공식 홈페이지·블로그 판정

### 기존 HIRA URL

- HIRA `hosapi_hospital.url`이 있으면 먼저 수집한다.
- `blog.naver.com`은 공식 홈페이지가 아닌 블로그로 간주하고 정식 도메인을 발굴한다.
- 상급/종합병원(코드 01/11)은 기존 URL이 있으면 자동 발굴로 대체하지 않는다.

**한계:** HIRA URL이 오래되었거나 제3자 URL인 경우 일반 크롤러 단계에서 병원명·전화번호 검증 없이 수집될 수 있다.

### 검색엔진 자동 발굴

발굴 순서는 Bing → Daum/Kakao → Google → Naver → 공식 홈페이지를 찾지 못한 경우 네이버 블로그다. 검색어는 대표전화+병원명, 병원명+도로명, 병원명+시군구, 병원명 단독을 사용한다.

#### 현행 제외 규칙

`EXCLUDED_DOMAINS`와 `PLATFORM_PATH_PATTERNS`로 포털·SNS·지도·예약·의료중개·일부 공공기관·채용·플랫폼과 `/hospital/`, `/clinic/`, `/detail/`, 숫자 ID형 URL을 제외한다.

#### 현행 홈페이지 통과 규칙

`verify_candidate_homepage()`가 후보 도메인의 루트 페이지를 내려받아 다음 중 하나면 통과시킨다.

1. `<title>`에 병원 핵심명 또는 정제 병원명이 포함됨
2. 본문에 병원명(또는 핵심명) **및** 심평원 대표전화가 함께 포함됨

#### 현행 블로그 통과 규칙

- `blog.naver.com/{id}`로 정규화한다.
- 모바일 블로그 제목 또는 첫 1,500자에 병원 핵심명이 있으면 채택한다.
- 별도 네이버 검색 경로에서는 대표전화 일치 또는 “병원명 + 병원/공식” 표현만으로도 채택한다.

## 5. 자동 발굴 URL의 잔여 위험과 현재 방어

| 위험 지점 | 현재 방어 | 남는 검토 사례 |
| --- | --- | --- |
| 블랙리스트 한계 | 공공·플랫폼 도메인 규칙으로 1차 제외하고 모든 자동 발굴 URL을 후보 테이블에 격리한다. | 새 제3자 도메인은 관리자가 반려해야 한다. |
| 제목·검색 문맥 혼입 | 제목 단독 통과를 제거하고 병원명+심평원 대표전화 동시 일치를 요구한다. | 전화번호를 복제한 목록 사이트는 관리자 주소 대조가 필요하다. |
| 블로그 외부 URL | `BLOG_LINK` 후보로만 저장하고 공개 URL은 바꾸지 않는다. | 협력기관·구청 링크는 관리자 반려 대상이다. |
| 리다이렉트 검증 부족 | 후보 상태에서는 공개·Trust 근거로 사용하지 않는다. | 최종 리다이렉트 URL과 Schema 근거 구조화가 후속 과제다. |
| 유튜브·블로그 채널 | 공개 홈페이지 확정과 분리해 채널 정보로만 저장한다. | 공식 채널 소유 검증 상태 세분화가 후속 과제다. |

## 6. 목표 공식 홈페이지 판정 기준

자동 발굴 URL은 아래 상태 중 하나여야 한다.

| 상태 | 의미 | 공개 `homepage_url` 반영 |
| --- | --- | --- |
| `VERIFIED` | 병원 본인 사이트로 강하게 확인 | 가능 |
| `CANDIDATE` | 검색으로 찾았지만 증거 부족 | 불가, 관리자 검토 |
| `REJECTED` | 공공기관·플랫폼·타 병원·도메인 불일치 | 불가 |
| `UNAVAILABLE` | 홈페이지 없음/접속 실패/robots 제한 | 불가 |

### VERIFIED 최소 조건

다음을 모두 만족해야 한다.

1. HTTP(S) 공개 URL이며 사설 IP·로컬호스트·비표준 포트가 아니다.
2. 포털, SNS, 지도, 예약 플랫폼, 언론, 채용, 공공기관/지자체 도메인이 아니다.
3. 최종 리다이렉트 URL도 같은 제외 규칙을 통과한다.
4. 본문 또는 구조화 데이터에서 **정제 병원명과 심평원 대표전화가 모두 일치**한다. 대표전화가 없으면 병원명 + 도로명 핵심 토큰 + 의료기관 Schema.org 두 가지 이상을 요구한다.
5. 진료안내·의료진·입원/예약·사업자/주소 중 복수의 의료기관 정체성 신호가 있다.
6. 원 URL·최종 URL·검증 근거·검증 시각을 함께 저장한다.

### 공식 블로그·유튜브 기준

- 블로그는 공식 홈페이지 링크 또는 블로그 프로필의 병원명 + 대표전화/공식 도메인 일치를 요구한다.
- 유튜브는 공식 홈페이지 링크 또는 채널 About의 병원명 + 대표전화/공식 도메인 일치를 요구한다.
- 단일 영상 URL, 병원명만 있는 블로그, 후기·대행사·커뮤니티는 자동 공개하지 않는다.

## 7. 구현 보완 순서

### P0 — 잘못된 공식 홈페이지 저장 차단 [✅ 2026-10-02 완료]

1. 일반 크롤러 자동 발굴 URL을 공개 프로필과 분리된 후보 테이블에 저장한다.
2. `title 병원명 단독` 통과를 제거하고 병원명+심평원 대표전화 동시 일치를 요구한다.
3. `.go.kr`, 공공기관·지자체·언론·채용·플랫폼은 기존 도메인 분류 규칙으로 차단한다.
4. `extract_homepage_from_text`가 찾은 URL도 `BLOG_LINK` 후보로만 저장한다.
5. 관리자는 후보를 대조 후 확정하거나 사유와 함께 반려한다. 동일 반려 URL은 재수집돼도 반려 상태를 유지하고 다른 URL이 발견돼야 재검토된다.

### P1 — 저장 구조와 관리자 검토 [부분 완료]

1. `official_website_registry`를 관리자 확정 URL 원장으로 사용한다(완료).
2. 자동 발굴은 `hospital_provider_profiles.homepage_url`을 변경하지 않고 후보 테이블에만 저장한다(완료). 기관회원 직접 입력 URL의 재검증 정책은 별도 보완한다.
3. 자동 후보에 `candidate_url`, `source_type`, `status`, `rejection_reason`, 최초·마지막 확인일, 수집 페이지 근거를 남긴다(완료). 최종 리다이렉트 URL·Schema 매칭 근거의 구조화는 후속 과제다.
4. 관리자 화면에서 후보 URL과 기관명·전화·주소를 대조해 승인·반려한다(완료). 자동 Schema 매칭 점수 표시는 후속 과제다.
5. (2026-10-01 완료) 로컬 사본 `crawled_profiles.json`은 폐기했고 운영 DB만 기준으로 한다.

### P1 — 정보별 신뢰도 분리

- 예약전화: 상담/예약 인접 표현과 HIRA 대표전화/공식 사이트 관계를 기록한다.
- 블로그·유튜브: `official`, `candidate`, `unverified` 상태를 분리한다.
- 특화 태그: 키워드 추출값은 `CRAWLED_CLAIM`으로 저장하고 HIRA·기관 확인값과 분리한다.
- 웹 키워드만으로 `has_dialysis`, `has_rehab`, `has_icu` 검색 hard filter를 변경하지 않는다.

### P2 — 운영성

- `robots.txt`, 도메인별 요청 간격, TLS 인증서 검증을 기본값으로 한다.
- `verify=False`를 제거하고 인증서 실패는 실패 사유로 기록한다.
- 수집 HTML 해시·추출 근거 위치·재수집 일시를 남겨 변경을 추적한다.
- JavaScript 렌더링 사이트는 별도 렌더러 큐로 분리한다.

## 8. 수정 후 검증 시나리오

1. 병원명만 언급한 구청 공지 → `REJECTED`
2. 동명 타 지역 병원(대표전화 불일치) → `REJECTED`
3. 병원명·대표전화·의료기관 JSON-LD가 모두 있는 도메인 → `VERIFIED`
4. 공식 홈페이지가 링크한 네이버 블로그 → 공식 블로그
5. 병원명만 있는 광고 대행 블로그 → `CANDIDATE` 또는 `REJECTED`
6. 블로그 소개글의 첫 외부 링크가 구청 사이트 → 홈페이지 승격 금지
7. YouTube 영상만 있는 페이지 → 채널 검증 전 `unverified`
8. robots/TLS/timeout → `UNAVAILABLE` 또는 재시도 상태와 실패 사유 기록
