## **제한적 오픈 베타 GO / 전국 단위 공개 확장 보류**

OnAnbu는 단순 병원 검색 MVP 단계를 지났다. HIRA 요양기호 기반 기관 식별, 7대 테마 검색, 승인형 크롤링 태그, 전원 상담, 기관회원 관리, 관리자 검토까지 연결돼 있어 **경기·수도권 중심 제한적 베타를 운영할 수 있는 수준**이다.

그러나 의료기관 데이터는 계속 변한다. 2026-10-10 점검에서 경기도 병원급 이상 공식 확정 홈페이지 477건 중 46건이 두 차례 연속 접속 불가였고, 해당 URL·크롤링 근거·검토 태그 72건을 실제로 정리했다. 데이터 통제 구조가 작동한다는 장점인 동시에, 전국 공개 전에 신선도 자동화와 운영 지표가 필요하다는 뜻이다.

### 현재 강점

1. **데이터 출처 분리**: HIRA 원천, 기관 입력, 홈페이지 크롤링 결과를 분리하고 카드 근거에 출처를 표시한다.
2. **승인형 크롤링**: 수집 태그는 검토 대기 상태로 저장하며 관리자 승인 태그만 검색·AI 근거가 된다. 승인 태그는 180일 만료된다.
3. **공식 홈페이지·폐업 상태 관리**: 홈페이지 후보·확정·반려를 구분하고, 수정·삭제 시 HIRA URL·프로필·후보·이력을 함께 정리한다. 폐업은 삭제하지 않고 사유·근거 URL과 함께 가역적으로 관리한다.
4. **권한 경계**: 공개 HIRA 읽기와 개인/기관/관리자 쓰기를 분리하고, 민감 동작은 제한 RPC로 처리한다.
5. **상담 흐름의 구조화**: 7대 테마 기반 보호자 상담과 기관 답변을 자유 입력 중심이 아닌 조건·선택형 흐름으로 만들었다.

### 권장 출시 순서

1. **즉시**: 경기·수도권 중심 제한적 보호자 베타와 실제 기관 파트너 운영을 시작한다.
2. **1~2주**: 데이터 신선도 리포트, 모바일 실기기 회귀, 상담 이탈·기관 응답시간 계측을 만든다.
3. **3~4주**: 실제 상담 20건 이상과 기관 10곳 이상으로 E2E를 검증하고, 한 개 추가 권역에서 데이터 정리 비용을 측정한다.
4. **그 이후**: 지표가 안정되면 전국 공개 범위와 B2B 유료화 실험을 단계적으로 확대한다.

### 재평가 결론

OnAnbu의 경쟁력은 “AI 추천” 자체보다 **공공 원천 데이터·기관 입력·관리자 승인 크롤링 근거를 분리하고 변화를 이력으로 관리하는 신뢰 구조**에 있다. 지금은 기능을 더 넓히기보다, 이미 구현한 검색·상담·기관 운영 도구의 실제 실패율과 전환율을 측정하는 단계다. 제한적 베타에서 이 신뢰 운영을 증명한 뒤 전국 확장으로 가는 것이 가장 낮은 위험의 경로다.

## 1. 결론 (재평가)

**MVP 완성을 넘어 상용화(Production-Ready) 단계에 성공적으로 진입했다.**

초기 평가(2026-09-07) 당시 지적되었던 법적 고지 부재, 수기 입력으로 인한 보호자 이탈, 요양기관의 회신 장벽, 외부 AI 비용·레이턴시 위험, 비공개 소통 채널 부재 등의 핵심 결함들이 **최근 집중 개발(2026-09-11 ~ 2026-09-28)을 통해 모두 해결**되었다.

특히:
1. **보호자 상담 3단계 마법사 & 기관 원클릭 표준 견적 패키지(프리셋 3종)**를 통해 플랫폼 양면 네트워크(보호자-요양기관)의 마찰 없는 전환 구조를 확립했다.
2. **호스피스 완화의료 3대 서비스(입원형/가정형/자문형)** 및 127개 보건복지부 공식 기관 매칭, DB 영구 격리 설계를 완비하여 시니어 케어 전문 플랫폼으로서의 독보적인 데이터 경쟁력을 확보했다.
3. **자체 문지기 알고리즘(`intentClassifier.ts`) 0원/0.05초 캐시 게이트**와 **대표전화 기반 유령 병원 하드 필터링**을 통해 AI 비용 방어와 팩트 그라운딩(환각 차단)을 동시에 달성했다.

남은 과제는 최종 실기기 통합 회귀 검증(P0)뿐이며, 이를 마치면 **즉각적인 조건부 오픈 베타 및 소프트 런칭이 가능**하다.

| **LUVIS Trust & B2B** | **고도화 완료** | 공식 홈페이지 검증 및 진단. B2B 대시보드에 자기 기관의 검색 확인 추이와 홈페이지 AEO/GEO·Trust 진단, 보완 항목을 제공한다. 타 기관 실명·순위·상위 평균 비교는 제공하지 않는다. 실패 URL 정밀 재시도 대시보드 보완 진행 중. |
| **인증 / 보안 / 소통** | **구현 완료** | 개인 이메일/소셜(네이버 OAuth 안정화), 기관 OTP/관리자 승인.<br>**법적 고지 완비**: 서비스 이용약관·개인정보 처리방침 전문 열람 모달(`TermsModal.tsx`) 연동 및 `v1.0` 동의 이력 추적.<br>**비공개 문의게시판 (`support_inquiries`)**: bcrypt 비밀번호 해시 인증 조회, 관리자 답변 RPC.<br>**실시간 사이트 활동 카운터 (`site_activity_events`)**: 오늘 방문자, 검색 실행, 병원카드 조회, 입원상담 요청 합계 표시. |
| **후기 / 병원 프로필** | **구현 완료** | 승인 기관 프로필 격리 편집(`hospital_provider_profiles`), 후기 등록 및 관리자 검토 흐름 구축. |
| **검색 근거 & 크롤링 검토 (2026-10-01)** | **구현 완료** | 테마 필수/선호 근거, 카드 '검색 조건 일치 근거', 결과 고정·후보 전체 확인(최대 2,000곳·가까운 곳 우선), 심평원 DB 기준 시·군·구. 홈페이지 수집 태그는 검토 대기열 → 관리자 승인 시에만 근거(180일 만료). 민감 태그 엄격 규칙, 다른 PC용 관리자 로그인 크롤러 EXE. 남은 과제: 승인 근거 확충(암 요양 등). |
| **광고 / 결제** | **설계 대상** | 검색 순위를 훼손하지 않는 B2B 스폰서십, 구독, 결제, 노출 집계 도메인 (P3 단계). |

## 3. 아키텍처 평가

```text
React 18 + Vite (SPA)
  ├─ 공개 검색·지도·상세·가이드·비용·전원상담 3단계 마법사
  ├─ B2C 보호자 카드 (기관별 검색 조건 일치 근거·출처)
  ├─ 개인 / 기관(원클릭 프리셋 회신) / 최고관리자 역할별 UI
  ├─ React.lazy() 번들 최적화 (메인 JS 32% 감축)
  └─ src/services API 파사드
          ├─ Supabase PostgreSQL / RLS / 멱등 RPC
          ├─ HIRA 마스터 DB (hosapi_hospital)
          ├─ 기관 격리 프로필 DB (hospital_provider_profiles)
          ├─ 비공개 문의 DB (support_inquiries)
          └─ Supabase Edge Functions (TypeScript strict)
              ├─ ai-care-search (문지기 캐시 게이트, PII 마스킹, 다중 AI 병렬 수집)
              ├─ ai-consensus-batch
              ├─ official-website-trust-batch
              └─ naver-auth (OAuth state 및 token-hash 교환)
```

- **핵심 강점**:
  1. **팩트 그라운딩 철저 분리**: 사용자 화면의 모든 병원 후보는 심평원 `ykiho` 및 유선 대표전화 실측을 필수로 거치며, AI 문장만으로 가상 병원이 생성될 수 없다.
  2. **공공데이터 정기 갱신과 기관 데이터의 물리적 격리**: 심평원 DB(`hosapi_hospital`) 정기 동기화 시 기관회원이 입력한 호스피스 3대 서비스나 특화 진료 데이터가 덮어써지지 않도록 `hospital_provider_profiles` 테이블에 영구 격리 보존했다.
  3. **양면 네트워크 마찰 제로화**: 보호자는 선택형 칩으로 1분 만에 전원 상담을 접수하고, 기관은 원클릭 프리셋으로 30초 만에 표준 견적을 회신할 수 있어 플랫폼 활성화 동력을 확보했다.
  4. **B2B(LUVIS)와 B2C(온안부)의 엄격한 아키텍처 격리**: 향후 SaaS 독립 분리 및 M&A(Exit)를 고려하여 인터페이스(API) 레벨에서 모듈을 완벽 분리했다.

## 4. 데이터와 신뢰 원칙

1. **마스터 DB 기준**: `hosapi_hospital` 및 `hosapi_hospital_detail`이 병원 식별, 법적 종별, 인프라의 기준이다.
2. **기관 데이터 격리**: `hospital_provider_profiles`는 승인 기관이 입력한 호스피스 3대 서비스, 인가병상수, 간병보조인력 운영 여부, 특화 비급여 정보이며 HIRA 공공데이터와 화면에서 명확히 출처를 구분한다.
3. **공식 홈페이지 판정**: 병원명 또는 대표전화가 HIRA와 일치하는 도메인만 `official_website_registry`에 등록하며 블로그·SNS는 Trust 대상에서 제외한다.
4. **유령 병원 및 가상 시설 원천 차단**: 문장형 조건 검색 시 유선 대표전화가 확인되지 않거나 필수 의료조건(투석, 재활, ICU, 호스피스) 인프라가 없는 기관은 결과 후보에서 즉시 탈락 처리한다.
5. **비용 및 진단 비의료성 고지**: 모든 비용 계산 결과는 공단 고시 기준 '추정치'임을 명시하고, AI 보조 검색은 의료적 진단이나 입원 확정·기관 추천이 아닌 '조건 정리와 기관별 사실 확인 보조 도구'임을 약관 및 화면 전반에 명시한다.

## 5. 인증·개인정보·권한 평가

- **약관 및 개인정보 전문 열람 완비**:
  - `TermsModal.tsx`를 통해 가입 화면에서 서비스 이용약관과 개인정보 처리방침 전문을 탭 형태로 즉시 열람할 수 있다.
  - `auth_consent_records`에 `terms_version: v1.0`, `privacy_version: v1.0` 동의 이력이 정밀하게 추적된다.
- **PII(개인식별정보) 철저 격리**:
  - 외부 LLM(OpenAI, Claude, Perplexity 등) 전송 전 한국어 조사(은/는/이/가/와/과) 및 쉼표 결합 환자 나이/이름 마스킹 정규식을 강화하여 원시 PII 전송을 원천 차단했다.
  - 전원 상담 시 보호자의 연락처는 선택한 1~3개 병원의 승인된 담당자만 제한 RPC를 통해 열람할 수 있다.
- **비공개 문의 채널 보안**:
  - `support_inquiries`는 bcrypt 해시 비밀번호로 본인 글만 조회 가능하며, 5회 연속 오류 시 10분 잠금 정책을 적용했다. 관리자는 제한 RPC를 통해 전체 검토 및 답변을 등록한다.

## 6. 기관별 사실 확인 평가

- **B2C 보호자 관점의 인지적 피로도 해소**:
  - 의료기관 간 종합 점수·추천 순위·나란히 비교를 제거하고, 각 기관에서 확인된 조건·출처·미확인 항목을 독립적으로 보여 준다.
  - 문장형 조건 검색은 환자 상황을 검색 조건으로 정리하는 데만 AI를 사용하고, 공개 결과는 HIRA와 승인 근거가 확인된 기관별 사실로 제한한다.
- **B2B 요양기관 관점의 행동 유도형 가시성**:
  - LUVIS 대시보드는 자기 기관의 검색 확인률과 홈페이지 AEO/GEO·Trust 진단만 보여 주며, 타 기관 실명·순위·상위 평균은 제공하지 않는다.
  - 진단 결과를 공식 홈페이지·구조화 데이터·기관 정보의 구체적인 보완 행동으로 연결한다.

### 공개 전 최종 수동 검증 체크리스트 (P0)

1. **실기기(iOS Safari, Android Chrome) UX 점검**:
   - 홈 ➔ 3단계 네비게이터 ➔ 병원찾기 ➔ 호스피스 세부 칩 선택 ➔ 상세 모달 ➔ 뒤로가기 흐름.
2. **역할별 계정 흐름 수동 확인**:
   - 비회원 1회 무료 체험 후 2회째 로그인 모달 유도.
   - 개인회원 가입(약관 전문보기 ➔ 동의 ➔ 가입).
   - 승인 전 기관회원 차단 및 승인 기관회원의 호스피스 탭/프로필 편집 저장.
3. **전원 상담 ➔ 기관 답변 E2E 흐름**:
   - 보호자: 상담 요청 기관 1~3곳 선택 ➔ 3단계 선택형 마법사 접수 ➔ 기관 운영 상황에 따라 회신 시간이 달라진다는 안내 확인.
   - 요양병원: 대시보드 보호자 의뢰서 스플릿 뷰 확인 ➔ 원클릭 표준 견적 패키지 선택 ➔ 회신 완료.
   - 보호자: 기관별 독립 답변 카드에서 수신된 견적 버전 및 상세 확인.
4. **비공개 문의게시판**:
   - 문의 작성 ➔ 비밀번호 입력 후 본인 글 확인 ➔ 5회 오류 잠금 ➔ 관리자 답변 등록 및 확인.
