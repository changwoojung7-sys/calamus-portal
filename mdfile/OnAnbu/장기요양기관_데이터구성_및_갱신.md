## 4. DB 설계와 갱신 보호

마이그레이션: `supabase/migrations/202610160004_ltc_source_snapshots.sql` (2026-10-16 운영 적용 완료).

| 테이블 | 역할 |
|---|---|
| ltc_import_batches | 원본 해시·기준일·변환 버전·예상 건수·적재/공개 상태 |
| ltc_institutions | 변하지 않는 기관코드와 관리자 확인 전화·홈페이지·운영상태 |
| ltc_service_types | 배치별 원본 유형명과 검색 분류 매핑 |
| ltc_institution_snapshots | 배치별 기관명·주소·지역·지정/신고일·품질 사유·원문 |
| ltc_service_snapshots | 배치별 서비스·정원·13개 직종 인원·정원/인력 원천 존재 여부·각 원문을 통합 저장 |
| ltc_staff_snapshots (뷰) | 통합 표의 인력 원천이 있는 행만 기존 컬럼 형식으로 조회. 별도 저장 없음 |
| ltc_staff_keywords (뷰) | 통합 표에서 직종 인원이 1 이상일 때 계산. 별도 저장 없음 |
| ltc_quality_reviews | 기관별 문제·제안값·검토 근거, 원본과 분리 |

- 기관코드·우편번호·지역코드는 문자열로 보관한다.
- 장기요양기관코드를 HIRA `ykiho`로 위장하지 않는다. 공통 시설 연결은 별도 nullable `facility_id`만 준비했다.
- 관리자 확인 전화·홈페이지·휴폐업 판정은 원천 스냅샷 밖에 있으므로 신규 자료 수입이 덮어쓰지 않는다. 기본 운영상태는 `UNVERIFIED`다.
- 수입은 기존 행을 수정하지 않는 INSERT로 구성했다. 원본 파일 해시 + 자료 기준일 + 변환 버전으로 배치를 식별한다.
- CSV 전체는 한 트랜잭션으로 적재하고 테이블별 예상 건수를 대조한다. 실패하면 전체 롤백한다.
- 반복 적재는 `ON CONFLICT DO NOTHING`으로 중복을 만들지 않는다. 같은 배치의 CSV를 수정해 재사용하지 말고 원본·변환 버전이 다른 새 배치를 만든다.
- 원천 표는 RLS 활성화, anon/authenticated 권한 회수 상태다. 현재 앱에서 읽거나 검색할 수 없다.
- `STAGED` 적재와 `PUBLISHED` 공개 승인을 분리했다. 이 단계에는 공개 승인 RPC나 자동 발행 기능을 만들지 않았다.

### 다음 자료 갱신 순서

1. 원본 파일을 기존 파일과 별도로 보관하고 실제 자료 기준일을 확인한다.
2. **직전 승인 자료의** `manifest.json`을 지정해 새 배치를 생성한다.
3. `changes.json`에서 신규·변경·누락 기관코드, 변동 없는 수를 확인한다. 비교는 기관명·주소·정원·서비스·인력을 포함하며 행 순서·배치ID 변경은 변동으로 세지 않는다.
4. `quality_report.json`의 주소 누락·신규 미매핑 서비스를 확인한다. 코드 개편·기준일 오류·누락 급증 시 반영을 보류한다.
5. 검증 후 새 배치를 STAGED로 적재한다. 기존 관리자 값과 과거 스냅샷은 유지한다.
6. 추후 공개 기능에서는 승인된 배치를 사용한다. 한 기관의 기본정보·서비스·인력·키워드는 **동일한 배치**에서 조회한다. 이전에 있던 서비스/키워드를 새 자료와 합치면 없어진 키워드가 살아나므로 금지한다.
7. 새 파일에서 기관 전체가 빠진 경우 자동 삭제·폐업하지 않는다. 이전 기록을 보관하고 `최신 자료 누락/재확인 필요` 대상으로 분리한다. 공개 노출 지속 여부도 별도 정책으로 결정한다.
8. 주소 변경 기관은 좌표 재검증 대상으로 보낸다. 향후 좌표는 주소 해시·좌표 출처·자료 버전을 별도 보관하며, 주소가 바뀌면 예전 좌표를 그대로 공개하지 않는다.

현재의 키워드 0명 전환은 새 스냅샷에 키워드가 생성되지 않는 방식으로 처리한다. 과거 근거는 삭제하지 않는다. 원천 인력값이 전부 0이라도 기관 전체 폐업으로 판단하지 않는다.

## 5. 실행 방법

로컬 데이터 구성(네트워크·DB 접근 없음):

```powershell
python scripts/prepare_ltc_excel.py --source "mdfile/hospital_info_file/국민건강보험공단_장기요양기관 시설별 현황_20260610.xlsx" --as-of 2026-06-10
```

같은 배치 출력 폴더가 있으면 덮어쓰지 않고 중단한다. 재검증하려면 별도 `--output` 경로를 지정한다. 다음 자료는 다음과 같이 이전 매니페스트를 연결한다.

```powershell
python scripts/prepare_ltc_excel.py --source "새로운파일.xlsx" --as-of YYYY-MM-DD --previous-manifest "이전배치폴더/manifest.json"
```

출력물: `institutions.csv`, `services.csv`, `staff.csv`, `staff_keywords.csv`, `service_mapping.csv`, `manifest.json`, `changes.json`, `quality_report.json`, `import.psql`.

`import.psql`은 **마이그레이션 적용 후, 명시적으로 psql을 실행할 때만** DB에 적재한다. 생성된 PC의 CSV 절대경로를 사용하므로 다른 PC에서는 구성 스크립트를 다시 실행한다. CSV의 빈 문자열과 NULL은 구분하며 NULL 표기는 `\N`이다. 결과 파일을 수동 수정하지 않는다. 운영 DB 비밀번호를 명령행·로그에 남기지 말고 안전한 연결 설정을 사용한다.

검증:

```powershell
python scripts/test_ltc_excel.py
node scripts/test_ltc_schema.cjs
```

- 파서 회귀 검증 12개 통과: 중복·고아 키·컬럼 변경·음수·알 수 없는 코드·정원/인력 분리·키워드 소멸·파일 재실행·기준일 역행·행 순서 변경.
- 스키마 검증 통과: 전체 ROLLBACK, 관리자값 보호·과거 이력·음수 정원 차단·0명 키워드 차단·STAGED 상태·RLS/공개 권한 회수.
- 실자료 30,595기관 전체 운영 적재 완료. `load_ltc_stage.cjs`로 표별 전체 건수 및 각 행의 실제 적재값을 대조했다. 운영 함수/스키마 검증은 `test_ltc_schema.cjs --live`로 수행하고 시험 데이터는 ROLLBACK했다.

### 운영 적재 및 품질 검토 실행

```powershell
# 기본은 로컬 입력 건수 검증만 수행
node scripts/load_ltc_stage.cjs mdfile/hospital_info_file/ltc_prepared/03242aaeef5ab322
# --apply를 지정할 때만 승인된 운영 배치에 저장
node scripts/load_ltc_stage.cjs mdfile/hospital_info_file/ltc_prepared/03242aaeef5ab322 --apply
python scripts/fetch_ltc_region_reference.py mdfile/hospital_info_file/ltc_prepared/03242aaeef5ab322
python scripts/review_ltc_quality.py mdfile/hospital_info_file/ltc_prepared/03242aaeef5ab322
node scripts/save_ltc_quality.cjs mdfile/hospital_info_file/ltc_prepared/03242aaeef5ab322 --apply
```

Management API 적재는 작은 요청 3개 이하로 나누어 수행한다. 이 경로는 psql의 전체 단일 트랜잭션과 다르며, 중단되면 비공개 `STAGED` 배치에 일부 행이 남을 수 있다. 같은 배치로 재시도할 수 있고, **전체 건수와 내용 대조를 마쳐야** 적재 검증이 `PENDING` → `VERIFIED`로 바뀐다. 공개 상태는 바꾸지 않는다.

`202610160005_ltc_compact_storage.sql` 통합 스키마부터는 원본 정원/인력 CSV를 기관·서비스 키로 합쳐 `ltc_service_snapshots` 한 표에만 저장한다. 인력·키워드 CSV는 두 계산 뷰와의 내용 대조에만 사용한다. 인력 원천 부재(NULL), 원본 인원 0, 미기재 인원은 구분하며 인원이 0으로 바뀌면 키워드도 자동으로 사라진다. 원문 JSON은 안전한 외부 원본 보관을 확보하기 전까지 유지한다.

검토 결과는 `quality_reviews.json`·`quality_reviews.csv`에 보관한다. 공식 코드자료와 출처/다운로드 시각/원문 해시도 보관하며, 제안값을 원본 스냅샷이나 관리자 확인값에 덮어쓰지 않는다. 상세 결과는 `장기요양기관_1차검증결과.md` 참조.

### 보존 확인

- 기관 30,595 · 서비스 49,324 · 인력 조회 49,162 · 인력 키워드 조회 135,434 · 검토 이력 387행 모두 유지.
- 인력 원문 49,162행은 통합 표에 그대로 보관. 인력 원천이 없는 162개 서비스도 NULL 상태로 구분한다.
- 이관 트랜잭션 안에서 기존 인력 모든 컬럼/원문과 계산 키워드의 값·근거·수를 대조한 뒤 구 물리 표를 제거했다. 실패하면 전환 전체가 롤백된다.
- 데이터 의미나 원본을 삭제한 것은 아니다. 이전 인력 형식은 `ltc_staff_snapshots` 뷰, 키워드는 `ltc_staff_keywords` 뷰로 재구성할 수 있다.
- 두 뷰는 `security_invoker`로 원천 RLS를 따르고 일반 사용자 조회 및 service_role 쓰기 권한을 회수했다. 조회만 허용한다. 계산 뷰는 테이블 목록과 비슷하게 표시될 수 있지만 데이터를 별도 저장하지 않는다.
- 원문 JSON은 안전한 외부 원본 보관을 확보하기 전까지 유지한다. 이번 작업에서 원본 엑셀·원문·검토 결과는 삭제하지 않았다.

### 갱신 및 검증 도구

- `load_ltc_stage.cjs`: CSV의 서비스·정원·인력을 합쳐 통합 표에만 적재하고, 인력·키워드 뷰와 원본 결과를 각각 대조한다. 적재를 시작하면 검증 상태를 PENDING으로 되돌리고 전체 대조 성공 후에만 VERIFIED로 바꾼다.
- `prepare_ltc_excel.py`: 앞으로 생성하는 `import.psql`도 같은 통합 구조를 사용한다. 기존 배치 폴더의 `import.psql`도 재생성했다. 예전에 다른 PC에 복사한 구형 적재 스크립트는 사용하지 않는다.
- 검증: 파서/갱신 12개, 품질검토 5개, CSV/통합 키 검사, 통합 마이그레이션 포함 ROLLBACK 검증 및 적용 후 `test_ltc_schema.cjs --live` 통과.
