# OnAnbu 현행 시스템 맥락

> 최종 현행화: 2026-10-17 · 기준 브랜치: `main` · 배포: GitHub `main` → Cloudflare Pages 자동 빌드

## 서비스

온안부(OnAnbu) AI Care는 환자와 보호자가 시니어·암·정형재활·소아발달·정신건강·산부인과·호스피스의 **7대 테마**에 맞는 의료기관을 **심평원(HIRA) 팩트**로 찾고 전원·입원 조건까지 설계하도록 돕는 B2C 포털이다. LUVIS는 기관의 공식 홈페이지를 AEO/GEO 관점에서 진단하는 B2B 모듈이다. AI·Trust는 의료 진단이나 입원 확정을 하지 않으며 HIRA 기준 시설 탐색을 보조한다. 공개 서비스는 개별 기관의 확인 정보만 제공하고 의료기관 간 순위·우열 점수·나란히 비교 기능을 제공하지 않는다.

## 현재 사용자 흐름

### 전원담당자 업무공간 (2026-10-17)

후보 탐색은 담당자 지정 지역의 행정기관 기준점에서 기본 10km(5/10/15/20/30km) 반경으로 지도·카드를 함께 표시한다. 행정경계를 넘는 반경 내 병원을 포함하고 기관 구분·진료분야·필수 조건을 AND 연결한다. 같은 페이지 40곳을 거리순 표시하며 조건 변경 시 선택을 초기화한다. 읽기 전용 반경 RPC `202610170007`을 운영 적용했으며 의뢰 희망지역·레거시 반경을 변경하지 않는다.

기존 `/tertiary`는 유지하고 `/coordinator`를 추가했다. 기관회원 가입에서 전원담당자를 선택해 소속기관별 다중 가입·관리자 승인을 받는다. 승인된 동일 기관 담당자는 의뢰 목록·기관별 회신·업무 기록을 공동 조회하며, 현재 배정된 담당자가 추가 질문에 답하고 연락처 공개 설정을 변경한다. 인계 UI·새 담당자 알림을 제공하고 수신기관 소유권과 역할은 분리한다. 기존 최고관리자로 로그인하면 새 화면으로 이동하여 용인세브란스·분당서울대 개발 컨텍스트를 선택할 수 있다. 개발 의뢰의 실제 기관 전송은 차단된다. 보호자와 담당자 모두 이름·전화번호를 보관하되 신규 의뢰의 기관 공유는 기본 비공개이고 기관별로 변경할 수 있다. 기관 응답·대화에서 서버 마스킹을 적용하고, 보호자는 내 입원상담·담당자는 전용 업무 화면으로 알림을 연결한다. 구형 보호자 경로에서도 담당자 의뢰를 분리해 정지·타기관 우회를 차단한다. 동의 안내는 2026-10-17/v2로 현행화하되 기존 v1 이력·호환은 보존한다. 상세 범위·검증·향후 확장은 `전원담당자_업무공간_구현및운영.md` 참고.

## 핵심 구현

- **기관 구분 · 진료분야 분리 (2026-10-15, 설계 `테마_필터_설계.md`)**:
  - 검색 '기관 구분'은 심평원 법정 종별만 쓴다(요양·상급종합/종합(묶음)·병원·의원·한방병원·한의원·호스피스·정신·치과병원·치과의원·조산원·보건기관). 재활·산부인과는 '진료분야'로 옮겼다.
  - '진료분야'(재활·암·정형척추·소아·정신건강·산부인과·이비인후과·피부과·성형외과·안과·비뇨의학과)는 DB `hosapi_hospital.specialty_fields`에 미리 계산한다(기관명·종별·기관 입력·승인 키워드). 줄 안은 OR, 기관 구분과는 AND.
  - 7대 테마는 일반검색·메인 네비게이터에서 기관 구분 + 진료분야만 자동 선택하고 필터는 자동 선택하지 않는다. 입원상담 테마(`transferTheme`)와 상급병원 퇴원연계 화면은 기존 그대로다.
- **크롤링 운영 (2026-10-16, 기준 `병원홈페이지 크롤링계획_EXE Plan.md`)**:
  - 서울·경기 병원급/의원급 배치, 지역 ZIP 모두 최근 1일 수집 기관 건너뛰기(멈춘 뒤 다시 실행하면 이어서). 병원당 180초 제한.
  - 발굴 홈페이지는 접속 + 기관명 + 대표전화가 맞으면 자동 확정(검색·블로그 링크 모두, 병원 찾기 포털 제외). 건너뜀·실패는 `hospital_crawl_misses`에 기록.
  - 수집 단계에서 AI 검토 거절 유형(단어만·키워드 나열·주차장 규모·직함 없는 전문의·경력 줄·포털 등)을 거른다. 카탈로그 161개 태그(암면역치료/암온열치료 분리, 이비인후과·피부과·성형외과·안과·비뇨의학과 추가).
  - AI 검토 에이전트(`keyword-reviewer`, `homepage-verifier`)는 판정을 기록만 하고, 승인·거절은 관리자가 반영한다. 관리자 '검색 품질 관리' 탭에서 크롤링 공백·표본 재검증·작업함을 본다.

- **7대 전원 테마 및 12대 전문 인프라 체계 (2026-10-01)**:
  - 7대 맞춤 전원 테마(`SENIOR`, `CANCER`, `ORTHO`, `PEDIATRIC`, `MENTAL`, `OBGYN`, `HOSPICE`)를 검색·전원상담·기관답변에 공통 적용한다. 테마 정의는 `src/data/transfer_theme_catalog.json` 한 곳에서 관리한다(2026-10-01 호스피스 추가).
  - 기존 8대 플래그에 `has_pediatric_psychiatry`, `has_delivery_room`, `has_postpartum_care`, `has_infertility_center`를 추가하고 기관회원 저장 RPC와 AI 후보 필터에 연결했다.
  - 테마·상담 목적(`consultation_purpose`)은 입원상담 접수 RPC가 같은 트랜잭션에서 전용 컬럼과 상담 JSON에 함께 저장하고, 허용값은 `transfer_theme_catalog`(카탈로그 JSON에서 생성) 트리거로 검증한다.
  - 테마별 연령·상태(`themeCondition`)를 분리해 소아·산부인과가 시니어 기본값(70대·치매)으로 저장되지 않는다.
  - 기관회원 대시보드·보호자 의뢰 현황·기관 답변 폼은 `resolveConsultTheme`로 같은 규칙의 테마 뱃지를 표시한다.
